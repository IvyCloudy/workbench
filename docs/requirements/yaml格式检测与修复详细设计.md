# YAML 格式检测与修复 — 详细设计文档

> 文档视角：技术实现（面向开发与维护者）
> 配套需求文档：`docs/requirements/yaml格式检测和修复需求.md`、`docs/requirements/yaml解析增强-推送保留原文需求.md`
> 适用范围：YAML 案例文件（`.yaml` / `.yml`）在 VS Code 编辑器内的实时检测/修复，以及独立命令行（AI Skill）形式的批量检测/修复。
> 章节约定：每个功能模块均按「需求要点 / 涉及模块与文件 / 核心数据结构 / 关键流程 / 边界与防御」展开。

## 1. 总体架构

YAML 检测修复能力在**两个运行位置**提供，但共享**同一套规则定义**，保证行为完全一致：

- **编辑器内（Node/ts，src/）**：打开/编辑 YAML 时实时诊断（波浪线 + 问题面板）、灯泡单行修复、右键/命令批量修复。
- **命令行（AI Skill）**：`skills/yaml-format-fix/scripts/fix-yaml.js`（Node）与 `fix_yaml.py`（Python），可被 AI 助手或 CI 调用，规则 1:1 移植，零 LLM token 消耗。

两个位置的规则集合分为三层（与需求文档 §3.1 对齐）：

| 层级 | 规则 | 覆盖 | 依赖 |
|------|------|------|------|
| 逐行（R1~R8） | Tab 缩进、行内 Tab、行末空格、冒号后缺空格、歧义值、值内 `#`、保留字符、`-` 后缺空格 | 8 类 | 无（纯字符串算法） |
| 文件级（F1） | 同层级重复 key | 1 类 | 无（需带作用域感知） |
| 解析器兜底（P1~P4） | 嵌套 map 错误、缺闭合引号、缩进列错位、重复 key | 4 类 | 可选 YAML 库（`yaml` / `PyYAML`） |

规则引擎分"基础版"（R1~R8 + F1，9 类，零依赖）与"增强版"（叠加 P1~P4，共 12 类，装库后自动启用）。未安装解析库时前两层照常工作，第三层跳过，不报错。

关键模块映射：

| 职责 | 模块 |
|------|------|
| 规则常量与关键词表 | `src/utils/yamlConstants.ts`（与脚本 1:1 复刻） |
| 逐行/文件级规则检测与修复 | `src/utils/yamlRules.ts`（与 `fix-yaml.js` 同源算法） |
| 解析器兜底检测（P1~P4） | `src/utils/yamlValidator.ts` |
| 编辑器诊断（波浪线 + 问题面板） | `src/handlers/yamlValidationHandler.ts` |
| 灯泡/批量修复入口 | `src/providers/YamlFixProvider.ts` |
| 打开即预检与降级拦截 | `src/handlers/yamlPreOpenInterceptor.ts`、`yamlResolveFallback.ts` |
| 命令行（Node / Python） | `skills/yaml-format-fix/scripts/fix-yaml.js` / `fix_yaml.py` |

## 2. 规则引擎设计

### 2.1 核心数据结构

```ts
// src/utils/yamlTypes.ts
type Severity = 'error' | 'warning';

interface YamlIssue {
  ruleId: string;        // 'R1' | 'R4' | 'F1' | 'P1' | ...
  line: number;          // 1-based
  column?: number;
  severity: Severity;
  message: string;
  autoFixable: boolean;  // 是否可自动修复
  fix?: {                // 若可修，给出替换后的整行（或行范围）
    fromLine: number;
    toLine: number;
    replacement: string;
  };
}
```

规则定义结构（`yamlRules.ts`）：每条规则是一个纯函数
`(line: string, ctx: LineContext, state: FileScanState) => YamlIssue[]`，其中 `LineContext` 由 `buildLineCtx` 产出（含精准的冒号/哈希定位，见 2.3）。

`yamlConstants.ts` 维护：
- `RESERVED_CHARS_PATTERN`（`[\[\]{},&*!>|]`）及豁免表 `YAML_INDICATOR_PATTERNS`（块标量 `|`/`>`、别名 `*`、锚点 `&`、标签 `!`、内联序列/映射）。
- 歧义关键词集：`BOOLEAN_KEYWORDS`（yes/no/on/off/true/false 各大小写）、`NULL_KEYWORDS`（null/~）、`NUMERIC_SPECIAL_KEYWORDS`（.inf/.nan 等）。
- 引号剥离/包裹辅助：`stripQuotes`、`wrapValueWithQuote`（按值内已含单/双引号智能选择包裹引号，单双皆有时双引号转义）。

### 2.2 逐行规则（R1~R8）

每条规则独立判定，命中即产出 `YamlIssue`；部分规则带 `stopOnHit` 标记避免同一行重复报（如 R1 命中后不再跑 R2 同位置判定）。

| 规则 | 判定 | 修复 |
|------|------|------|
| R1 Tab 缩进 | 行首缩进段含 `\t` | 每个 `\t` → 2 空格，`stopOnHit` |
| R2 行内 Tab | 引号外、非行末的 `\t` | → 1 空格 |
| R3 行末空格 | 行尾 `\s+$`（含不间断空格 `\u00A0`） | `rstrip` |
| R4 冒号后缺空格 | 真冒号（见 2.3）后紧跟非空格 | 插入 1 空格；若补空格后值仍需加引号，则连带 R5/R7 一次完成（见 2.4） |
| R5 歧义值 | `getAmbiguousType(value)` 命中关键词 | `wrapValueWithQuote` 包裹 |
| R6 值内 `#` | 值段含 `#` 且非行尾注释（哈希在冒号后、引号外、`//!` 之外） | 整值加引号（只包"值是内容"段，不影响对齐写的真注释） |
| R7 保留字符 | 值段命中 `RESERVED_CHARS_PATTERN` 且非 `YAML_INDICATOR_PATTERNS` 豁免 | 加引号；若值本身是合法内联序列 `[a,b]`/映射，则跳过 |
| R8 `-` 后缺空格 | 列表项 `-` 后紧跟非空格且非 `--`/`---` 分隔线 | 插入 1 空格 |

### 2.3 真冒号识别（避免误报的关键）

`findYamlColon(line)` 逐字符扫描，维护 `inSingle`/`inDouble`/`flowDepth` 状态：
- 引号内字符跳过；
- `{`/`[` 入栈、`}`/`]` 出栈，`flowDepth>0` 时冒号归解析器管辖（内联集合里的冒号不当键分隔）；
- 跳过 `://`（URL）、`::`（双冒号）；
- 其余首个 `:` 即为真冒号，返回索引。

`findYamlChar(line, '#')` 同理只在引号外定位哈希，用于区分"值内 `#`"（R6）与"真注释"。

### 2.4 修复冲突与合并（一步到位）

当一行同时触发多条规则时，按需求 §3.2.2 原则：
- **一步到位优先**：R4 补空格后若值仍需加引号（R5/R7），直接合并为"加引号"一次完成，不先补空格再补引号。
- **整体包裹优先**：值含歧义关键词且紧贴 `#`（R5+R6），直接整体加引号，不分开处理。
- **同一条行不重复修**：已被前几条规则修过的行，不再被解析器兜底规则改写。
- **破坏性修复后置**：凡把行改成注释的修复（F1 重复 key、P3 缩进错位、P4 解析器重复 key、无法识别错误）留到最后一批统一执行。

### 2.5 文件级重复 key（F1）与解析器兜底（P1~P4）

- **F1**：扫描时维护"当前缩进层级 → 已见 key 集合"作用域栈；同一作用域内二次出现同名 key 判为重复，后续行改为 `# [duplicate key removed] <原内容>`（保留原内容于注释，便于审计）。
- **P1~P4**（增强版，依赖 YAML 库）：捕获解析异常
  - P1 嵌套 map 错误 → 优先包裹列表项后面的值；非列表项则包裹冒号后值（从第一个冒号起，避免命中值内冒号）；
  - P2 缺闭合引号 → 统计单/双引号奇偶，补齐对应闭合引号；
  - P3 缩进列错位（same column） → 注释化该行；
  - P4 解析器报重复 key → 注释化该行。

## 3. 编辑器内实时检测与修复

### 3.1 诊断注册与触发（yamlValidationHandler.ts）

#### 需求要点
打开/编辑 YAML 案例时实时扫描，红色波浪线（error）与黄色波浪线（warning）标注，问题面板列出明细，点击跳转对应行。

#### 涉及模块与文件
- `src/handlers/yamlValidationHandler.ts`（诊断集合构建、防抖、问题面板）。
- `src/utils/yamlRules.ts` + `yamlValidator.ts`（规则引擎）。

#### 关键流程
1. **触发时机**：文档 `onDidChangeTextDocument` 经防抖后启动；性能分级（需求 §3.1.3）：
   - ≤200KB：停止输入 500ms 后检查；
   - ＞200KB：延迟 1000ms；
   - 刚执行批量修复后短窗口内不重复触发（避免修复连锁反应）。
2. **三层顺序检测**（需求 §3.1.2）：① 文件头 BOM/异常标记 → ② 逐行 R1~R8 → ③ 全文 F1 重复 key → ④ 解析库完整验证 P1~P4 → ⑤ 汇总注入诊断集合。
3. **诊断注入**：每条 `YamlIssue` 映射为 VS Code `Diagnostic`（`range` 精确定位），`severity` 按 error/warning 着色；问题面板数据源与诊断行号一致。
4. **智能识别**：真冒号识别（2.3）、17 种歧义关键词覆盖，避免误报。

#### 边界与防御
- 解析器自身异常 → 按安全降级（见 §4）处理，不抛未捕获异常阻断编辑器。
- 校验器自保护：即便校验逻辑异常，也降级为文本编辑器打开并提示手动检查。

### 3.2 修复入口（YamlFixProvider.ts）

#### 需求要点
问题处点击灯泡单行修复，右键/命令面板批量修复，编辑体验流畅、可整体撤销。

#### 涉及模块与文件
- `src/providers/YamlFixProvider.ts`（CodeAction、命令注册）。
- 复用 `yamlRules.ts` 的修复输出（`YamlIssue.fix`）。

#### 关键流程（需求 §3.2.5）
1. **单行修复**：波浪线 → 灯泡 `CodeAction` → 应用该行 `fix.replacement`，一次编辑操作。
2. **批量修复**（修复全部 / 仅 error / 仅 warning / 选中范围）：
   - 收集目标范围内所有 `autoFixable` 问题；
   - **从最后一行往前修**（避免行号变化错位）；
   - 每 100 行一批，批间 yield 让出（保持流畅）；
   - 所有修复合并为**单个 Undo 栈操作**，一次撤销全部回滚；
   - 多轮"检查→修复→再检查"循环，对比内容是否变化，最多 5 轮，收敛解析器级级联错误；
   - 完成后重新检测，告知"共修复 N 处，剩余 M 处"。
3. **破坏性修复后置**：注释化类修复（F1/P3/P4）统一在最后一批执行。

#### 边界与防御
- 修复后文件再次检测不得重复报同样问题（需求 AC-3）；收敛循环以"内容无变化"为退出条件，防死循环。
- 选中范围修复仅在选区行号区间内应用。

## 4. 打开即预检与安全降级

### 需求要点
语法严重错误文件打开时瞬间切换到文本编辑器并定位首错行，绝不展示空表/数据丢失（对应需求 §3.2 / 解析增强需求 §3.2）。

### 涉及模块与文件
- `src/handlers/yamlPreOpenInterceptor.ts`（打开拦截预检）。
- `src/handlers/yamlResolveFallback.ts`（兜底解析失败切换）。
- `src/utils/yamlInterceptorState.ts`（拦截态标记，防重复弹提示/拉光标）。

### 关键流程
1. **打开即预检**：标签页出现瞬间同步预检内容；一旦检测到致命语法错误（解析器无法产出表结构），立即关闭案例编辑器标签页、改用普通文本编辑器打开，用户看不到中间空表/过渡页。
2. **错误定位与提示**：切换后光标定位首条错误行，弹出"已切换为文本编辑器，共 N 处错误"，提供"一键修复全部""查看问题面板"入口；行号与问题面板一致。
3. **双保险兜底**：若时序原因预检未拦截，内部解析失败仍静默切换到文本编辑器（不重复弹提示、不重复拉光标，靠 `yamlInterceptorState` 去重）。
4. **校验器自保护**：校验器异常也按安全降级——文本编辑器打开并提示手动检查。

### 边界与防御
- `yamlInterceptorState` 保证预检路径与兜底路径不双重弹窗/双重拉光标。
- 解析增强需求中"行级对齐保留原文"的保存/推送回写逻辑与本降级路径正交：仅当文件可解析为表结构时才进入编辑器，否则不入编辑器，避免数据覆盖风险。

## 5. 命令行 / AI Skill（双版本一致性）

### 需求要点
将检测修复能力独立打包为 CLI（Node + Python），AI 助手零 token 读文件即可完成修复，规则与编辑器版完全一致（需求 §3.3）。

### 涉及模块与文件
- `skills/yaml-format-fix/scripts/fix-yaml.js`（Node）、`fix_yaml.py`（Python）。
- `skills/yaml-format-fix/SKILL.md`、`README.md`、`references/detection-rules.md`、`references/fix-strategies.md`。

### 核心数据结构（CLI 输出）
```jsonc
{
  "tier": "full" | "basic",
  "capability": "增强版 / 基础版",
  "summary": {
    "total": 12, "errors": 3, "warnings": 9,
    "autoFixable": 11, "applied": 10, "skipped": 1, "remainingErrors": 0
  },
  "issues": [
    { "ruleId": "R4", "line": 5, "column": 10,
      "severity": "warning", "message": "...", "autoFixable": true }
  ]
}
```

### 关键流程（需求 §3.3.5）
1. 解析参数：`<file>` + 模式（`--dry-run` 预览 / `--verbose` 详细 / `--json` 机器可读）。
2. 检查 YAML 库是否存在，决定 full/basic tier。
3. 读取全文 → 第一轮检测（基础 10 类 + 增强 4 类）。
4. 非预览模式：从最后一行往前逐行应用修复。
5. 修复后重检，若解析器级问题未清完自动多轮（最多 5 轮，每轮确认有变化）。
6. 非预览模式写回文件。
7. 输出结果并返回执行码：`0` 全修完 / `2` 仍有严重问题 / `1` 工具异常（文件找不到、无权限等）。

### 双版本一致性保障（需求 §3.3.6，SKILL.md）
- 规则定义、执行顺序、判断标准、歧义关键词、豁免情况、冒号识别逻辑、重复 key 作用域逻辑、引号包裹策略——JS 与 Python **完全相同**。
- R1~R8 + F1：纯字符串算法，字节级等效；P1~P4：问题类别一致，仅底层解析器报错措辞/行偏移可能 ±1，重跑 1~2 次两版均收敛为干净态。
- 依赖**软可选**：无 `package.json`/`requirements.txt`，未装库时自动降级 basic tier，不报错。

### 边界与防御
- `--dry-run` 不改文件，仍输出检测与将应用摘要。
- `--json` 输出单对象，便于流水线接入；返回码供 CI 判定通过/人工介入。
- 大文件性能（需求 AC-7）：万行内检测+修复目标 ≤2s（纯字符串算法，无 AST 构建开销）。

## 6. 跨功能交互与一致性

- **规则单一真相源**：编辑器版（`yamlRules.ts`/`yamlValidator.ts`）与 CLI 版（`fix-yaml.js`/`fix_yaml.py`）均源自同一份规则定义（`yamlConstants.ts` 常量表 1:1 复刻），确保"同一文件两份实现结果一致"。
- **与解析增强（推送保留原文）正交**：本能力负责"让文件能被正确解析"（格式层）；解析增强负责"解析后保存/推送不破坏原文"（语义层）。前者是后者的前置保障——格式错误时直接降级，不进入编辑器，避免 `testcase_id` 行对齐错位覆盖。
- **诊断与降级联动**：`yamlValidationHandler` 的波浪线检测与 `yamlPreOpenInterceptor` 的预检共用同一解析器入口，错误行号天然一致。
- **性能防抖共享**：编辑器内检测的大文件分级延迟与批量修复批处理，均避免在超大文件上阻塞事件循环。

## 7. 待确认 / 可演进项

- **规则数量口径**：需求文档 §3.1.1 列 14 类（含"文件头多余标记""解析器非致命提醒"等），而 CLI/SKILL 实际落地为 12 条规则（BOM 单列 + R1~R8 + F1 + P1~P4）。建议统一对外口径：以 12 条活跃规则为准，文件头 BOM 作为 R1 同级文件级检查项，解析器非致命提醒（W*）作为 warning 不产出自动修复。
- **多轮收敛上限**：P1~P4 级联错误最多 5 轮，极端畸形文件可能仍需人工；是否暴露"最大轮数"为可配置项待定。
- **批量修复整文件 vs 选区**：当前命令面板支持"仅 error / 仅 warning / 选中范围"，是否补充"仅某规则类型"待评审。
- **降级后修复入口**：安全降级切到文本编辑器后，"一键修复全部"调用的是 CLI 版还是编辑器内 `YamlFixProvider`，需明确闭环路径（建议统一走 CLI 以保证双位置一致）。

## 8. 验收对照表（映射到需求 §5）

| 编号 | 验收项 | 设计落点 |
|------|--------|----------|
| AC-1 | 覆盖全部问题类别 | 12 条活跃规则（BOM + R1~R8 + F1 + P1~P4），§2/§5 |
| AC-2 | 检测准确（不误报/不漏报） | 真冒号识别（§2.3）、17 种歧义关键词、豁免表（§2.1） |
| AC-3 | 连续修复两次无新问题 | 多轮收敛（§3.2）+ 破坏性修复后置 + 内容变化退出（§2.4/§5） |
| AC-4 | 修复后可解析、语义不变 | 引号包裹保留原值、重复 key 注释化保留原内容（§2.2/§2.5） |
| AC-5 | JS/Python 结果一致 | 规则 1:1 移植、双版本一致性保障（§5） |
| AC-6 | 无解析库时基础版可用 | 软可选依赖、basic tier 降级（§1/§5） |
| AC-7 | 万行 ≤2s | 纯字符串算法、无 AST 开销（§5） |
| AC-8 | 返回码 0/2/1 | CLI 退出码定义（§5） |
