# 插件运营指标体系

> 本文档基于当前代码库中已落地的全部埋点（约 90 个事件），整理出一套可直接交付给数据/运营同学的运营指标。
>
> 全部事件上报至 `/api/v1/track`，每条事件自动注入以下公共属性：
>
> `extName / extVersion / vscodeVersion / platform / arch / nodeVersion / osRelease / language / machineId / sessionId / ts`

## 一、规模 & 健康度（北极星 + 基础盘）

| 指标 | 计算口径 | 数据来源 |
|---|---|---|
| **DAU / WAU / MAU** | `distinct(machineId)` 按时间窗去重 | `extension.activated` |
| **新增用户数** | 首次出现的 `machineId` | `extension.activated`（首次） |
| **留存（次日 / 7 日 / 30 日）** | 首次激活后 N 天再次激活的占比 | `extension.activated` |
| **会话数** | `count(distinct sessionId)` | `extension.activated` |
| **会话时长 P50/P95** | `extension.deactivated.sessionMs` | `extension.deactivated` |
| **激活耗时 P50/P95** | `activateMs` | `extension.activate.done` |
| **版本分布** | 按 `extVersion` 分组 | 公共属性 |
| **VSCode 版本 / 平台 / OS / 语言分布** | 按 `vscodeVersion / platform / osRelease / language` 分组 | 公共属性 |

> 这些指标用于回答"插件总盘子有多大、版本/平台分布、用户粘性"。

## 二、核心功能使用漏斗

### 2.1 推送漏斗（最重业务）

资源管理器右键推送和编辑器内推送是两条独立漏斗，可以分开看也可以合并看。

| 漏斗节点 | 资源管理器入口 | 编辑器入口 |
|---|---|---|
| ① 命令触发 | `command.executed[command=testcaseViewer.pushTestCaseFromExplorer]` | — |
| ② 启动推送 | `explorerPush.start` | `editorPush.start` |
| ③ 后端调用 | `api.pushTestCase.ok` / `api.pushTestCase.fail` / `api.pushTestCase.exception` | 同左 |
| ④ 完成推送 | `explorerPush.complete` | `editorPush.complete` |

**关键运营指标**：

| 指标 | 计算口径 | 字段 |
|---|---|---|
| 推送启动数 | `count(*.start)` | — |
| 推送完成数 | `count(*.complete)` | — |
| **推送成功率** | `sum(successRows) / sum(totalRows)` | `*.complete.successRows / totalRows` |
| **行级失败率** | `sum(failedRows) / sum(totalRows)` | `*.complete.failedRows / totalRows` |
| **整体结果分布** | 按 `pushResult ∈ {allSuccess, partial, allFail}` 计数 | `*.complete.pushResult` |
| **推送耗时 P50/P95/P99** | `costMs` | `*.complete.costMs` / `*.failed.costMs` |
| **后端 API 耗时 P50/P95** | `api.pushTestCase.ok.costMs` | http 层 |
| **单次推送行数分布** | `totalRows` 直方图 | `*.complete.totalRows` |
| **文件类型分布** | 按 `ext` 分组（yaml / csv / xlsx 等） | `*.complete.ext` |
| **被中断流失分布** | 按 `reason ∈ {multiFile, dirNotQualified, unbound, noData, onlyTemplateExample}` | `explorerPush.aborted.reason` |
| **后端错误码分布** | `returnCode` | `*.failed.returnCode` / `api.pushTestCase.fail.returnCode` |

> 漏斗转化率 = `*.complete / *.start`，对比两个入口可以看出哪条路径用户更顺。

#### 2.1.1 多文件批量推送（explorerPush.batch.*）

多文件/文件夹右键推送采用"进度面板 + 总结视图"的独立流程，有专属埋点。

| 指标 | 计算口径 | 数据来源 |
|---|---|---|
| **每日批量推送次数** | `count(explorerPush.batch.start)` 按天聚合 | `explorerPush.batch.start` |
| **平均每批文件数** | `avg(fileCount)` | `explorerPush.batch.start.fileCount` |
| **批次文件类型分布** | 按 `extBreakdown` 解析（如 `csv:3,yaml:2`） | `explorerPush.batch.start.extBreakdown` |
| **每文件结果分布** | `resultType ∈ {success, partialFail, error}` 占比 | `explorerPush.batch.fileResult.resultType` |
| **每文件行级统计** | `avg(succ) / avg(fail) / avg(total)` 按 `ext` 分组 | `explorerPush.batch.fileResult.succ / fail / total` |
| **用户取消率** | `count(batch.cancelled) / count(batch.start)` | `explorerPush.batch.cancelled` |
| **取消时平均完成比例** | `avg(completed / (completed + remaining))` | `explorerPush.batch.cancelled.completed / remaining` |
| **批次总耗时 P50/P95** | `durationMs` 分位线 | `explorerPush.batch.done.durationMs` |
| **批次成功率** | `sum(totalSucc) / sum(totalSucc + totalFail)` | `explorerPush.batch.done.totalSucc / totalFail` |
| **含错误文件比** | `sum(errorFiles) / sum(fileCount)` | `explorerPush.batch.done.errorFiles / fileCount` |
| **总结面板点击文件频次** | `count(explorerPush.batch.openFile)` 按 `ext` 分组 | `explorerPush.batch.openFile` |
| **点击文件的结果分布** | 点击的是成功文件 vs 失败文件 | `explorerPush.batch.openFile.hasError` |
| **推送时用户已打开占比** 🆕 | `avg(refreshed / total)` | `explorerPush.batch.postRefresh.refreshed / total` |
| **批次刷新面板数** 🆕 | `sum(refreshed)` | `explorerPush.batch.postRefresh.refreshed` |

> 多文件批次完成后，`pushCore` 仍会为每个文件独立触发 `explorerPush.start / .complete / .failed` 等单文件埋点，分析时可通过同 `sessionId` 下的时序进行关联。

### 3.1 YAML 格式校验 & 自动修复

> 插件在用户打开/保存/编辑 `.yaml` / `.yml` 文件时自动进行格式校验（Tab 缩进、行末空格、冒号缺空格、特殊未引号值、YAML 保留字符等），并将问题以内联 Diagnostic 波浪线展示，同时提供 Quick Fix 一键修复。

| 指标 | 计算口径 | 数据来源 |
|---|---|---|
| **每日校验触发次数** | `count(yaml.validation.issues)` 按天聚合 | `yaml.validation.issues` |
| **平均每次校验问题数** | `avg(total)` | `yaml.validation.issues.total` |
| **错误 / 警告占比** | `sum(errorCount) / sum(total)` vs `sum(warningCount) / sum(total)` | `yaml.validation.issues.errorCount / warningCount` |
| **问题数分布（直方图）** | 按 `total` 分桶（1-5 / 6-10 / 11-20 / 20+） | `yaml.validation.issues.total` |
| **文件格式分布** | 按 `ext` 分组 | `yaml.validation.issues.ext` |
| **每日修复次数** | `count(yaml.fix.applied)` 按天聚合 | `yaml.fix.applied` |
| **平均每次修复行数** | `avg(fixCount)` | `yaml.fix.applied.fixCount` |
| **有问题的文件中用户触发修复的渗透率** | `distinct(sessionId from yaml.fix.applied) / distinct(sessionId from yaml.validation.issues)`（同天） | 两个事件关联 |
| **修复后仍然有问题的残留率** | 同 sessionId 同文件，`yaml.fix.applied` 后 5s 内 `yaml.validation.issues.total > 0` 的比例 | 需要同文件时序分析 |

> 校验触发场景：打开文件、保存文件、内容变更（500ms 防抖）、窗口重载（Cmd+R）。修复支持单行修复和全部修复两种模式。

## 四、错误与异常（质量看板）

按事件名前缀分组，每个事件都自带 `errorMessage` / `stackHead` 便于聚类。

| 类别 | 关键事件 |
|---|---|
| **推送链路异常** | `editorPush.failed` / `explorerPush.failed` / `editorPush.writeBackFailed` / `explorerPush.writeBackFailed` / `editorPush.allFailSnapshotFailed` / `editorPush.reparseFailed` |
| **后端 API 失败** | `api.pushTestCase.fail` / `api.pushTestCase.exception` / `api.fetchTaskTree.fail` / `api.queryTestCases.done[returnCode != SUC0000]` / `api.batchImport.done[returnCode != SUC0000]` |
| **鉴权失效** | `api.auth.unauthorized[api, httpStatus]`（401/403） |
| **网络层** | `http.request.error[errCode, target]` / `editor.network.error` / `http.sm2.signFailed` |
| **持久化文件健康** | `snapshot.load.failed` / `snapshot.load.invalidFormat` / `snapshot.save.failed` / `snapshot.init.failed` / `snapshot.initFailed` / `fileIdentifier.read.failed` / `fileIdentifier.write.failed` / `fileIdentifier.write.noWorkspace` / `highlight.initFailed` / `pushFailure.initFailed` / `deletedRows.initFailed` |
| **业务规则违常**（必须强报警） | `editorPush.templateExampleLeaked` / `explorerPush.templateExampleLeaked`（样例行漏过过滤） |
| **未捕获异常** | `extension.unhandledRejection` |
| **编辑器异常** | `editor.testcaseId.saveFailed` / `editor.message.error` / `editor.save.error` / `editor.push.error` / `editor.keepEditor.failed` |
| **命令级异常** | `command.openWithEditor.error` / `command.openWithText.error` / `command.tableBrowser.open.error` / `command.viewOnline.error` / `explorerPush.commandError` / `createNewTestCase*.commandError` |

**关键运营指标**：

- **崩溃率** = `extension.unhandledRejection` 用户数 / DAU
- **业务违常率** = `*.templateExampleLeaked` 次数（理想 = 0，>0 即报警）
- **登录态失效率** = `api.auth.unauthorized` 用户数 / 当日活跃用户数
- **后端错误码 Top10**：聚合 `api.*.returnCode`，识别哪个 returnCode 是主要噪音
- **持久化文件损坏率**：`snapshot.load.invalidFormat / snapshot.load.failed` / 总会话数

## 七、推荐的 5 张运营仪表盘

按"看一眼能立刻得出结论"的原则，不要堆事件，要堆指标。

1. **总览盘**：DAU/WAU/MAU、版本分布、平台分布、激活耗时 P95、崩溃率
2. **推送质量盘**：行级成功率（趋势）、`pushResult` 堆叠柱、错误码 Top10、推送耗时 P95、aborted 原因 Top
3. **错误盘**：所有 `*.failed / *.error / *.exception` 事件的小时计数 + 报警阈值（含 `templateExampleLeaked` / `api.auth.unauthorized` 强报警）
4. **功能渗透盘**：每个核心命令的日触发用户数（`command.executed`）、核心漏斗的转化率
5. **性能盘**：激活耗时、推送耗时、查询耗时分位线（按版本 / 平台拆分）

#### 8.3.0 推送结果的失败分类 + 字段维度（`*.complete` / `*.aborted` / `*.failed` 共享）

所有推送结局事件都会携带以下 4 组维度，用于**大盘失败分布分析**。全部为字符串，`Breakdown` 为 `"key:count,key:count"` 形式，`top*` 为单个字段名（无命中时为 `""`）。

##### ① 行计数（基盘）

| 字段 | 含义 |
|---|---|
| `totalRows` | 文件解析出的**原始总行数**（含样例、含被过滤行） |
| `successRows` | 接口返回 `SUC0000` 且行内无错误的行数 |
| `failedRows` | 最终失败行数 = `preValidationFailedRows` + 接口失败行 |
| `preValidationFailedRows` | **本地预校验**拦截的行数（未调接口的部分） |
| `costMs` | 端到端耗时（含接口调用+回写+快照，毫秒） |

##### ② 失败分类（横向聚合）

| 字段 | 示例值 | 含义 |
|---|---|---|
| `failCategoryBreakdown` | `"fieldMissing:42,duplicate:8,network:2"` | 按错误短码聚合的分布 |
| `topFailCategory` | `"fieldMissing"` | 上表 count 排名 top1 |

> `category` 枚举：`fieldMissing`（缺必填字段）/ `fieldInvalid`（字段格式非法）/ `duplicate`（sourceId 已存在或案例重复）/ `network`（网络异常）/ `auth`（权限失败）/ `mapError`（客户端字段映射失败）/ `placeholder`（占位 testcase_id）/ `emptyTestcaseId`（空 testcase_id）/ `backendReject`（后端非 SUC0000 但无具体分类）/ `unknown`。

#### 8.3.1 多文件批量推送（`explorerPush.batch.*`）

> 与 §8.3.0 的单文件推送事件**并行发送**：外层 6 个批次事件 + 内层每个文件仍走 §8.3.0 的 `explorerPush.complete/aborted/failed`。batch 事件**只做文件/批次维度聚合**，不重复统计行级/字段级失败——「哪个字段错最多」需下钻单文件事件。

| eventName | props | 触发时机 |
|---|---|---|
| `explorerPush.batch.start` | `fileCount, extBreakdown` | 批次启动 |
| `explorerPush.batch.fileResult` | `ext, resultType, succ, fail, total` | 每个文件推送完 |
| `explorerPush.batch.cancelled` | `fileCount, completed, remaining, durationMs` | 用户中途取消 |
| `explorerPush.batch.postRefresh` 🆕 | `refreshed, total` | 批次结束后统一刷新已打开 webview 面板 |
| `explorerPush.batch.openFile` | `ext, hasError` | 用户从总结面板点开某个文件 |
| `explorerPush.batch.done` | `fileCount, totalSucc, totalFail, errorFiles, cancelled, durationMs, extBreakdown` | 批次汇总 |

**关键字段语义**：

- `resultType ∈ { success, partialFail, error }`：单文件三态（全成功 / 部分行失败 / 整文件异常）
- `extBreakdown` = `"csv:3,yaml:2"`：`batch.start` 是输入分布，`batch.done` 是已处理结果分布
- `completed / remaining`（`batch.cancelled`）：用户在第几个文件放弃的判定依据
- `refreshed / total`（`batch.postRefresh`）：批次结束时**只刷新已打开的 webview 面板**（性能优化，避免循环内每文件全量刷新），未打开的文件由 `pushFailureStore.json` 持久化
- `hasError`（`batch.openFile`）：`"1"`=点的失败文件 / `"0"`=点的成功文件
- `cancelled`（`batch.done`）：`"1"`=批次被取消 / `"0"`=正常完结
- `errorFiles`（`batch.done`）：`resultType='error'` 的文件数（整文件挂的量）

**典型分析（batch 独有维度）**：

- **平均一次拖几个文件** → `avg(explorerPush.batch.start.fileCount)`
- **文件全挂率** → `count(batch.fileResult where resultType='error') / count(batch.fileResult)`（单文件事件算不出此维度）
- **用户放弃点** → `avg(batch.cancelled.completed / batch.cancelled.fileCount)`
- **面板刷新覆盖** → `avg(batch.postRefresh.refreshed / batch.postRefresh.total)`，反映批量推送时"用户当前打开的文件占比"
