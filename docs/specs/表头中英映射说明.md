# 表头中英映射 配置说明

本文档介绍测试案例编辑器中 **表头 / 详情弹窗的英文字段 → 中文别名映射** 功能：用途、配置方式、优先级、热更新、常见问题与排查。

> 配置项：`testcaseViewer.headerLabels`
> 影响范围：**表格表头** 与 **单元格详情弹窗（复杂数据查看弹窗）**
> 数据安全：**仅用于显示**，不会写入任何数据文件（yaml / csv / json）

---

## 一、能干什么

打开测试案例（yaml / csv / json）后，表格列名默认是英文 key（如 `testcase_id`、`path`、`priority`）。配置中英映射后：

- **表格表头**：每列变成 **两行** —— 第一行英文 key，第二行中文别名；
- **详情弹窗**：复杂数据点击展开后，左侧字段名以 「英文 中文」 形式 **同行** 展示。

未配置中文且不在 [插件内置默认](#三优先级) 中的字段，**只显示英文 key**，不会出现空白或占位行。

---

## 二、在哪里配置

`testcaseViewer.headerLabels` 是一个 **对象（key-value）**，key 为数据中的英文字段名，value 为想要展示的中文。可在以下任一位置配置（VSCode 自动合并）：

### 方式 1 · 工作区设置（推荐，团队共享）

在打开的工程根目录创建/编辑：

```
<打开的工程根>/.plugin/.tms/headerLabels.json
```

> ⚠️ 注意：工作区根 = 你在 VSCode 中「打开的那个文件夹」，**不是项目仓库根**。
> 例如打开的是 `C001_测试/`，那就放到 `C001_测试/.plugin/.tms/headerLabels.json`。

示例：

```jsonc
// .plugin/.tms/headerLabels.json
{
  "testcase_id": "用例ID",
  "testCaseNo": "用例编号",
  "testCaseName": "用例名称",
  "path": "路径",
  "priority": "优先级",
  "type": "类型",
  "tags": "标签",
  "preconditions": "前置条件",
  "steps": "步骤",
  "expected": "预期结果",
  "status": "状态",
  "remark": "备注",
  "owner": "负责人"
}
```
```

把这份 `headerLabels.json` 提交到 Git，团队成员都能享受同一套中文表头。

### 方式 2 · 用户全局设置（个人偏好，所有工程通用）

`Cmd + ,` 打开设置 → 搜索 `testcaseViewer.headerLabels` → 点击「在 settings.json 中编辑」，写入相同结构。

适用：希望所有工程默认带某些中文映射，又不污染业务仓库。

## 三、优先级

VSCode 会自动按以下顺序合并（**靠后的覆盖靠前的**）：

```
插件内置默认值  <  用户设置  <  工作区设置（最高）
```

> 项目 `package.json` 中已内置常见字段的中文映射（如 `testcase_id`、`path`、`priority`、`steps`、`expected`、`ui-expected` 等约 20+ 项），开箱即用。
> 同一个 key 在多层都出现时，工作区设置 winner；未在任何层出现的 key 表头只显示英文。

举例：

| 来源 | `path` 配置 | 最终生效 |
|---|---|---|
| 内置默认 | `"path": "路径"` | |
| 用户设置 | `"path": "用户路径"` | |
| 工作区设置 | `"path": "工作区路径"` | ✅ **工作区路径** |

如果想 **去掉** 某个内置默认（比如不希望 `path` 显示中文），可在用户/工作区设置里把 value 设为空字符串：

```jsonc
{ "testcaseViewer.headerLabels": { "path": "" } }
```

> ⚠️ value 为空字符串时，前端不会渲染中文行（因为代码里判断 `typeof v === 'string' && v` 才显示）。

---

## 四、热更新

修改 `headerLabels.json` 并保存后：

- **表头**：自动刷新，**无需重开文件**；
- **详情弹窗**：下次打开弹窗时取新值。

实现位置：[`src/utils/headerLabels.ts`](src/utils/headerLabels.ts) 的 `onHeaderLabelsChange()` 监听 VSCode 配置变更事件。

---

## 五、字段命名约定

- **大小写敏感**：`testCaseNo` 与 `testcaseno` 不等价，必须与数据文件中字段名完全一致；
- **特殊字符 key 加引号**：如 `ui-expected`、`api-expected` 这类带连字符的 key，JSON 里本来就要加引号，无需特殊处理；
- **未在配置中出现的字段**：表头只显示英文 key，详情弹窗只显示英文 key，不会出现空白行或占位符。

## 六、常见问题

### Q1：保存了配置但表头还是英文

按顺序检查：

| # | 检查点 | 操作 |
|---|---|---|
| 1 | 文件名是 `headerLabels.json` 不是 `headerLabel.json` | `ls .plugin/.tms/` 确认 |
| 2 | 配置文件路径是「打开的那个工程根」 | 看 VSCode 标题栏的工程名 |
| 3 | JSON 是否合法 | `Cmd+Shift+P` → `Preferences: Open Workspace Settings (JSON)` 看是否能解析 |
| 4 | key 大小写与数据文件完全一致 | 打开 yaml 比对 |
| 5 | 插件是否加载新版本（开发模式） | `Developer: Reload Window` |

### Q2：如何确认配置已生效

打开 webview 开发者工具：`Cmd+Shift+P` → `Developer: Open Webview Developer Tools` → Console 输入：

```js
S.headerLabels
```

应该输出与 `headerLabels.json` 里完全一致的对象。如果是 `{}`，说明配置没读到。

### Q3：保存数据文件后中文会被写入 yaml 吗

**不会**。中文别名仅用于 webview 渲染，原始数据文件读写流程完全不受影响。可以保存后用文本编辑器再开 yaml 验证：里面仍是英文 key。

### Q4：表头与详情弹窗的中文不一致

不会发生，两处共用同一份 `S.headerLabels`。如果出现，请先确认两处取的是不是同一个 key（嵌套对象的子字段可能与外层重名）。

### Q5：能不能给同一个 key 在表头和弹窗设置不同中文

当前不支持，未来如有需要可扩展为 `key@detail` 后缀机制。如有诉求请提 issue。

## 八、最小可用示例

插件已内置常见字段（详见 [package.json](package.json) 的 `testcaseViewer.headerLabels.default`）。如果需要 **覆盖或扩展**，复制下面这份写入工作区即可：

```jsonc
// .plugin/.tms/headerLabels.json
{
  "testcase_id": "用例编号",         // 覆盖内置的 "用例ID"
  "customField1": "自定义字段1",     // 扩展内置没有的字段
  "path": ""                          // 隐藏某个内置中文（恢复纯英文）
}
```

如果完全不配置任何 `headerLabels.json`，打开测试案例文件也能直接看到 20+ 个常用字段的中文表头。
