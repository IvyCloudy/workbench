## 一、功能概述

YAML 案例文件在编写过程中常出现**缩进错乱、歧义值被误判、注释吞掉数据**等格式问题，导致编辑器无法正常打开文件，甚至出现**数据丢失**（重复字段覆盖、注释截断内容）。

本功能围绕 YAML 案例的完整编辑流程，提供三项能力：

1. **编辑时自动检测**：打开 / 编辑 YAML 文件时实时扫描，用波浪线标注问题，鼠标悬停看说明；
2. **一键修复**：在问题处点灯泡单行修复，或对整文件批量修复；
3. **命令行工具**：把同样的检测修复能力独立打包，供 AI 助手或自动化流水线调用。

> 检测与修复**不改变你的业务数据含义**：能安全修的自动修，无法安全自动修的行会被**改为注释**（保留原内容），由你人工确认，绝不直接删除数据。

## 二、编辑时自动检测

打开或编辑 YAML 案例文件时，插件自动扫描内容，无需任何手动触发。

### 2.1 问题标注

| 标注 | 含义 | 严重程度 |
|------|------|---------|
| 🔴 红色波浪线 | 严重问题，会导致解析失败或数据错误 | error |
| 🟡 黄色波浪线 | 提醒问题，可能影响数据含义但不阻断解析 | warning |

- 鼠标**悬停**波浪线可查看问题说明；
- 底部**问题面板**列出全部问题，点击可跳转到对应行；
- 检测按"由浅入深"顺序执行：先查文件头异常标记 → 逐行格式检查 → 全文重复字段扫描 → 解析库最终把关。

### 2.2 性能与智能识别

- **延迟检查**：停止输入约 0.5 秒（大文件 >200KB 延迟到 1 秒）后启动，避免编辑卡顿；
- **智能冒号识别**：自动区分"真冒号"（键:值分隔）与网址 `://`、引号内冒号、双冒号 `::` 等"假冒号"，避免误报；
- **歧义关键词覆盖**：`yes/no/on/off/null/true/false/NaN` 等 17 种写法的大小写变体，均被当作普通字符串提示，不会被误解析为特殊值。

## 三、一键修复

### 3.1 编辑器内操作入口

| 操作方式 | 效果 |
|---------|------|
| 点击波浪线 → 点灯泡按钮 💡 | 只修复**当前这一行** |
| 右键菜单 → **修复全部** | 修复整个文件所有 error + warning |
| 命令面板 → **修复严重问题** | 只修红色波浪线（error 级） |
| 命令面板 → **修复提醒问题** | 只修黄色波浪线（warning 级） |
| 选中多行 → 右键修复 | 只修选中范围内的行 |
| 状态栏按钮 / 命令面板 | 展示当前文件可修复问题数，由你选择执行 |

### 3.2 修复后反馈

- 修复完成会提示「共修复 N 处，还剩 M 处问题」；
- 所有修复合并为**一次撤销操作**，按一次 `Ctrl/Cmd + Z` 即可全部回滚；
- 修复后的文件可正常解析，再次检查不会重复报同样的问题。

## 四、可检测的问题类型

共 **14 类**格式问题，分三个层级。

### 第一层：逐行检查（8 类）

| 问题 | 严重程度 | 触发示例 |
|------|---------|---------|
| 文件头多余标记 | 提醒 | 文件首行有不可见特殊字符 |
| 使用了 Tab 缩进 | **严重** | `→→key: value`（Tab 而非空格） |
| 行内有 Tab | 提醒 | 键值之间混入 Tab |
| 行末多余空格 | 提醒 | `key: value··`（末尾空格） |
| 冒号后没留空格 | 提醒 | `key:value` |
| 值的写法有歧义 | 提醒 | `enabled: yes` 中 `yes` 被误判为布尔 |
| 值中的 `#` 可能被截断 | 提醒 | `url: http://abc#section` 中 `#section` 被当注释 |
| 值的写法含特殊符号 | 提醒 | `value: {a,b}` 本意是文字却被当语法 |
| 列表项缺空格 | 提醒 | `-item` 写成 `-item` |

### 第二层：全文检查（1 类）

| 问题 | 严重程度 | 说明 |
|------|---------|------|
| 同一级别下字段名重复 | 提醒 | 后面的字段覆盖前面的，**数据丢失风险** |

### 第三层：解析器兜底（5 类，需安装 YAML 解析库）

| 问题 | 严重程度 | 触发 |
|------|---------|------|
| 嵌套结构写法错误 | **严重** | 列表项嵌套 map 层级不对 |
| 引号忘了闭合 | **严重** | 引号不成对 |
| 缩进对不齐 | **严重** | 子内容没对齐到父级 |
| 解析器发现重复字段 | **严重** | 解析库报重复 key（覆盖更广） |
| 解析器非致命提醒 | 提醒 | 解析库一般提醒，不自动修 |

> 未安装 YAML 解析库时，前两层 10 类问题仍正常检测修复，第三层自动跳过，不影响使用。

## 五、各问题的修复方式

| 问题 | 怎么修复 | 说明 |
|------|---------|------|
| 文件头多余标记 | 删除多余标记 | 不影响其余内容 |
| Tab 缩进 | 每个 Tab → 2 个空格 | 符合 YAML 标准 |
| 行内 Tab | 替换为 1 个空格 | 仅替换不该出现 Tab 的位置 |
| 行末多余空格 | 清除尾部所有空白 | 含不可见不间断空格 |
| 冒号后没留空格 | 冒号后补空格 | 如 `enabled:yes` 直接修为 `enabled: "yes"` |
| 值的写法有歧义 | 给值加引号保护 | 智能选单/双引号避免冲突 |
| 值中 `#` 被截断 | 给值整体加引号 | 仅包裹"值是内容"的那段 |
| 值的写法含特殊符号 | 给值加引号保护 | 本身是合法 YAML（如 `[a,b]`）则跳过 |
| 列表项缺空格 | `-` 后补空格 | `--` / `---` 分隔线不处理 |
| 字段名重复 | 重复行改为注释 | **保留原内容**，方便审计 |
| 嵌套结构错误 | 优先包裹列表项后的值 | 从第一个冒号找起 |
| 引号忘了闭合 | 补齐缺少的闭合引号 | 单/双引号分别判断 |
| 缩进对不齐 | 该行改为注释 | 复杂错乱标记出来等人工检查 |
| 无法识别的错误 | 该行改为注释 | 兜底策略 |

## 六、批量修复与多轮修复

### 6.1 批量修复流程

对整文件一次性修复所有问题时：

1. 收集文件全部检测到的问题；
2. **从最后一行往前修**，避免行号变化错位；
3. 每 100 行一批，批间稍作停顿保持流畅；
4. 所有修复合并为一次撤销操作；
5. 修复后重新检查，告知「修复 N 处，剩 M 处」。

### 6.2 多轮修复（深层问题）

嵌套结构等深层问题，修好一个可能暴露之前隐藏的其他错误。修复会执行多轮"**检查 → 修复 → 再检查**"循环，直到无新问题，最多 **5 轮**，每轮确认内容有变化才继续，避免死循环。

---

## 七、修复冲突处理原则

一行同时触发多条规则时：

- **一步到位优先**：补空格后还需加引号，直接合并为加引号一次完成；
- **整体包裹优先**：歧义关键字紧贴 `#` 时，直接整体加引号包裹；
- **同一条行不重复修**：已被前几条规则修过的行，不再用解析器兜底规则改一次；
- **标记性修复后做**：把行改为注释的"破坏性修复"留到最后一批统一执行。

## 八、命令行工具（供 AI / 流水线）

检测修复能力独立打包为命令行工具（Node.js + Python 双版本），规则与编辑器版完全一致。AI 助手只需调用命令行即可完成修复，无需把文件读进对话，节省 Token 且避免误改。

### 8.1 运行模式

| 模式 | 用途 |
|------|------|
| 默认 | 检测并直接写入修复后的内容 |
| 预览 | 只看问题和修复方案，不改文件 |
| 详细 | 输出每条问题的修复前后行对比 |
| JSON | 机器可读结构化数据，接入流水线 |

### 8.2 执行结果码

| 返回码 | 含义 | 处理建议 |
|--------|------|---------|
| `0` | 所有严重问题已修复 | 流程通过 |
| `2` | 还有严重问题没修完 | 人工检查或再跑一次 |
| `1` | 工具运行出错（文件找不到/无权限） | 检查环境和文件 |

> 部分深层问题可能需跑 1~2 次才能完全修干净，工具会在输出中给出提示。

### 8.3 与编辑器版一致性

命令行版与 VS Code 编辑器版基于**同一套规则定义**：检测规则、执行顺序、歧义关键词、冒号识别逻辑、重复字段检测、引号包裹策略完全一致，保证不同场景结果相同。

## 九、常见问题

### Q1：黄色波浪线要不要管？

warning 级提醒（如 `yes` 歧义、行末空格）不一定阻断解析，但**可能导致数据含义被改变**（如 `enabled: yes` 被当成布尔）。建议推送前修复，尤其是涉及值语义的场景。

### Q2：修复会把我的数据删掉吗？

不会。能安全自动修的会直接修正；无法安全自动修的行（如复杂缩进错乱）会被**改为注释保留原内容**，由你人工确认，绝不删除数据。重复字段也会保留在注释里。

### Q3：为什么有些问题标红、有些标黄？

红色（error）是会**导致解析失败或数据错误**的严重问题；黄色（warning）是提醒类，可能影响含义但不阻断解析。修复「严重问题」可快速消除阻断打开/推送的障碍。

### Q4：YAML 解析库没装会有影响吗？

不影响基础使用。未安装时仅跳过第三层 5 类深层解析问题（前两层 10 类照常检测修复）。安装解析库后自动启用增强版全部 14 类。

### Q5：修复后还能撤销吗？

能。所有修复合并为一次撤销操作，按一次 `Ctrl/Cmd + Z` 全部回滚。

### Q6：大文件会不会卡？

不会。普通文件停止输入 0.5 秒后检查，>200KB 文件延迟到 1 秒，批量修复按 100 行分批并保持流畅。
