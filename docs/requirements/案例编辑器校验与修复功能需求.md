## 1. 背景与目标

当前案例推送失败率较高，而现有度量体系（`pushFailureCategory` + `*.complete` 埋点）均为**推送之后**才生效——一次失败意味着：一次失败的接口调用、一次失败的回写、一次用户等待。

从推送链路（`pushCore.stages.ts`）看，推送前的本地拦截仅有 4 道（任务绑定、`testcase_id` 占位/空/格式、模板样例行、YAML 语法）。而真实后端报错场景（`推送失败度量说明.md` §4 的 43 类）中，**绝大多数行级字段错误（empty / length / enum / format）和全部接口级字段错误（designer / artifactId / sourcePlatform）都未在前置阶段拦截**，直接打到后端才返回失败。

**本功能目标**：在案例编辑器（表格 webview）内提供「校验」按钮，用户点击后对全表做数据校验，把"哪一行、哪一格、什么问题"精确呈现；对其中**确定性可修复**的问题（必填空值、格式可归一化项）提供「一键修复」，直接在表格内写回具体单元格并落盘，把高频失败从"推送后才发现"前移到"编辑期主动发现 + 修复"。

**与现有 YAML 修复的关系（重要）**

下表对比本功能与既有 YAML 修复的定位，二者互补而非冲突：

| 维度 | 现有 YAML 修复（YamlFixProvider） | 本功能（编辑器校验 + 修复） |
|------|-----------------------------------|---------------------------|
| 作用对象 | YAML **文本行**（语法层：缩进 / 重复键 / 解析错误） | **字段 / 单元格**（语义层：空值 / 枚举 / 格式） |
| 触发位置 | 文本编辑器灯泡菜单 / 命令面板 | 案例编辑器（表格 webview）工具栏 + 结果面板 |
| 修复落点 | 整行文本替换 | 具体 `[row, col]` 单元格值 |
| 复用关系 | 独立 | 复用其“批量修复”心智 + 同一落盘通道 |

两者互补：YAML 修复解决"文件打不开 / 解析错"；本功能解决"能打开但推不过"。

## 2. 术语与前提

| 术语 | 含义 |
|------|------|
| 单元格 `[row, col]` | 主表中具体一格，`row` 为数据行下标（0-based），`col` 为列下标（0-based），与既有 `highlightedCells.cells` 坐标体系一致 |
| 字段码 `field` | 底层英文 key（如 `testCaseName` / `testCasePath` / `description` / `expected`），经 `headerLabels` 映射为中文列名展示。**后端只回传 `field`，`col` 由前端用 `headerLabels` 反查得到**（避免后端依赖前端列序） |
| `CellIssue` | 一条校验问题，携带 `row / field / category / reason / fixable / fixValue / suggestion`（`col` 不在此结构中，前端映射后补全）。**同一 `[row, col]` 可能命中多条规则（如空值 + 超长 + 非法字符），前端按格聚合为一条展示**（见 §3.3 修复步骤） |
| 可修复（A/B 类） | A 类：必填空值，可确定性填默认值；B 类：格式可归一化（路径非法字符、枚举同义词归一、大小写），修复值确定 |
| 不可修复（C 类） | 需业务判断（语义不符、枚举选错具体值、长度超限需删减），只定位 + 建议值文案，不自动改 |
| 冻结行 / 冻结列 | 样例数据行（`testcase_id` 占位值）整行只读；`testcase_id` 列系统列不可编辑（既有冻结行 / 冻结列约束） |
| 行级校验能力 | 校验按钮与推送预校验共用的行级字段校验能力，非抛错式收集一行内全部问题，复用既有的必填 / 长度 / 枚举 / 格式约束；具体函数形态属技术实现（见配套技术设计文档），不在需求范围 |
| `highlightedCells.cells` | 既有单元格高亮机制，结构为 `[row, col]` 数组；本功能前端将 `CellIssue` 映射为该项以触发红底 |

## 3. 功能需求

### 3.1 工具栏「校验」按钮

#### 需求背景与目标
用户编辑案例后、推送前，缺少一个"先自查"的入口。目标是：在编辑器工具栏提供常驻「校验」按钮，点击后跑一遍行级字段校验，给出"可推送性"结论，而非等到推送才报错。

#### 交互与功能规则
- **入口位置**：工具栏新增「校验」按钮，与现有「推送」「查找」按钮并列。
- **校验范围**：
  - **默认校验全表**：对所有非样例行执行行级校验。
  - **选中范围校验为后续增强**：若用户已框选单元格，当前仍按全表校验；仅选中范围校验列为后续增强。
  - **过滤视图（如"仅看失败行"）下的可见性**：校验基于全量数据行（不受前端过滤影响），但结果面板可与过滤视图叠加显示；"隐藏行误伤"风险见 §5.2。
- **触发行为**：点击后触发一次行级校验（基于当前已加载的表格数据，无需重新解析文件），略过样例行，对每行收集校验问题并回推结果。
- **结果呈现**：以「校验结果面板」（复用编辑器现有的结果弹窗样式）列出每条问题；无问题时提示"校验通过，可推送"。
- **与推送预校验一致性**：校验规则应与推送前的本地预校验规则共用同一份字段约束（以推送预校验为唯一权威源），确保"校验通过"即代表"推送时不会因行级字段错失败"；任一侧新增 / 修改字段约束须同步另一侧。

### 3.2 单元格级问题定位

#### 需求背景与目标
推送失败弹窗只能给"行号 + 文案"，用户还要自己找列。目标是：校验发现的每个问题都能**精确高亮到具体单元格**，用户一眼看到"哪一格"有问题。

#### 交互与功能规则
- **列映射**：后端回传 `field`（英文 key），前端经表头映射关系反查 `col`（列下标）；若某 `field` 在当前表头中**找不到对应列**（如新增字段未纳入映射、或中文表头列名漂移），则降级为**高亮整行**并在面板标注"列缺失，请检查表头映射"，不静默丢弃该问题。
- **红底高亮**：每条 `CellIssue` 经单元格高亮机制精确渲染到具体单元格，复用现有单元格级红底样式。同一格的多条问题聚合为一条展示（见 §3.3），高亮与定位均作用于该 `[row, col]` 单格。
- **点击定位**：结果面板每条问题带「定位」按钮，点击滚动到该格并临时聚焦高亮；与现有"推送失败行定位"体验一致。
- **字段名可读**：面板显示「行 N · 中文列名（field）· 原因」，中文列名经 `headerLabels` 映射得到，便于非技术用户理解。

### 3.3 单元格级「一键修复」

#### 需求背景与目标
校验发现的问题中，相当一部分是"必填空着"或"格式不标准"这类确定性错误，本可由系统直接补正，无需用户逐项手填。目标是：对 A/B 类可修复问题，提供单条「修复」+ 顶部「一键修复全部可修复项」，直接在表格内写回具体单元格并落盘。

#### 交互与功能规则
- **修复值来源**：A 类填默认值、B 类做归一化，取值以系统级内置兜底为基准（复用既有字段默认值与枚举归一规则），并允许通过配置覆盖（见下「修复步骤与值的配置」）。
  - **系统级兜底值清单**：
    - A 类：`testCaseName.empty`→`'未命名'`、`type.empty`→`'功能点类'`、`description/testCaseDes.empty`→占位描述文本、`expected.empty`→占位预期文本、`keyFlag` 空值按 `'否'` 兜底。
  - **B 类归一化**：`testType` 口语归一（`接口`→`接口自动化`、`界面`→`UI自动化`，或 `手工/自动化` 等白名单）；`keyFlag`（`是/否` 同义归一）；其余枚举大小写 / 同义词归一。
  - **关于 `designer` / `artifactId` / `sourcePlatform`**：这些属于**接口级字段**，纯本地无法判定其合法值（需调后端），因此**不纳入 A/B 类自动修复范围**，仅 C 类提示用户手填（见 §5.1）。
  - 校验时给出的建议值与修复时写入的值须完全一致（均取自同一份生效配置）。
- **单条修复（单元格级，按格聚合）**：结果面板以**单元格**为最小粒度展示与修复——同一 `[row, col]` 即使命中多条规则（如空值 + 超长 + 非法字符），也**聚合为一条**显示，只提供一个「修复」按钮。点击后对该格执行一条**修复步骤**：按配置决定的优先级依次应用该格内所有 A/B 类修复动作，一次计算最终值并写回该格；单条操作不弹确认框——影响范围仅限该格、且可撤销（`Ctrl+Z`）。
  - **与 C 类共存**：若同格混有 C 类问题，聚合条内 A/B 类提供「修复」、C 类仅提供「定位 + 建议值文案」，两者按钮分离、互不影响；C 类不自动改。UI 上同一聚合条内，A/B 类「修复」按钮与 C 类「定位」按钮分列两行（A/B 修复区在上、C 类引导区在下），避免操作混淆。
  - **不选"每问题一按钮"**：避免同格多按钮视觉混乱，以及多次写回同一格导致后一个 `fixValue` 基于旧值失效的竞争问题。
- **修复步骤与值的配置**：修复动作的**执行顺序**及**兜底值/归一目标值**均为可配置项，而非硬编码。
  - **配置内容**：
    - **步骤优先级**：同格多 A/B 类动作的执行次序可配置（如"填空值兜底"与"去非法字符/归一化"谁先谁后）。
    - **兜底值与归一目标**：A 类各字段空值兜底文本、B 类枚举归一目标值，可由配置覆盖系统内置默认。
  - **默认配置**：未提供配置时，使用系统内置默认——默认顺序为"填空值兜底 → 去非法字符 / 归一化 → 大小写 / 同义词归一"，默认兜底值与归一目标见上「系统级兜底值清单 / B 类归一化」。
  - **配置作用域与承载形式**：采用**系统级配置**——由扩展统一提供一份系统级配置文件（随扩展分发，对所有用户/项目生效），集中定义修复步骤优先级与各字段兜底值 / 归一目标值。系统级配置为统一基准，本项目不引入项目级或用户级覆盖层（如需分级覆盖，列为后续增强）。
  - **一致性约束**：校验时给出的建议值与修复时写入的值须严格取自**同一份生效配置**（默认或覆盖后），避免建议与写回不一致。
- **批量修复**：结果面板顶部「一键修复全部可修复项」按钮，遍历所有 `fixable` 项写入，最后统一落盘（对齐现有"批量填充选区"逻辑）。**执行前弹一次二次确认**（"将自动填充 / 归一化 N 个单元格，是否继续"），避免静默改数据。
- **落盘通道（复用，不新增）**：修复须复用编辑器既有的单元格回写能力（写值 → 标记已改 → 保存落盘 → 刷新单格视图），不新增写入通道。
  - **与"未保存保护"的关系**：修复写回后状态等同用户手动编辑（黄底=已改）且已落盘，因此推送前无需再次保存；若用户未触发保存直接点推送，推送预校验读取的是最新内存数据，仍可正常推送。
- **安全护栏**：
  - 冻结行、冻结列**不修复**，沿用既有拦截提示。
  - 修复前记录历史，用户可 `Ctrl+Z` 撤销整批改写。
  - 样例行（占位 `testcase_id`）不参与修复。
- **修复后反馈**：单条 / 批量修复完成后，结果面板中对应条目置灰或标记为"已修复"，并**提供「重新校验」按钮**一键重跑校验，便于用户确认修复效果；「重新校验」复用工具栏「校验」同一逻辑（全表校验）。

### 3.4 不可修复项的引导

#### 需求背景与目标
C 类问题（语义不符、需业务判断）系统不应擅自改写，否则可能破坏案例真实性。目标是：对这类问题只做"定位 + 建议值文案"，由用户手改。

#### 交互与功能规则
- **C 类处理**：不显示「修复」按钮，仅显示「定位」+ 原因说明 + **建议值文案**，但建议值**不自动写入**，由用户手改。建议值仅在结果面板以文案展示，不触发任何写盘。
- **建议值文案来源（明确）**：
  - 若为"枚举非法但非别名"（如 `testType` 拼错）：建议值 = 枚举白名单列表（如"建议改为：手工 / UI自动化 / 接口自动化 / 自动化"）——**静态话术，由系统枚举白名单生成**。
  - 若为"步骤 / 预期缺失"：建议值 = 通用补全提示（如"建议至少补充一个步骤"）——**静态话术**。
  - 若为"语义数量不一致"（预期数 ≠ 步骤数）：当前**仅给提示文案，不计算具体建议值**（动态计算预期内容超出当前需求范围）；如需动态，列为后续增强。
- 结果面板顶部「一键修复全部可修复项」仅作用于 A/B 类，C 类保持原样并在面板中标注"需手动处理"，其建议值仅作展示。

## 4. 用户操作流程

### 4.1 校验并定位
1. 在案例编辑器编辑案例，点击工具栏「校验」。
2. 系统跑行级校验（默认全表；选中范围校验为后续增强），弹出校验结果面板。
3. 面板按**单元格**列出每条问题（同格多问题聚合为一条）：「行 N · 中文列名 · 原因（可含多条）」+「定位」/「修复」按钮（C 类仅有「定位」；C 类与 A/B 类共存时按钮分离）。
4. 点击「定位」，表格滚动到该格并红底高亮；若列缺失则高亮整行。

### 4.2 一键修复
1. 校验结果面板中，A/B 类问题显示「修复」；点击单条「修复」即时写回该格并落盘（黄底=已改），无需确认。
2. 点击顶部「一键修复全部可修复项」→ 二次确认 → 批量写回所有可修复项 → 一次落盘。
3. 修复后 `Ctrl+Z` 可整体撤销。
4. 点击「重新校验」（复用工具栏「校验」逻辑）确认修复效果；C 类问题保持"需手动处理"标记，用户按需手改。

### 4.3 修复后推送
1. 修复完成（或确认无 C 类阻塞）后点击「推送」。
2. 因行级字段错已被修复，推送预校验不再因这些问题失败，失败率下降。
3. **注意**：接口级字段（designer / artifactId / sourcePlatform）无法本地校验，仍需推送后才能发现（见 §5.1）。

## 5. 边界、风险与对策

### 5.1 必须明确的边界
- **接口级错误无法本地修复**：`designer` / `artifactId` / `sourcePlatform` 等只有调后端才知道对错，纯本地校验无法发现，也不能自动修复（不在 A/B 类范围内）。"校验通过"≠"一定推送成功"，需在面板提示此边界，避免用户误解。
- **C 类只定位不修（仅给建议值）**：语义类问题（预期与步骤数不一致、枚举选错具体值）系统不擅自改写，防止破坏案例真实性（见 §3.4）。
- **空表 / 仅样例行边界**：文件为空或所有数据行均为样例行时，点「校验」应提示"无可校验的数据行（均为样例行或文件为空）"，而非空面板或报错。
- **过滤视图叠加**：校验基于全量数据行，结果面板可与"仅看失败行"等过滤视图共存；若用户处于过滤视图，修复操作仍作用于全量中命中的单元格，不限于可见行（避免隐藏行漏修或误修，具体策略见 §5.2）。

### 5.2 风险与对策
| 风险 | 对策 |
|------|------|
| 修复值误改业务语义 | A 类仅填空值兜底（来自系统级配置）、B 类仅做确定性归一化（来自系统级配置）；**「一键修复全部」批量操作前**二次确认，单条修复免确认；修复前记录历史可整体撤销 |
| 列映射失败导致问题丢失 | 前端字段→列反查失败时降级为整行高亮 + 面板标注"列缺失"，不静默丢弃 |
| 隐藏行 / 过滤视图下误伤或漏修 | 基于全量数据行修复，不区分可见性；后续增强"选中范围"校验时再按范围裁剪，与批量填充逻辑一致 |
| 校验规则与推送不一致 | 校验与推送预校验共用同一份字段约束（以推送预校验为唯一权威源），单方改动需同步维护 |
| 冻结行 / 列被修复 | 修复前复用既有冻结行 / 列拦截 |
| 修复值来源不一致 | 取值统一为同一份生效的系统级配置（§3.3），保证校验建议值与修复写入值一致 |

## 6. 验收标准

1. **校验按钮**：工具栏出现「校验」按钮；点击后对**全表**跑校验，弹出结果面板，无问题时提示"校验通过，可推送"；空表 / 仅样例行时提示"无可校验数据行"。
2. **单元格定位**：每条问题精确红底高亮到 `[row,col]`（列由 `field` 映射；映射失败时高亮整行并标注）；点「定位」滚动并聚焦该格；面板显示中文列名 + 原因。
3. **一键修复**：A/B 类问题显示「修复」按钮，单条点击即写回并落盘（黄底，免确认）；「一键修复全部可修复项」弹二次确认后批量写回、一次落盘；`Ctrl+Z` 可撤销；冻结行 / 列不被修复；修复值取自系统级配置（默认或覆盖后）定义的兜底值（不含 designer/artifactId 等接口级字段）。
4. **C 类处理**：只定位 + 建议值文案（静态话术，由枚举白名单 / 通用提示生成），不自动改；批量修复作用于 A/B 类，C 类保持"需手动处理"标注。其中"预期数 ≠ 步骤数"这类语义数量不一致项仅给提示文案、不计算具体建议值。
5. **一致性**：校验与推送预校验共用同一份字段约束（以推送预校验为唯一权威源）；修复值取自系统级配置（默认或覆盖后）定义的兜底值与归一目标，不新造规则。
6. **边界**：面板提示"校验通过≠一定推送成功（接口级错误需推送才发现）"；修复不误伤冻结行/列、不改动 C 类语义；列缺失不导致问题丢失。
7. **修复后反馈**：单条 / 批量修复后，结果面板对应项标记"已修复"或提供「重新校验」入口，用户可确认修复效果。
