# 新增测试要点文件功能需求文档

> 文档视角：业务 / 用户（案例编辑者、测试负责人）
> 适用范围：在「测试任务 / <子任务文件夹> / 测试大纲 /」目录体系下，通过资源管理器右键或命令面板快速新建测试要点文件（Markdown / XMind）
> 说明：本文档描述用户需要的能力、业务规则与验收标准，不涉及具体实现方式。

---

## 1. 总体背景与目标

测试要点（测试大纲）以 Markdown 或 XMind 形式维护于「测试任务」目录体系下，作为测试案例的上游输入与关联检索对象。过去新建要点需手动建文件并补齐大纲层级结构，门槛较高。本功能目标是提供"一键新建 + 模板预填 + 自动打开编辑"的轻量入口，让用户快速产出规范结构的测试要点。

总体目标：
1. **多入口新建**：资源管理器右键「测试大纲」目录 / 子文件夹 / 其下已有文件，或命令面板执行命令，均可触发新建。
2. **格式可选**：支持 Markdown（.md，表格格式）与 XMind（.xmind，思维导图格式）两种格式。
3. **模板预填**：新建 Markdown 自带标准大纲层级与测试点表格结构；XMind 从合法二进制模板复制生成，保证可直接打开。
4. **与测试案例创建隔离**：要点创建不写入命令创建记录、不显示装饰器、不显示状态栏创建信息，保持"零侵入"——与测试案例文件的命令创建标识体系明确区分。

---

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 测试大纲目录 | 固定目录名 `测试大纲`，文件必须位于该目录或其子文件夹下才被识别为测试要点 |
| 命令创建（要点） | 通过右键「新增测试要点」子菜单或命令面板命令创建的要点文件 |
| Markdown 模板 | `examples/point_example.md`，含「1. 测试大纲」「1.1 测试点列表」层级与测试点表格 |
| XMind 模板 | `examples/point_example.xmind`，合法二进制模板文件 |
| 命令创建记录 | 工作区 `.plugin/.tms/testcase-viewer/created-files.json`；要点文件**不**写入该记录 |

## 3. 功能需求

### 3.1 新建入口触发

#### 需求背景与目标
新建入口需贴合用户习惯，且菜单仅出现在「测试大纲」体系内，与「新增测试案例」菜单严格隔离，避免误建文件到错误目录。

#### 交互与功能规则
- **资源管理器右键子菜单**：在 `测试任务 / <任务名> / 测试大纲` 文件夹（或其下任意子文件夹、或其下的 .md/.xmind 文件）上右键，上下文菜单出现「新增测试要点」子菜单，展开后含「Markdown (.md)」与「XMind (.xmind)」两项；右键文件时以文件 dirname 为创建目录。
- **命令面板入口**：命令面板可检索「新增测试要点」，执行后弹出格式选择 QuickPick（Markdown / XMind），选择后按当前活动文件所在测试大纲目录创建。
- **入口隔离**：「新增测试要点」菜单仅出现在测试大纲目录 / 文件上，测试案例、任务根目录等位置不显示，与「新增测试案例」菜单互不串菜单。

### 3.2 目录校验

#### 需求背景与目标
新建位置必须落在「测试大纲」目录体系内，否则文件将不被识别为测试要点。校验失败需明确提示而非静默生成游离文件。

#### 交互与功能规则
- **合格目录创建**：目标路径包含「测试大纲」字样时校验通过，文件创建于该目录（右键文件夹即自身，右键文件即其 dirname，子文件夹内创建保持层级不提升）。
- **非合格目录拒绝**：目标路径不含「测试大纲」时，弹出警告「只能在测试大纲目录或其子文件夹中创建新测试要点」并终止，不创建任何文件，不破坏工作区结构。

### 3.3 格式选择与模板内容

#### 需求背景与目标
Markdown 与 XMind 两种格式面向不同编辑习惯，模板需分别正确生成：Markdown 预填大纲结构，XMind 复制合法二进制模板。

#### 交互与功能规则
- **子菜单免弹窗**：右键子菜单直接选「Markdown / XMind」时跳过格式 QuickPick，按所选扩展名直接创建（Markdown 用 `point_example.md` 模板内容，XMind 从 `point_example.xmind` 二进制复制）。
- **命令面板弹窗选择**：无预设格式时弹出 QuickPick 列出 Markdown(.md)/XMind(.xmind)（描述分别为"表格格式"与"思维导图格式"），Markdown 在前；取消选择则不创建文件。
- **Markdown 模板结构**：含一级标题「1. 测试大纲」→ 二级「1.1 测试点列表」→ 「功能条目：功能条目路径」说明行 → 测试点表格（序号 / 测试点 / 描述）。
- **XMind 模板复制**：从 `examples/point_example.xmind` 读取二进制 Buffer 写入新文件，生成合法可打开的 .xmind；非空白、非损坏。
- **模板读取失败**：Markdown 模板读取失败（缺失 / 权限）时错误提示「读取模板文件失败」且不创建文件，不产生无内容空文件。

### 3.4 默认文件名与同名处理

#### 需求背景与目标
新建文件需有合理默认名并进入改名态；同名时自动递增避免覆盖既有文件。

#### 交互与功能规则
- **默认命名**：首次创建默认名为「测试要点.<ext>」，文件创建后自动进入资源管理器 inline 编辑（文件名输入框聚焦），用户直接输入新名回车即按新名保存。
- **同名递增**：目录已存在同名文件时自动递增为「测试要点1.<ext>」「测试要点2.<ext>」……序号连续无跳号、不覆盖既有文件。

### 3.5 打开与编辑

#### 需求背景与目标
新建后应立刻进入可编辑状态，使用对应格式的默认程序打开（非测试案例自定义编辑器），并触发 inline 改名。

#### 交互与功能规则
- **默认编辑器打开**：Markdown 以 VS Code 默认（Markdown）编辑器 / 预览打开，XMind 以系统 / XMind 关联程序打开；**不以**「测试案例编辑器（unifiedEditor）」打开（该自定义编辑器仅匹配测试案例文件）。
- **inline 重命名**：创建后执行 revealInExplorer + 延时 100ms + renameFile 触发 inline 改名；修改扩展名（如 .md→.xmind）时内容格式随之变化。
- **重命名超时兜底（Markdown）**：Markdown 创建经 `createFileAndTriggerRename` 注册 onDidRenameFiles 监听，并以 setTimeout(30000) 兜底 dispose，避免监听器长期挂起；XMind 创建直接触发 renameFile，不注册该超时监听（与 Markdown 行为存在差异但均正常触发改名）。

### 3.6 文件标识（与测试案例创建的明确区分）

#### 需求背景与目标
测试要点是大纲类文档，不属于"命令创建的测试案例"标识体系。其创建不应产生装饰器、状态栏项或推送来源副作用，保持零侵入。

#### 交互与功能规则
- **不写入创建记录**：命令创建的要点文件不调用 markAsCreatedByCommand，因此不写入 created-files.json（与命令创建的测试案例文件形成明确差异）。
- **无装饰器**：编辑器首行不显示 📝 装饰器（依赖 isCreatedByCommand，要点文件未被标记）。
- **无状态栏项**：状态栏不显示「通过命令创建」信息。
- **重命名 / 删除无记录同步**：因未被标记，要点文件重命名或删除时不触发 created-files 记录的新增 / 更新 / 清理，避免脏数据。

## 4. 用户操作流程

### 4.1 右键新建测试要点
1. 在资源管理器定位到「测试任务 / 任务A / 测试大纲」文件夹（或其子文件夹）。
2. 右键该文件夹，选择「新增测试要点 → Markdown (.md)」（或 XMind）。
3. 文件以默认名创建并进入 inline 改名态，同时以对应格式默认编辑器打开，模板已预填结构。
4. 重命名文件并补充测试要点内容。

### 4.2 命令面板新建
1. 打开命令面板（Cmd/Ctrl+Shift+P），输入「新增测试要点」回车。
2. 在格式 QuickPick 中选择 Markdown 或 XMind。
3. 文件按当前活动文件所在测试大纲目录创建并打开。

### 4.3 边界：非测试大纲目录
1. 误在「测试案例」或任务根目录右键 / 命令触发新增测试要点。
2. 系统弹出警告「只能在测试大纲目录或其子文件夹中创建新测试要点」，不创建文件。

---

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 右键测试案例目录 | 不出现「新增测试要点」菜单，仅出现「新增测试案例」 |
| 目标路径不含「测试大纲」 | 警告「只能在测试大纲目录或其子文件夹中创建」并终止 |
| 格式 QuickPick 取消 | 不创建任何文件、无残留 |
| 目录已存在同名文件 | 自动递增命名，不覆盖 |
| 连续多次同名创建 | 依次递增 1、2、3…无跳号无冲突 |
| Markdown 模板读取失败 | 错误提示且不创建空文件 |
| 用户 30 秒未重命名（Markdown） | 重命名监听自动释放，无异常 |
| XMind 创建 | 不注册 30 秒超时监听，直接触发改名 |
| 命令创建要点文件 | 不写入 created-files.json、无首行装饰、无状态栏项 |
| 要点文件重命名 / 删除 | 不触发 created-files 记录同步，无残留 |

---

## 6. 验收标准

1. **多入口可用**：资源管理器右键（目录/文件/子文件夹）与命令面板均可在测试大纲目录下触发新建；非测试大纲目录不出现该菜单。
2. **格式可选 + 模板正确**：Markdown / XMind 均可创建；Markdown 预填大纲层级与测试点表格，XMind 从合法二进制模板复制生成可直接打开；模板读取失败时提示且不创建空文件。
3. **命名与打开**：默认名「测试要点.<ext>」、同名自动递增、创建后 inline 改名；以对应格式默认编辑器打开（非测试案例自定义编辑器）。
4. **零侵入标识**：命令创建的要点文件不写入 created-files.json、首行无 📝 装饰、状态栏无「通过命令创建」；重命名 / 删除不触发记录同步，与命令创建的测试案例文件明确区分。
5. **目录校验**：目标路径不含「测试大纲」时警告并终止，不生成游离文件，不破坏工作区结构。
