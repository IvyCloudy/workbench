# 测试案例批量推送功能需求文档

> 文档视角：业务 / 用户（案例编辑者、测试负责人）
> 适用范围：在「测试任务 / <子任务文件夹> / 测试案例 /」目录体系下，通过资源管理器右键同时选中多个案例文件或选中整个文件夹，一次性把多个测试案例文件推送到系统
> 说明：本文档描述批量推送（多选 / 文件夹）用户需要的能力、业务规则与验收标准，不涉及具体实现方式。

---

## 1. 总体背景与目标

测试案例以 CSV / YAML 文件形式维护于「测试任务」目录体系下。实际工作中，一个任务目录下往往存在多个案例文件（如 `login_case.csv`、`search_case.yaml`、`pay_case.yaml`），用户需要一次性把它们全部推送到系统，而不是逐个文件右键推送。单文件推送入口（编辑器内「推送」按钮 / 资源管理器右键单个文件）走内嵌弹窗，适合少量行 / 单文件；而一次性处理多文件、整文件夹时，需要独立的「进度面板 + 总结视图」以掌握整体进度与逐文件结果。

本功能的定位是「资源管理器右键推送」的扩展模式：**在资源管理器中同时选中多个文件，或直接选中整个文件夹**，一次性推送其中所有合规的测试案例文件。

总体目标：
1. **多入口选择**：支持资源管理器 `Ctrl/Cmd + 点击` 或 `Shift + 点击` 多选文件，也支持直接右键选中文件夹（插件递归收集其中的合规文件）。
2. **合规文件收集**：自动识别并收集位于 `测试任务/<任务文件夹>/测试案例/` 目录体系下的 .csv/.yaml/.yml/.json 文件，跳过非合规目录 / 非支持格式的文件（不报错、计数为 0）。
3. **进度可视 + 可取消**：推送过程中弹出独立进度面板，实时展示每个文件状态，支持中途取消（已完成文件结果仍保留）。
4. **按文件聚合的总结视图**：全部处理完后自动切换到总结视图，按文件聚合展示成功 / 失败，点击文件名可下钻查看单文件推送结果明细。
5. **来源拆批一致**：批量推送沿用单文件推送的 `sourcePlatform` 判定与拆批逻辑，一次推送中不同行可走不同通道。

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 合规目录 | 固定结构 `测试任务/<任务文件夹>/测试案例/`（或其下任意子文件夹）；文件必须位于该结构内才被识别为案例 |
| 合规文件 | 位于合规目录下、且扩展名为 `.csv` / `.yaml` / `.yml` / `.json` 的案例文件；临时文件、层级外文件（如 `src/foo.json`、普通说明文档）一律按普通文件处理，批量推送时静默跳过 |
| 批量推送 | 资源管理器右键多选多个案例文件，或选中整个文件夹（含其下子文件夹），一次性推送其中所有合规文件 |
| 进度面板 | 批量推送过程中弹出的独立面板，展示每个文件的实时推送状态，与总结视图为同一面板无缝切换 |
| 总结视图 | 批量推送结束后同一面板自动切换的聚合视图，按文件展示成功 / 失败统计与状态图标 |
| 来源平台 `sourcePlatform` | 每行案例推送时由插件自动判定（testAgent / testAgentMA），决定后端按哪种来源通道处理，无需用户填写 |
| 拆批推送 | 同一次推送内，插件按 `sourcePlatform` 将同通道的行归为一批请求 |

## 3. 功能需求

### 3.1 入口与合规文件收集

#### 需求背景与目标
批量推送的入口需贴合资源管理器操作习惯：多选文件针对「挑几个推送」，选文件夹针对「整任务回归」。无论哪种入口，都必须先完成合规文件收集，只对真正可推送的案例文件发起推送。

#### 交互与功能规则
- **多选文件**：在资源管理器中 `Ctrl/Cmd + 点击` 或 `Shift + 点击` 选中多个案例文件，右键 →「推送测试案例」即进入批量模式。
- **选文件夹**：直接右键点击包含案例文件的文件夹（如 `测试案例/` 或其子文件夹），插件递归收集其中的合规文件。
- **合规文件识别**：仅收集位于 `测试任务/<任务文件夹>/测试案例/` 目录结构内的 `.csv` / `.yaml` / `.yml` / `.json` 文件；非合规目录、非支持扩展名、临时文件目录内的文件一律静默跳过，不报错且计数为 0。
- **跳过规则**：批量推送时每个文件独立推送；临时文件目录里的文件被静默跳过且不计入失败；层级外文件（`src/foo.json`、普通说明文档）默认以文本打开、不进案例编辑器、不提供推送能力，批量推送不触碰。

### 3.2 进度面板

#### 需求背景与目标
多文件推送耗时较长，需有实时进度反馈，并允许用户在中途放弃而不破坏已完成结果。

#### 交互与功能规则
- 推送过程中弹出进度面板，显示：
  - 顶部标题：`正在推送测试案例...`
  - 副标题：`本次共推送 N 个文件 · 已完成 X / N`
  - 每个文件一行：文件名 + 实时状态（`推送中` / `✓ 成功` / `⚠ 部分失败` / `✕ 出错`）
- 面板右上角提供**取消**按钮：取消本次批量推送后，已完成的文件结果仍会保留并展示。
- 进度面板与总结视图为**同一个面板无缝切换**，不额外打开多个 Tab；连续发起批量推送时复用同一面板。

### 3.3 总结视图（按文件聚合）

#### 需求背景与目标
多文件推送结束后，用户需要一眼看到整体成功率与每个文件的结果，并能快速下钻到失败文件定位问题。

#### 交互与功能规则
- 所有文件处理完毕后，同一面板自动从「进度」切到「总结」：
  - 顶部状态条：`<成功数> 成功` / `<失败数> 失败` · 共 `<文件数>` 个文件
  - 文件列表：每个文件的状态图标（`✓` / `⚠` / `✕`）+ 成功行数 / 失败行数
- **点击任意文件名** → 打开该文件并在弹窗中展示其推送结果明细（成功 / 失败统计 + 失败明细列表）；若文件尚未在编辑器打开则先打开再弹明细，已打开的文件直接聚焦、不重复弹窗。
- 失败行高亮：批量推送后，每个文件中的失败行会在各自表格中红色高亮，可打开文件用「仅看失败行」筛选处理。
- 关闭面板：点击「关闭」或按 `Esc` 关闭总结面板。

### 3.4 推送前自动校验（按文件聚合）

#### 需求背景与目标
批量推送同样需要在真正发往后端前做格式 / 必填校验，避免把明显非法的文件批量发往后端。批量场景下校验结果需按文件聚合展示，避免信息散落。

#### 交互与功能规则
- 复用单文件推送的同一套校验规则与字段清单（「待补充」匹配、枚举合法性、数据类型、案例名称非空、唯一性、必备列 / 字段存在性等），保证两处口径一致。
- **批量推送**：先按文件顺序逐个执行推送前校验（纯校验，无落盘、无埋点），完成后按文件聚合展示命中清单。
- 文件名可点击进入对应文件；点击后若目标文件尚未在编辑器打开，则打开并弹出该文件的校验详情弹窗（复用单文件校验弹窗组件），若已打开则直接聚焦不重复弹窗。
- 校验详情面板按「文件名 + 该文件汇总结果」两列展示，不展开每案例明细；点击文件名进入对应文件并弹出该文件详情面板。
- YAML 前置语法校验同样生效：批量中某个 YAML 文件语法错误时，该文件被中止拦截并计入失败，不影响其他文件继续推送。

### 3.5 来源判定与拆批推送（来源拆批）

#### 需求背景与目标
批量推送中每行案例的来源平台判定与单文件推送必须一致，且同通道的行应归并成一批请求，避免通道混乱。

#### 交互与功能规则
- 每行案例按统一的来源平台判定规则自动判定 `sourcePlatform`：
  - 文件由「新增测试案例」命令创建 → `testAgentMA`
  - 所选案例中存在以 `TC` 开头的 `testcase_id` → `testAgent`
  - 其他情况（默认） → `testAgentMA`
- 一次批量推送中**不同行可走不同通道**：插件按 `sourcePlatform` 自动**拆批**，同通道的行归为一批请求。
- 编辑器内推送与资源管理器批量推送共用同一判定与拆批逻辑，结果一致。

### 3.6 推送结果与回写

#### 需求背景与目标
批量推送的结果处理应与单文件推送保持一致的语义（回写编号、失败行高亮、失败归因口径统一）。

#### 交互与功能规则
- **推送结果回写**：每个文件推送成功的行，其 `testCaseNo` 自动回写到对应文件（与单文件推送一致）。
- **失败归因统一**：推送接口返回码非 `SUC0000`（后端返回失败）或接口超时（90 秒）均视为「整文件级错误」，弹窗样式与文案前缀（`后端返回失败:`）与单文件入口一致。批量推送中按文件分别标记，点文件才弹对应错误，不加批量级弹窗。
- **未绑定任务的文件**：作为该文件的失败项（分类 `taskNotFound`）计入总结，需在任务绑定配置补充后重推。
- **失败行高亮**：批量推送后，每个文件中的失败行在各自表格中红色高亮，可打开文件用「仅看失败行」筛选处理。

## 4. 用户操作流程

### 4.1 多选文件批量推送
1. 在资源管理器定位到 `测试任务/TT001_测试任务1/测试案例/` 文件夹，按住 `Ctrl/Cmd` 或 `Shift` 选中多个案例文件（如 `login_case.csv`、`pay_case.yaml`）。
2. 右键 →「推送测试案例」，插件先收集所有合规文件（自动跳过非合规目录 / 非支持格式）。
3. 弹出进度面板实时展示每个文件状态；如需放弃，点击右上角取消（已完成结果保留）。
4. 全部完成后自动切换到总结视图；点击任意文件名可下钻查看该文件推送明细。
5. 打开失败文件，失败行红色高亮，可用「仅看失败行」筛选处理。

### 4.2 选文件夹整任务回归
1. 直接右键 `测试案例/` 文件夹（或某子文件夹）。
2. 插件递归收集其中所有合规案例文件并批量推送。
3. 进度面板与总结视图展示整体成功率；点击文件名下钻定位失败文件。

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 选中含非合规目录的文件 | 自动跳过，不报错、计数为 0 |
| 选中 `.json` / `.txt` / 普通说明文档等不支持格式 | 静默跳过，不计入推送文件数 |
| 临时文件目录里的文件 | 批量推送静默跳过，不计入失败；双击以纯文本打开，右键看不到推送 / 绑定菜单 |
| 文件夹内含非案例文件 | 仅推送合规案例文件，其余跳过 |
| 某个 YAML 文件语法错误 | 该文件被前置拦截并计入失败，不影响其他文件继续推送 |
| 中途点击取消 | 已完成的文件结果保留并展示，剩余文件不再推送 |
| 文件未绑定任务 | 作为该文件失败项（分类 `taskNotFound`）计入总结，补充绑定后重推 |
| 后端返回非 `SUC0000` 或超时 | 整文件级错误，按文件标记 ✕，点击该文件才弹对应错误，不加批量级弹窗 |
| 连续发起批量推送 | 复用同一进度 / 总结面板，不额外开 Tab |
| 已打开的失败文件 | 点击文件名直接聚焦，不重复弹窗；未打开的先打开再弹明细 |

## 6. 埋点要求（可观测性）

批量推送需上报独立的 `explorerPush.batch.*` 事件族，与单文件 `explorerPush.complete` 口径天然分离、不再重叠，可直接分别求和：

| eventName | 描述 | 关键 props |
|-----------|------|-----------|
| `explorerPush.batch.start` | 批次启动 | `fileCount`、`extBreakdown`（如 `csv:3,yaml:2`） |
| `explorerPush.batch.fileResult` | 单文件推送完成摘要 | `ext`、`pushResult`(allSuccess/partial/allFail)、`totalRows`、`successRows`、`failedRows`、`preValidationFailedRows?`、`traceId?`、`costMs?`、`reason?`、失败分类 / 字段维度 |
| `explorerPush.batch.cancelled` | 用户中途取消批次 | `fileCount`、`completed`、`remaining`、`durationMs` |
| `explorerPush.batch.postRefresh` | 批次结束统一刷新已打开的 webview 面板 | `refreshed`、`total` |
| `explorerPush.batch.openFile` | 从总结面板点开文件 | `ext`、`hasError` |
| `explorerPush.batch.done` | 批次汇总 | `fileCount`、`totalRows`、`successRows`、`failedRows`、`errorFiles`、`cancelled`、`durationMs`、`extBreakdown`、失败分类 / 字段维度 |

- `batch.*` 事件只做文件 / 批次维度聚合，不重复统计行级 / 字段级失败；想看「哪个字段错最多」需下钻到单文件事件。
- 逐文件结果由 `explorerPush.batch.fileResult` + `explorerPush.batch.done` 承接，且携带与单文件 `.complete` 对齐的分类 / 字段维度（`failCategoryBreakdown` / `topFailCategory` / `failFieldBreakdown` / `topFailField` / `interfaceFailBreakdown` / `topInterfaceFailField` / `caseFailBreakdown` / `topCaseFailField` / 各类原样 reason 样本等），批量下钻分析已可支撑。
- 异常兜底：`batch.done` 计算若抛错，重新基于真实 `results` 安全累加 `successRows`/`failedRows`/`errorFiles` 并带 `summaryError=1` 上报，绝不清零。

## 7. 验收标准

1. **多选入口**：资源管理器 `Ctrl/Cmd+点击` 或 `Shift+点击` 多选案例文件后右键「推送测试案例」可进入批量模式。
2. **文件夹入口**：右键选中文件夹可递归收集其中所有合规案例文件并批量推送。
3. **合规收集**：仅收集合规目录下的 `.csv/.yaml/.yml/.json` 文件；非合规目录 / 非支持格式 / 临时文件目录内的文件静默跳过、计数为 0。
4. **进度面板**：推送中展示每个文件的实时状态（推送中 / 成功 / 部分失败 / 出错），顶部显示「共 N 个文件 · 已完成 X / N」。
5. **可取消**：面板右上角可取消本次批量推送，已完成的文件结果仍保留并展示。
6. **总结视图**：完成后自动切到总结视图，按文件展示成功 / 失败状态图标与行数；进度面板与总结视图同一面板无缝切换。
7. **点击下钻**：点击文件名可打开文件并展示该文件推送结果明细；未打开的先打开再弹、已打开的直接聚焦不重复弹窗。
8. **失败行高亮**：批量推送后各文件失败行红色高亮，可用「仅看失败行」筛选。
9. **校验聚合**：批量推送前按文件逐个执行推送前校验，命中项按文件聚合展示；YAML 语法错误文件被拦截并计入失败，不影响其他文件。
10. **来源拆批一致**：每行 `sourcePlatform` 判定与单文件推送一致；同推送内按 `sourcePlatform` 拆批，同通道归并成一批请求。
11. **结果回写**：成功行 `testCaseNo` 自动回写到对应文件，与单文件推送一致。
12. **失败归因统一**：后端返回失败 / 超时均为「整文件级错误」，按文件标记 ✕、点文件才弹对应错误且文案前缀统一，不加批量级弹窗。
13. **埋点完整**：批量推送上报 `explorerPush.batch.start/fileResult/cancelled/postRefresh/openFile/done` 全事件族，行级字段命名与单文件 `.complete` 一致，`batch.*` 与 `.complete` 口径天然分离。
14. **异常兜底**：`batch.done` 计算异常时安全累加真实行数并带 `summaryError=1` 上报，不清零。
