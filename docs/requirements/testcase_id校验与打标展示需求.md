# testcase_id 校验与打标展示功能需求文档

> 文档视角：用户（测试人员 / 案例编辑者）
> 适用范围：表格编辑器中的「测试案例」文件，列 `testcase_id`（案例唯一标识）的编辑、展示与推送前校验

---

## 1. 背景与目标

测试案例通过 `testcase_id` 唯一标识，并在推送到不同后端平台（testAgent / testAgentMA）时据此路由。日常维护中，用户会填入多种形态的 `testcase_id`，既有标准格式，也有系统自动生成的掩码格式，还有误填、占位、空值等情况。

本功能目标：
1. **校验**：推送前自动识别非法 / 占位 / 空值，拦截并给出明确提示，避免脏数据进入后端接口。
2. **打标展示**：在表格内对特殊形态的 `testcase_id`（testagent / testflow 掩码 uuid）做可视化标记，让用户一眼识别该案例归属的平台类型，无需记忆复杂格式规则。

---

## 2. 用户视角下的 testcase_id 形态

### 2.1 合法形态（推送放行）

| 编号 | 形态 | 示例 | 用户感知 |
|------|------|------|----------|
| L1 | 标准 UUID（8-4-4-4-12 十六进制带连字符） | `123e4567-e89b-12d3-a456-426614174000` | 普通案例，推送至 **testAgentMA** 平台 |
| L2 | `TC` + 32 位十六进制 | `TC1234567890abcdef1234567890abcdef12` | 推送至 **testAgent** 平台 |
| L3 | `MA` + 32 位十六进制（系统自动生成） | `MAa1b2c3d4e5f60718293a4b5c6d7e8f90ab` | 推送至 **testAgentMA** 平台 |
| L4 | `TC` + testagent 掩码 uuid | `TC16tc5dec6s0f6t03a438g2ce9b5n14t6` | 推送至 **testAgent** 平台，**带 TA 标记** |
| L5 | `TC` + testflow 掩码 uuid | `TCd7t48fe2ds771t04f9e8le9o3d2wca4d` | 推送至 **testAgent** 平台，**带 TA 标记** |

> 掩码 uuid 本质：在一段 32 位随机 uuid.hex 基础上，把特定位置字符替换为固定字母串（testagent / testflow），其余位保留原 hex 值。总长度固定为 `TC` 前缀 + 32 位 = 34 位。

### 2.2 非法形态（推送拦截）

| 编号 | 形态 | 示例 | 用户感知 |
|------|------|------|----------|
| X1 | 裸 32 位 hex 无前缀 | `a1b2c3d4e5f60718293a4b5c6d7e8f90ab` | 非 UUID 也非 TC/MA 前缀 → 拦截 |
| X2 | 含非 hex 字符（空格 / 下划线 / 中文） | `TC_zzzzzzzzzzzzzzzzzzzzzzzzzzzzzzzz` | 拦截 |
| X3 | 错误前缀（仅允许 TC / MA） | `TA1234...`（前缀 TA） | 拦截 |
| X4 | 长度不对（非 32 位） | `TC...cdef1`（31 位）/ `MA...f90abc`（33 位） | 拦截 |
| X5 | 掩码位被篡改 | `...e000n0000`（第 31 位 t→0）/ `...a000l00o...`（第 17 位 f→a） | 不再命中掩码规则 → 按非法格式拦截 |

### 2.3 占位 / 空值（特殊处理，不推送）

| 编号 | 形态 | 示例 | 用户感知 |
|------|------|------|----------|
| P1 | 英文占位 | `TESTCASE_ID`（大小写不敏感） | 阻断推送，弹窗列出可跳转行 |
| P2 | 中文长占位 | `案例唯一标识，不可修改` | 静默过滤，不推送、不报错 |
| P3 | 中文短占位 | `案例唯一标识` | 静默过滤，不推送、不报错 |
| E1 | 空值 | ``（空单元格） | 阻断推送，提示具体行号 |

## 3. 功能需求

### 3.1 打标展示（编辑器内）

**FR-1 掩码标识展示**
- 当 `testcase_id` 单元格值命中 testagent 或 testflow 掩码规则时，在单元格内容**左侧**显示一个绿色椭圆小标签 `TA`。
- testagent 与 testflow 共用同一标识（不区分显示文案）。
- 标签带 `title` 悬浮提示，内容为：`TC 掩码标识（testagent/testflow）：<原始值>`。

**FR-2 展示不影响数据**
- 标签仅为可视化标记，不修改单元格实际存储值，不参与编辑、不进入推送 payload。
- 文本与标签之间保留 6px 间距，保证可读。

**FR-3 自动识别**
- 标记随单元格值实时更新：用户编辑保存后，若新值命中掩码规则则显示标签，否则移除。

### 3.2 推送前校验（预校验阶段）

**FR-4 校验时机**
- 校验在调用后端推送接口**之前**完成（占位 / 空值 / 格式三类）。
- 若整份文件全部非法，则**绝不**发起任何后端接口调用，直接以失败明细汇总。

**FR-5 合法放行**
- 命中 L1~L5 任意一种合法形态的行，正常进入推送；并依据前缀/格式路由到正确平台批次（testAgent / testAgentMA）。

**FR-6 非法格式拦截**
- 命中 X1~X5 的行，标记为「非法格式（invalidFormat）」拦截，不进入接口。
- 推送结果弹窗按行号列出失败明细，提示「格式不正确」。

**FR-7 占位拦截与静默过滤**
- 英文占位（P1）：阻断推送，弹窗列出该行并标注为占位，支持点击行号跳转到主表对应行。
- 中文占位（P2 / P3）：静默过滤（不计入 failures、不调用接口、不报错），提示「跳过 N 行样例数据」。
- 全部为样例数据时：终止推送，提示「为样例数据」并列出所有样例行号。

**FR-8 空值拦截**
- 空 `testcase_id`（E1）：阻断推送，提示包含具体行号（如「案例 [xxx] 缺少 testcase_id」）。

**FR-9 混合处理**
- 一份文件中合法行与非法行混合时：非法行被剔除并记入失败明细，剩余合法行照常推送；成功 / 失败明细按行号分别呈现，无错位。

## 4. 用户操作流程

### 4.1 日常编辑
1. 在表格编辑器中打开测试案例文件。
2. 查看 `testcase_id` 列：掩码格式（testagent/testflow）行左侧显示绿色 `TA` 标签，便于区分平台归属。
3. 修改某行 testcase_id 并保存，标签随值自动刷新。

### 4.2 推送
1. 点击「推送」按钮。
2. 系统先执行预校验：
   - 全部合法 → 直接进入推送，按平台批次调用接口。
   - 含非法 / 占位 / 空值 → 弹窗汇总失败明细（标注行号、类型），合法行照常推送。
3. 用户根据弹窗提示修正对应行后重新推送。

---

## 5. 校验规则明细（用户可理解的口径）

- **必须带前缀**：`TC` 或 `MA`，或标准 UUID 连字符格式；否则非法。
- **TC/MA 后必须恰好 32 位十六进制**：多一位、少一位都非法。
- **掩码 uuid**：`TC` + 32 位，其中特定位置为固定字母（testagent / testflow），其余为十六进制；掩码位被改、位数错位即非法。
- **占位不推送**：`TESTCASE_ID`、模板示例文案（`案例唯一标识，`不可修改 / `案例唯一标识`）不进入后端。
- **空值必拦截**：单元格为空不允许推送。

---

## 6. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 大小写前缀 `tc` / `ma` | 与 `TC` / `MA` 同规则处理（大小写不敏感） |
| `TESTCASE_ID` 全大写 / `Testcase_Id` | 识别为英文占位，阻断 |
| 文件全为样例占位 | 终止推送，提示「为样例数据」 |
| 全部行非法 | 不调用后端接口，仅弹窗失败明细 |

---

## 7. 验收标准

1. L1~L5 各取一条样本，推送均放行且路由正确。
2. X1~X5 各取一条样本，推送均被拦截并提示格式不正确。
3. P1 阻断并弹窗可跳转；P2/P3 静默过滤不推送；E1 阻断并提示行号。
4. 掩码格式（L4/L5）在编辑器内显示绿色 `TA` 标签，标签不修改原值。
5. 混合文件中合法行照常推送，非法行被剔除且明细无错位。
6. 全部非法时后端接口零调用。
