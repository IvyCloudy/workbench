# 测试子任务文件夹名取消限制需求文档

> 文档视角：业务 / 用户（案例编辑者、测试负责人、项目管理员）
> 适用范围：测试案例文件的目录归属判定——即案例文件所在「测试子任务文件夹」的命名规则
> 说明：本文档描述用户需要的能力、业务规则与验收标准，不涉及具体实现方式。

---

## 1. 总体背景与目标

测试案例文件需放置在特定目录结构下才能被识别与推送：`测试任务 / <子任务文件夹> / 测试案例 /`。早期实现要求子任务文件夹必须遵循固定命名格式（如 `<编号>_<名称>`），否则文件不被识别为合法案例、无法推送。这给团队带来不必要的约束：

- 团队命名习惯各异（有的用纯中文任务名、有的用 Jira 单号、有的用业务模块名），强制格式增加协作摩擦。
- 历史项目 / 已归档目录的文件夹名往往不符合新格式，导致存量文件"失联"。
- 重命名子任务目录需同步改格式，增加维护成本。

总体目标：
1. **取消子任务文件夹的命名格式限制**：只要位于 `测试任务 / <任意文件夹> / 测试案例 /` 之下，即被识别为合法案例文件。
2. **兼容既有层级规则**：仍要求"测试任务"与"测试案例"两级固定目录名，仅放开中间的子任务文件夹名。
3. **支持子目录嵌套**：案例文件可直接放在 `测试案例/` 下，也可放在其子文件夹中，均被识别。

---

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 测试任务目录 | 固定的顶级目录名 `测试任务`，作为案例归属的根节点 |
| 子任务文件夹 | `测试任务` 下一级的任意文件夹，**名称不再受限**（旧规要求 `<编号>_<名称>` 格式，现已取消） |
| 测试案例目录 | 固定目录名 `测试案例`，必须位于子任务文件夹之下 |
| 合格目录 | 案例文件所在路径满足 `.../测试任务/<子任务文件夹>/测试案例/[子目录...]/<文件>` 的判定条件 |

---

## 3. 功能需求

### 3.1 子任务文件夹命名格式放开

#### 需求背景与目标
不同团队、不同项目管理工具下的子任务命名习惯不同（纯中文、英文代号、Jira 单号、业务模块等），强制 `<编号>_<名称>` 格式既无业务必要性，又阻碍存量文件与跨工具协作。本功能目标是让"任意文件夹名"都可作为子任务容器，只要层级正确即被识别。

#### 交互与功能规则
- **任意文件夹名均可作为子任务**：位于 `测试任务` 下一级的文件夹，无论其名称是中文、英文、数字、混合，还是带特殊分隔符，均被视为合法的子任务文件夹，其下的 `测试案例` 目录中的文件可被正常识别、打开与推送。
- **不再校验命名格式**：系统不再要求子任务文件夹名包含编号、下划线或特定前缀；旧的格式约束（如必须为 `<编号>_<名称>`）已移除，用户按团队习惯自由命名。
- **与绑定 / 推送流程一致**：取消格式限制后，案例的绑定（point ↔ case）、推送、批量推送等能力对子任务文件夹名无任何格式依赖，沿用原有目录层级判定即可。

### 3.2 固定层级的保留

#### 需求背景与目标
放开子任务文件夹名不等于放开整个目录结构。仍需保证案例文件确实归属于"测试任务"体系，避免散落文件被误判为案例。本功能目标是"放开中间、守住两端"。

#### 交互与功能规则
- **两级固定目录名仍需满足**：文件路径中必须存在名为 `测试任务` 的祖先目录，且其下紧邻一级为子任务文件夹，再下一级必须为名为 `测试案例` 的目录。三者层级与名称缺一不可。
- **动态定位测试任务根**：系统从文件路径中动态查找 `测试任务` 所在位置（不限定固定倒数层级），只要向上能找到该目录并满足上述层级链，即判定为合格。
- **测试案例下允许子目录**：案例文件可直接放在 `测试案例/` 根下，也可放在 `测试案例/` 的任意深度子文件夹中，均被识别为合法案例文件。

### 3.3 识别失败时的明确反馈

#### 需求背景与目标
当文件不在合格目录下时，用户需要清晰知道"为什么不能被识别 / 推送"，而非静默失效。本功能目标是给出可读的路径归属提示。

#### 交互与功能规则
- **推送前目录校验**：从资源管理器或编辑器发起推送时，系统先校验文件是否在合格目录下；不在时给出明确提示，说明应放置于 `测试任务 / <子任务文件夹> / 测试案例 /` 结构，并展示当前文件路径，便于用户自查。
- **绑定流程目录校验**：执行案例与要点绑定等关联操作时，若当前文件不在 `测试任务 / <子任务文件夹> /` 结构下，提示用户"当前文件不在测试任务子任务目录结构下"，引导其移动到正确位置。
- **新建案例位置约束**：在资源管理器中新建测试案例时，仅允许在 `测试案例` 目录或其子文件夹内创建，避免生成游离文件；该约束与子任务文件夹名无关，不影响命名放开。

## 4. 用户操作流程

### 4.1 用任意名称的子任务文件夹管理案例
1. 在 `测试任务` 下新建文件夹，命名为团队习惯的名称（如「登录模块」「PROJ-123」「回归测试一期」）。
2. 在该文件夹内新建 `测试案例` 目录，放入 YAML / CSV 案例文件。
3. 打开文件：正常以案例编辑器打开，无需遵循旧格式命名。
4. 推送 / 绑定：功能正常可用，与旧格式文件夹体验一致。

### 4.2 存量 / 历史目录直接复用
1. 打开一个历史项目，其子任务文件夹名为旧习惯（无编号前缀）。
2. 文件仍被正常识别为案例，可直接编辑、推送，无需重命名目录。

### 4.3 不在合格目录时的提示
1. 误将一个文件放在 `测试任务` 之外或层级错误处。
2. 推送时提示"文件不在合规目录下（测试任务/<子任务文件夹>/测试案例/）"，并展示当前路径，引导修正。

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 子任务文件夹名为纯中文 | 正常识别为合法子任务，无格式报错 |
| 子任务文件夹名为 Jira 单号 / 英文代号 | 正常识别 |
| 子任务文件夹名含空格 / 特殊分隔符 | 正常识别 |
| 文件直接在 `测试案例/` 根下 | 被识别为合法案例 |
| 文件在 `测试案例/子目录/子目录/` 深层 | 仍被识别 |
| 缺少 `测试任务` 祖先目录 | 判定不合格，推送提示明确路径要求 |
| 有 `测试任务` 但下一级不是文件夹（直接是文件） | 判定不合格，提示层级错误 |
| 子任务文件夹下没有 `测试案例` 目录 | 判定不合格，提示需有 `测试案例` 层级 |
| 绑定操作文件不在子任务结构下 | 提示"不在测试任务子任务目录结构下"，不继续 |
| 新建案例时选在非 `测试案例` 区域 | 提示只能在测试案例目录或其子文件夹创建 |

---

## 6. 验收标准

1. **命名放开**：子任务文件夹使用任意名称（中文、英文、数字、混合、含空格 / 分隔符）时，其下 `测试案例` 中的文件均被正常识别、打开、推送、绑定，无格式约束报错。
2. **层级守住**：文件必须满足 `测试任务 / <子任务文件夹> / 测试案例 /` 的层级链才被识别；缺失任一层级或名称不符时判定不合格，并给出明确路径提示。
3. **子目录兼容**：案例文件在 `测试案例/` 根或其任意深度子文件夹中均可被识别。
4. **能力一致**：放开命名后，推送、批量推送、point↔case 绑定、失败定位等既有能力对子任务文件夹名无任何格式依赖，行为与旧格式目录完全一致。
5. **存量兼容**：历史项目中不符合旧 `<编号>_<名称>` 格式的目录，无需重命名即可直接作为子任务容器使用。
