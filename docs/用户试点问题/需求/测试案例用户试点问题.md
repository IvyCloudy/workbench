# 测试案例用户试点问题功能需求文档

> 文档视角：业务 / 用户（测试人员、案例编辑者、测试负责人）
> 适用范围：用户试点期间提出的测试案例编辑器与推送链路增强诉求，覆盖展开步骤、字段默认值、样例冻结、预期序号、TA 标识、空步骤初始化、推送埋点任务信息、适配TMS执行方式（UI自动化/接口自动化）等 8 个方向
> 说明：本文档描述试点用户提出的能力诉求、业务规则与验收标准，不涉及具体实现方式。
> 章节约定：每个功能模块均按「需求背景与目标」「交互与功能规则」「验收标准」三部分展开。

---

## 1. 总体背景与目标

测试案例插件在用户试点过程中，用户提出了若干体验与数据质量诉求（其中部分能力在既有需求文档中已有基线，本文档一并归口、统一口径）。8 项用户诉求包括：展开步骤后子表内查找替换、推送精益字段缺失默认值、样例数据行冻结、预期结果序号、testcase_id 的 SDT 生成标识（TA）、空步骤展开自动初始化、推送埋点任务上下文、适配 TMS 执行方式（UI自动化/接口自动化）等。本文档将这 8 项用户诉求统一固化为功能需求，明确每项能力的业务规则与验收口径。

总体目标：
1. **展开步骤内查找替换**：在展开的内联子表格中复用表格编辑器通用查找替换能力。
2. **推送字段默认值**：推送对接精益平台字段 `keyFlag` / `planExecNum` / `projectDes`（CSV）与 `key_flag` / `plan_exec_num` / `project_des`（YAML），未填时提供系统默认值。
3. **样例数据行冻结**：模板示例（样例）数据行设为冻结行，整行只读、不可编辑。
4. **预期结果增加序号**：预期结果区域（步骤子表与预期结果列）增加序号展示，便于引用与核对。
5. **testcase_id TA 识别标识**：对 SDT 生成的掩码 `testcase_id` 展示 `TA` 绿色标识。
6. **空步骤展开自动初始化**：`steps` 为空的行点击展开时，自动初始化一个空步骤结构，便于直接录入。
7. **推送埋点任务信息**：推送埋点携带测试任务、子任务、文件名、用户等任务上下文，支撑按任务 / 文件 / 用户维度分析。
8. **适配TMS执行方式**：新增测试案例执行方式覆盖 UI自动化、接口自动化，推送前按执行方式严格白名单校验，支撑 TMS 案例适配与归一。

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 结构化案例文件 | 底层为 YAML / JSON 的案例文件，步骤以对象数组形式存在，可被结构化展开 |
| 展开态 / 折叠态 | `steps` 列内联渲染子表格（展开态）或显示为「[N 项]」聚合文本（折叠态） |
| 步骤子表格 | 展开态下 `steps` 列内部渲染的表格，含序号、步骤描述、预期结果、数据、操作列 |
| 样例数据行 | 模板示例行，`testcase_id` 为占位值（如「案例唯一标识，不可修改」），推送时静默过滤 |
| 冻结行 | 系统强制只读、不可编辑的数据行（如样例数据行） |
| 精益字段 | 对接精益平台所需的案例字段：`keyFlag` / `planExecNum` / `projectDes`（CSV 字段名），对应 YAML 为 `key_flag` / `plan_exec_num` / `project_des` |
| 掩码 testcase_id | SDT 生成的 `TC` + 32 位掩码 uuid，即源需求中的 `testagent` / `testflow` 掩码格式，用于标识案例归属平台 |
| 任务上下文 | 推送相关埋点中携带的测试任务编号、子任务 Id、文件名、用户等维度信息 |

## 3. 功能需求

### 3.1 展开步骤支持查找替换

#### 需求背景与目标
用户将 `steps` 展开为内联子表格后，仍需在子表内对步骤描述、预期结果、数据等单元格做查找 / 替换（如批量修正某个接口地址、统一预期文案）。当前查找替换仅作用于主表，子表内无法使用，用户只能切回折叠态或逐格手改，效率低。本需求目标：在展开态子表格中复用表格编辑器的查找替换通用能力。

#### 交互与功能规则
- **入口复用**：展开态子表格内打开查找替换面板，复用表格编辑器通用能力的查找 / 替换交互（关键字输入、大小写匹配、正则、导航上一项 / 下一项、替换当前 / 替换全部），不另起一套 UI。
- **作用范围**：查找替换仅作用于当前展开子表内的可编辑单元格（步骤描述 / 预期结果 / 数据）；不命中操作列、序号列。
- **只读跳过**：样例数据行（冻结行）子表为只读，查找可命中但替换跳过，并提示「样例数据行已冻结，不可操作」。
- **筛选态协同**：子列筛选开启时，查找仅命中当前可见步骤；替换全部仅替换可见命中的可编辑单元格。
- **写回与同步**：替换结果即时写回底层步骤字段，并同步折叠态合并文本；撤销（Ctrl+Z）可回退本次替换。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 子表查找可用 | 展开步骤后，查找替换面板可打开并在子表内定位关键字 |
| AC-2 | 替换写回 | 替换当前 / 替换全部后，底层数据模型与折叠态文本同步更新 |
| AC-3 | 只读跳过 | 样例数据行子表单元格不被替换，提示已冻结 |
| AC-4 | 筛选协同 | 子列筛选开启时，查找 / 替换仅作用于可见步骤 |
| AC-5 | 撤销可回退 | 替换后 Ctrl+Z 可撤销本次替换结果 |

### 3.2 推送字段默认值（精益字段）

#### 需求背景与目标
推送案例到精益平台时，`keyFlag` / `planExecNum` / `projectDes` 三个字段若为空，会导致后端缺字段或报错。本需求目标：在推送落库前，对未填写的精益字段按系统默认值兜底，提升推送成功率与数据完整性。

#### 交互与功能规则
- **字段映射**：
  - CSV 字段：`keyFlag`（关键案例）、`planExecNum`（计划执行次数）、`projectDes`（项目说明）。
  - YAML 字段：`key_flag`、`plan_exec_num`、`project_des`。
- **默认值兜底**：
  - `keyFlag` / `key_flag` 未填 → 默认 `'否'`。
  - `planExecNum` / `plan_exec_num` 未填 → 默认 `1`（可由系统配置覆盖）。
  - `projectDes` / `project_des` 未填 → 按系统配置默认值（空串或占位说明文案）。
  - 三字段同时缺失且未配置时，统一走系统默认值。
- **生效时机**：默认值在推送落库阶段生效；不强制回写源文件（回写行为以系统配置为准）。
- **占位过滤优先**：样例数据行（占位 `testcase_id`）在默认值兜底之前已被静默过滤，不参与兜底。
- **模板样例文件补充字段**：新建测试案例的模板（CSV / YAML）应补充上述精益字段——CSV 模板增加 `keyFlag` / `planExecNum` / `projectDes` 列（含默认占位或系统默认值），YAML 模板增加 `key_flag` / `plan_exec_num` / `project_des` 字段；新增文件即具备完整字段结构，无需用户手动补齐。
- **历史案例文件兼容**：早期未包含这些精益字段的历史案例文件，推送时不因字段缺失而报错或拒绝；解析层对缺失字段容忍，按「字段未提供」处理并走系统默认值兜底，不强制要求回填源文件、不污染既有内容。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 单字段缺失兜底 | 仅 `keyFlag` 为空时，推送自动补默认 `'否'`，后端不复报缺字段 |
| AC-2 | 多字段缺失兜底 | 三字段全空时均走系统默认值 |
| AC-3 | YAML 对齐 | YAML 的 `key_flag` / `plan_exec_num` / `project_des` 缺失同样兜底 |
| AC-4 | 样例行不污染 | 样例数据行在兜底前被过滤，不写入默认值 |
| AC-5 | 后端不再缺字段 | 兜底后推送不再因该三字段缺失而失败 |
| AC-6 | 模板含字段 | 新建模板文件已含精益字段列 / 字段，新增文件结构完整 |
| AC-7 | 历史文件兼容 | 历史文件缺失该字段时推送不报错，按默认值兜底且不污染源文件 |

### 3.3 样例数据行冻结

#### 需求背景与目标
模板新建的案例文件首行为示例数据（`testcase_id` 为占位），仅作格式示范，不应被误编辑或误推送。本需求目标：将样例数据行设为冻结行，整行只读，与推送、展开、校验修复等场景协同。

> 关联：本能力在 `案例编辑器展开步骤功能需求.md` §3.6 与 `案例编辑器校验与修复功能需求.md` §3 中已有覆盖，此处归口汇总。

#### 交互与功能规则
- **整行只读**：`testcase_id` 为占位值的样例数据行，主表与展开态子表均只读，不显示编辑 / 删除 / 复制 / 添加分组等操作入口。
- **操作拦截提示**：对样例数据行触发编辑或子表操作按钮时，提示「样例数据行已冻结，不可操作」。
- **推送过滤**：样例数据行在推送前被静默过滤，不发送到后端（全样例时终止推送并提示）。
- **校验修复豁免**：样例数据行不参与行级校验与一键修复，冻结行 / 列不被修复写回。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 主表只读 | 样例数据行主表单元格不可编辑 |
| AC-2 | 子表只读 | 展开态下样例行子表只读、无操作按钮，点击提示已冻结 |
| AC-3 | 推送过滤 | 样例行不进入推送后端，全部为样例时终止并提示 |
| AC-4 | 校验豁免 | 样例行不参与校验修复，冻结行不被写回 |

### 3.4 预期结果增加序号

#### 需求背景与目标
步骤与预期结果在维护、评审、缺陷回溯时常需被口头或书面引用（「第 3 步预期」「预期 2」）。本需求目标：在步骤子表与预期结果展示中提供明确的序号，提升可引用性与核对效率。

#### 交互与功能规则
- **步骤序号（已存在，纳入口径）**：展开态子表首列「序号」按步骤顺序连续编号；新增步骤插入到当前步骤之后、其余序号顺延；删除步骤后剩余序号重新连续编号。
- **预期结果序号（新增）**：针对同一预期分组内的多条预期文本（如 UI 检查分组下多行预期），在该分组内按行显示连续序号（如「预期 1 / 预期 2」），随预期增删自动重排；该序号独立于「步骤序号」，仅作展示、不写入底层字段。
- **持久化**：序号仅展示用，不写回底层数据模型；折叠态合并文本与展开态序号展示保持一致。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 步骤序号连续 | 展开子表序号按步骤顺序连续，增删后自动重排 |
| AC-2 | 预期序号展示 | 同一预期分组内多条预期显示连续序号（区别于步骤序号） |
| AC-3 | 不污染数据 | 序号仅为展示，不写入底层文件 |

### 3.5 testcase_id TA 识别标识

#### 需求背景与目标
`testcase_id` 存在多种形态，其中 SDT 生成的掩码格式（`testagent` / `testflow` 掩码）代表案例由系统自动生成并归属特定平台。本需求目标：在编辑器中以 `TA` 标识直观区分该类案例，无需用户记忆复杂格式。

> 关联：本能力在 `testcase_id校验与打标展示需求.md` FR-1 中已有完整定义，此处归口汇总。

#### 交互与功能规则
- **标识触发**：`testcase_id` 单元格值命中 `testagent` 或 `testflow` 掩码规则（即 SDT 生成的 `TC` + 32 位掩码 uuid）时，在单元格内容**左侧**显示绿色椭圆小标签 `TA`。
- **不修改原值**：标识仅为展示层装饰，不改变 `testcase_id` 实际取值。
- **悬浮提示**：标签带 `title` 提示，内容为 `TC 掩码标识（testagent/testflow）：<原始值>`。
- **路由协同**：命中标识的行按既有规则路由到正确平台批次（testAgent），标识展示与路由口径一致。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 掩码显示 TA | testagent / testflow 掩码行左侧显示绿色 `TA` 标签 |
| AC-2 | 不修改原值 | 标签不写入或改变 `testcase_id` 原值 |
| AC-3 | 悬浮提示 | 鼠标悬浮显示掩码类型与原始值 |

### 3.6 空步骤展开自动初始化

#### 需求背景与目标
试点用户反馈：当某行 `steps` 为空时，希望点击「展开步骤」能**直接得到一个可录入的空步骤结构**，而非空标记，以降低录入门槛。本需求目标：空 `steps` 行展开时自动初始化一个空步骤（序号 1、空描述 / 预期 / 数据），用户可直接在子表内录入。本项为 `案例编辑器展开步骤功能需求.md` §3.1 的功能增强，仅扩展「空步骤展开」行为，不与原需求冲突。

#### 交互与功能规则
- **自动初始化（内存态）**：`steps` 为空数组（或缺失）的行点击「展开步骤」时，在内存中初始化一个空步骤结构（序号 1、步骤描述 / 预期结果 / 数据均为空占位）并渲染为内联子表格；该初始化仅存在于编辑会话中，**未实际录入时不写回源文件**。
- **可直接编辑**：初始化后的空步骤子表可立即录入，录入内容即时写回底层 `steps` 字段并同步折叠态合并文本。
- **保存落盘**：仅当用户在初始化出的空步骤中实际录入内容后保存，才将 `steps` 以规范化结构落盘（字段名以实际步骤 schema 为准，如 `steps: [ { step: '', expected: '', data: '' } ]`）；若仅展开未录入，保存时不产生空步骤对象，避免污染源文件。
- **持久化与撤销**：初始化状态可持久化恢复；撤销可回退到空步骤前的状态。
- **样例行豁免**：样例数据行仍遵循冻结规则，空步骤展开不触发自动初始化（保持只读）。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 空步骤自动初始化 | 空 `steps` 行点击展开生成含一个空步骤的子表 |
| AC-2 | 可即时录入 | 初始化后子表可输入，内容写回底层与折叠态文本 |
| AC-3 | 录入后落盘 | 仅当实际录入内容后保存才写回 `steps` 结构；仅展开未录入则不落盘、不污染源文件 |
| AC-4 | 样例行豁免 | 样例数据行空步骤展开不初始化，保持只读 |
| AC-5 | 既有行为不变 | 非空 `steps` 行的展开 / 收起行为保持与原 `案例编辑器展开步骤功能需求.md` 一致，本增强仅作用于空步骤场景 |

### 3.7 推送埋点任务信息（测试任务 / 子任务 / 文件名 / 用户）

#### 需求背景与目标
推送埋点是分析案例维护行为、定位问题、评估使用热度的关键数据来源。试点用户需要按**测试任务、子任务、文件名、用户**等维度对推送行为做下钻分析，但当前推送事件维度不全。本需求目标：补齐推送埋点的任务上下文信息。

> 关联：推送埋点已在 `测试案例用户行为埋点需求.md` 与 `docs/specs/埋点事件清单.md` 中定义。`editorPush.start` / `explorerPush.start` 已含 `testTaskNo` / `subTestTaskId` / `artifactId`；本需求补齐 `fileName`、用户维度，并将任务信息延伸至批量 `explorerPush.batch.*` 事件。

#### 交互与功能规则
- **统一任务上下文字段**：以下字段在推送埋点事件中作为标准维度提供：
  - `testTaskNo`：测试任务编号（顶层）。
  - `subTestTaskId`：子任务 Id（顶层）。
  - `fileName`：文件名（仅文件名，遵循脱敏约定，不含明文完整路径）。
  - `userId` / `userName`：发起推送的用户标识（取自当前会话 / 配置）；遵循既有 telemetry 脱敏约定，**用户名以匿名化（如哈希）形式上报，不采集明文**。
- **单文件推送事件覆盖**：`editorPush.start` / `editorPush.complete` / `explorerPush.start` / `explorerPush.complete` 及失败类事件均携带上述任务上下文（当前 `.complete` 缺失 `testTaskNo` / `subTestTaskId` / `fileName` / 用户，需补齐）。
- **批量推送事件覆盖**：`explorerPush.batch.*` 事件同样携带任务上下文；其中 `testTaskNo` / `subTestTaskId` 等任务级字段在 per-file 事件（`batch.fileResult`）中**按文件各自携带**（支持跨多个测试任务的批量场景），`batch` 级汇总事件携带 `fileName`（多文件列表）/ 用户维度等可聚合字段（当前批量事件完全缺失任务信息，需补齐）。
- **脱敏合规**：文件名仅上报文件名 / 扩展名，不含完整路径；用户维度遵循既有 telemetry 脱敏约定，以匿名化标识上报，不涉及明文个人信息。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 单文件事件含任务信息 | `editorPush.*` / `explorerPush.*` 单文件事件均含 `testTaskNo` / `subTestTaskId` / `fileName` / 用户 |
| AC-2 | 批量事件含任务信息 | `explorerPush.batch.*` 含任务上下文；跨任务批次时任务级字段按 `batch.fileResult` 逐文件携带 |
| AC-3 | 文件名脱敏 | 上报 `fileName` 仅为文件名，不含明文完整路径 |
| AC-4 | 用户可聚合（匿名） | 埋点含匿名化用户标识，可下钻按用户分析推送行为，不含明文个人信息 |
| AC-5 | 不影响主流程 | 埋点缺失 / 失败不影响推送核心链路 |

### 3.8 适配TMS执行方式（UI自动化 / 接口自动化）

#### 需求背景与目标
TMS（测试管理平台）案例适配到本插件时，执行方式需覆盖 **UI自动化**、**接口自动化** 两类自动化类型，与既有 `手工` / `自动化` / `半自动化` 共同构成完整的执行方式取值。试点用户在新増测试案例、推送前校验等环节需要：① 新建模板的执行方式字段即包含 UI自动化 / 接口自动化；② 推送前按执行方式进行严格白名单校验，非法或缺失执行方式被拦截而非静默兜底。本需求目标：将 UI自动化 / 接口自动化 纳入执行方式取值体系，并打通「新增测试案例 → 推送前校验」全链路。

> 关联：执行方式严格白名单已在 `docs/requirements/testtype-whitelist-requirements.md` 定义（白名单含 `手工` / `UI自动化` / `接口自动化` / `自动化` / `半自动化`）；新增测试案例模板字段见 `docs/requirements/新增测试案例文件功能需求.md` §CSV 模板结构 / §YAML 模板结构。本需求归口汇总「TMS 适配」场景下的执行方式诉求。

#### 交互与功能规则
- **新增模板含 UI自动化 / 接口自动化**：新建测试案例（命令 / 右键）的模板中，执行方式（CSV「执行方式」列 / YAML `test_type` 字段）可选值应包含 `UI自动化`、`接口自动化`（与白名单一致），新增文件即具备完整执行方式取值，无需用户手填。
- **新增选择落盘**：新建时选择 `UI自动化` / `接口自动化`，文件对应字段正确落盘为该取值。
- **推送前严格校验**：推送映射阶段对执行方式实施严格白名单校验——命中白名单（含 `UI自动化` / `接口自动化`）原样保留并透传后端 `testType`；空 / 未填写 / 白名单外取值（如 `手动` / `自动` / `xyz`）一律拦截抛 `invalidTestType`，不回退默认值、不静默入库。
- **归一与适配**：从 TMS 适配 / 导入案例时，TMS 执行方式应归一为白名单取值（如 UI 自动化类 → `UI自动化`），归一后复用同一套推送前校验。
- **去空格保留**：执行方式取值含首尾空格（如 ` UI自动化 `）时，去空格后命中白名单并保留，不报错。

#### 验收标准
| 编号 | 验收项 | 标准 |
|------|--------|------|
| AC-1 | 模板含取值 | 新建模板执行方式可选值含 `UI自动化` / `接口自动化`（CSV 与 YAML 一致） |
| AC-2 | 新增选择落盘 | 选 `UI自动化` / `接口自动化` 新建，文件字段正确落盘 |
| AC-3 | 合法透传 | 执行方式=`UI自动化` / `接口自动化` 推送前校验通过并透传 testType |
| AC-4 | 空值拦截 | 执行方式空 / 未填时推送前拦截，抛 `invalidTestType`，提示未填写，不静默入库 |
| AC-5 | 非法拦截 | 白名单外取值（手动 / 自动 / xyz）推送前拦截，提示取值不合法，不回退默认值 |
| AC-6 | TMS 归一 | TMS 导入执行方式归一为白名单取值并复用同一校验 |
| AC-7 | 空格去留 | 带首尾空格取值去空格后命中白名单并保留，不报错 |

## 4. 用户操作流程

### 4.1 展开步骤内查找替换
1. 在结构化案例文件中点击「展开步骤」，进入内联子表格。
2. 打开查找替换面板，输入关键字并选择匹配选项。
3. 在子表内定位 / 替换步骤描述、预期结果或数据；样例行只读被跳过。
4. 替换后内容写回，折叠态文本同步；如需撤销，Ctrl+Z 回退。

### 4.2 空步骤展开自动初始化
1. 某行 `steps` 为空，点击「展开步骤」。
2. 自动生成一个空步骤子表（序号 1，各字段为空占位）。
3. 直接录入步骤描述 / 预期结果 / 数据，失焦即写回。
4. 保存后 `steps` 规范化落盘，再次展开完整还原。

### 4.3 推送并查看埋点任务信息
1. 在资源管理器右键推送单个或批量案例文件。
2. 推送埋点事件携带 `testTaskNo` / `subTestTaskId` / `fileName` / 用户等维度上报。
3. 后台按测试任务 / 子任务 / 文件名 / 用户下钻分析推送行为与失败分布。

### 4.4 适配TMS执行方式
1. 通过命令 / 右键新建测试案例，模板执行方式可选值含 `UI自动化` / `接口自动化`。
2. 选择 `UI自动化` 或 `接口自动化` 创建，文件对应字段落盘为该取值。
3. 推送前校验按白名单执行：合法值透传 `testType`；空 / 非法值拦截并提示，不静默兜底。
4. 从 TMS 适配 / 导入的案例，执行方式归一为白名单取值后复用同一校验链路。
