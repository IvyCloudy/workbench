# 文件标识功能说明

## 概述

为了区分通过"新增测试案例"命令创建的文件和手动创建的文件，插件采用 **`.vscode` 目录记录方案**：在工作区下的 `.vscode/testcase-viewer/created-files.json` 中维护一份"通过命令创建的文件"清单。

> 该方案**不修改** YAML / JSON / CSV 文件本身的内容，避免干扰解析逻辑、对比工具和文件格式合法性。

---

## 实现方式

### 1. 记录文件位置

```
<workspaceRoot>/.vscode/testcase-viewer/created-files.json
```

### 2. 记录文件结构

```json
{
  "/abs/path/to/.../测试案例/登录功能测试.yaml": {
    "createdAt": "2026-06-13T14:44:22.123Z",
    "version": "1.0"
  },
  "/abs/path/to/.../测试案例/输入验证/case.yaml": {
    "createdAt": "2026-06-14T10:11:12.000Z",
    "version": "1.0"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| 顶层 key | string | 文件**绝对路径** |
| `createdAt` | string | 创建时间（ISO 8601） |
| `version` | string | 模板版本号 |

### 3. 写入时机

在 `extension.ts` 的 `handleCreateNewTestCase` 函数中，文件创建成功后调用 `markAsCreatedByCommand(filePath)` 写入记录。

### 4. 自动同步

| 文件操作 | 行为 |
|---|---|
| 重命名 | 监听 `onDidRenameFiles`，将记录的旧路径键替换为新路径 |
| 删除 | 监听 `onDidDeleteFiles`，移除对应记录 |
| 手动维护 | `cleanupRecords()` 一次性清理已不存在的文件记录 |

## 工具 API

实现位置：[`src/utils/fileIdentifier.ts`](/Users/myronliu/IdeaProjects/yyy/workbench/src/utils/fileIdentifier.ts)

| 导出函数 | 作用 |
|---|---|
| `markAsCreatedByCommand(filePath)` | 标记文件为通过命令创建 |
| `unmarkAsCreatedByCommand(filePath)` | 移除指定文件的标记 |
| `isCreatedByCommand(filePath)` | 判断文件是否通过命令创建 |
| `getFileCreationInfo(filePath)` | 获取 `{ createdAt, version }`，未标记返回 `null` |
| `cleanupRecords()` | 清理已不存在的文件记录 |
| `addCommandCreatedDecoration(editor)` | 为命令创建的文件在编辑器首行添加 `📝` 装饰器 |
| `showCreationInfoInStatusBar(filePath)` | 在状态栏显示创建信息（返回 `StatusBarItem`） |

## 如何识别

### 方法一：程序检测（推荐）

```typescript
import { isCreatedByCommand, getFileCreationInfo } from './utils/fileIdentifier';

if (isCreatedByCommand(filePath)) {
    const info = getFileCreationInfo(filePath);
    // info => { createdAt: '2026-06-13T14:44:22.123Z', version: '1.0' }
}
```

### 方法二：直接查看记录文件

打开 `<workspaceRoot>/.vscode/testcase-viewer/created-files.json`，文件路径作为 key 出现即代表该文件由命令创建。

> 注意：不要再通过"读取 YAML 文件开头是否有 `---` 前置元数据"来判断，旧方案已废弃。

## 优势

| 优势 | 说明 |
|---|---|
| 零侵入 | 不修改 YAML/JSON/CSV 内容，不影响解析、对比、推送等流程 |
| 兼容性好 | 不需要处理前置元数据带来的解析与同步问题 |
| 简单可靠 | 仅维护一份 JSON，结构清晰 |
| 可扩展 | 后续可在每条记录上新增字段（作者、来源等） |
| 自动同步 | 监听重命名/删除，记录与实际文件保持一致 |

---

## 注意事项

1. **该 JSON 文件位于 `.vscode/`**：建议按照团队习惯纳入项目共享，或加入 `.gitignore`。
2. **手动复制/移动文件不会自动产生记录**：仅"新增测试案例"命令创建的文件会被标记。
3. **删除该 JSON 文件不会损坏数据**：仅会丢失"通过命令创建"的标识信息，YAML 数据本身不受影响。
4. **跨工作区不共享**：记录与当前工作区强绑定，换工作区打开时记录不会自动迁移。
