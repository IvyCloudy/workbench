# YAML 解析功能增强需求文档（推送后不破坏原始内容）

> 文档视角：业务 / 用户（案例编辑者、测试负责人）
> 适用范围：案例编辑器中的 YAML 格式案例文件（`.yaml` / `.yml`），聚焦「解析」与「推送 / 保存回写」环节对原始文件内容的保护
> 说明：本文档描述用户需要的能力、业务规则与验收标准，不涉及具体实现方式。

---

## 1. 总体背景与目标

YAML 案例文件以可读的缩进结构书写，常包含注释、多行文本（步骤描述）、特定缩进与块标量（`|` / `>`）等手工排版习惯。早期实现中，推送 / 保存会把文件整体重新序列化，可能丢失注释、打乱原有的块标量与多行文本、改变顶层结构（数组 / 单对象），导致"推送一次，原文件面目全非"。

总体目标：
1. **推送 / 保存后保留原始内容形态**：注释、多行文本、块标量、顶层数组 / 单对象结构不被破坏。
2. **只动被编辑的行，不动其余内容**：以 `testcase_id` 为主键对齐行，避免插入 / 删除 / 排序导致的错位覆盖。
3. **不可解析时安全降级**：文件无法解析为表结构时，切换到文本编辑器并定位错误，绝不展示空表 / 数据丢失。

---

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 原始源数据 | 文件打开时解析出的原始内容快照，用于保存 / 推送时与当前编辑结果做行级对齐 |
| 行主键 | 案例中稳定标识一行的字段（如 `testcase_id`），用于把编辑后的行与原始记录对应 |
| 块标量 | YAML 中表示多行文本的语法（`|` 保留换行、`>` 折叠换行） |
| 顶层形态 | 文件最外层是「对象数组」（多条案例）还是「单个对象」（单条案例），保存时必须维持一致 |

---

## 3. 功能需求

### 3.1 推送 / 保存回写时保留原始形态

#### 需求背景与目标
用户编辑 YAML 案例并推送 / 保存后，期望原文件除被修改的字段外保持原样——注释、手工排版、多行文本、块标量、顶层数组 / 单对象结构均不被动。早期整体重序列化会破坏这些习惯，本功能目标是让回写"像手工改了几行"而不是"整篇重写"。

#### 交互与功能规则
- **行级对齐（主键匹配）**：保存 / 推送时，系统以案例的主键字段（`testcase_id`）为基准，将当前编辑的每一行与原始源数据中的真实记录一一对应；只替换被改动的字段值，未改动的字段沿用原始记录，避免"插入 / 删除 / 排序后索引错位导致相邻行被覆盖"。
- **新插入行的安全处理**：对于新增且无法在原始数据中匹配到主键的行，其明细字段（对象 / 对象数组）回退为空结构，而非错误地继承相邻原始行的数据。
- **顶层形态维持**：原文件顶层是数组（多条）则回写仍为数组；原文件是单个对象（单条）则维持单对象；系统识别并保留该形态，不擅自在数组 / 对象间转换。
- **多行文本与块标量保留**：字段值中的换行（如步骤描述、SQL）以 YAML 块标量（`|-` 字面量）形式输出，避免把换行写成转义字符破坏可读性；原文件使用的块标量语义在可识别范围内予以保留。
- **注释与手工排版保护**：保存 / 推送仅重写被编辑的数据行，不重写整文件，从而不清除文件头部说明注释、行间注释等原有内容（注释属于全文级结构，由"仅动被编辑行"的策略自然保护）。

### 3.2 不可解析时的安全降级

#### 需求背景与目标
当 YAML 语法错误严重到无法解析为表结构时，若仍强行用案例编辑器打开，用户会看到空表或数据丢失的过渡页。本功能目标是"早发现、安全切"，在打开瞬间即识别并切换到文本编辑器定位错误，而非展示错误结果。

#### 交互与功能规则
- **打开即预检**：用户从资源管理器 / 问题面板等入口打开 YAML 案例文件时，系统在编辑器标签页出现的瞬间同步预检内容；一旦检测到致命语法错误，立即关闭案例编辑器标签页、改用普通文本编辑器打开，用户完全看不到中间的空表 / 过渡页。
- **错误定位与提示**：切换后自动将光标定位到首条错误行，并弹出提示说明"已切换为文本编辑器，共 N 处错误"，提供"一键修复全部""查看问题面板"等快捷入口；错误行号与问题面板数据源保持一致。
- **双保险兜底**：除"打开即预检"路径外，若因时序等原因未能拦截，编辑器内部仍有兜底逻辑在解析失败时静默切换到文本编辑器（不重复弹提示、不重复拉光标），保证用户最终不会停留在空表状态。
- **校验器自保护**：即使语法校验器自身异常，也按"安全降级"处理——直接以文本编辑器打开并提示用户手动检查，而非展示崩溃态。

## 4. 用户操作流程

### 4.1 编辑并推送 YAML 案例（保留原文）
1. 打开 YAML 案例文件，编辑若干行的字段值（如补充预期结果）。
2. 点击「推送」或保存文件。
3. 系统按主键逐行对齐原始数据，仅重写被改动的字段；文件其余内容（注释、未改行、多行文本、块标量、顶层结构）保持不变。
4. 重新打开文件确认：仅目标字段更新，原排版与注释完整保留。

### 4.2 打开有语法错误的文件
1. 双击一个语法严重错误的 YAML 文件。
2. 编辑器瞬间切换为文本编辑器，光标定位到首条错误行。
3. 提示框告知错误数量并提供修复 / 查看问题面板入口。

---

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 编辑后推送，期间新增 / 删除了行 | 以 `testcase_id` 为主键对齐，新增行不继承相邻行旧数据，删除行原始记录不被误并入其它行 |
| 原文件顶层是单对象，编辑多条 | 维持单对象 / 数组形态判定，不擅自在数组与单对象间转换 |
| 字段含多行文本（步骤 / SQL） | 以块标量 `|-` 输出，换行可读，不被转义成字面 `\n` |
| 仅修改个别字段 | 其余字段沿用原始值，不整体重写 |
| 文件语法严重错误无法解析 | 打开即切换文本编辑器并定位首错行，绝不展示空表 |
| 校验器自身异常 | 按安全降级处理，文本编辑器打开并提示手动检查 |
| 修复一条问题可能触发多条诊断 | 逐行独立给出修复，互不冲突，不重复改写同一位置 |

---

## 6. 验收标准

1. **保留原始形态**：编辑并推送 / 保存 YAML 案例后，文件除被编辑字段外，注释、未改行、多行文本（块标量）、顶层数组 / 单对象结构均完整保留，不发生整篇重排。
2. **行级对齐正确**：在插入 / 删除 / 排序后推送，各行以主键正确对应原始记录，不出现"相邻行数据错位覆盖"；新增行明细字段为空结构而非继承旧数据。
3. **安全降级**：语法严重错误的文件打开时瞬间切换文本编辑器并定位首错行，问题面板与提示行号一致；校验器异常时仍安全降级，绝不展示空表 / 数据丢失。
