# 推送失败案例报错数据度量与统计分析 — 需求文档

---

## 一、需求背景

案例经由本插件的推送链路送往后端。推送是一个多阶段、易出错的流程,失败的案例数据目前缺乏系统性的度量与统计分析能力:

1. **失败原因看不见全貌**:当次推送仅提示"成功 N / 失败 M",无法回答"这批失败的案例,失败原因到底集中在哪";
2. **失败无分类**:后端返回的自由文案未被归类为稳定的失败分类与字段维度,无法区分"接口级整批失败"与"行级字段错误",也无法聚合统计;
3. **高频字段缺陷无感知**:若某字段(如步骤描述、预期结果)普遍缺失,推送时高频触发对应空值失败,但这类规律散落在单次失败里,无人汇总;
4. **来源失败差异不透明**:不同来源平台的案例,失败率差异无法量化对比;
5. **未知报错无收敛**:未归类原文散落各次推送,未聚类,分类体系的盲区一直补不上;
6. **分析结果无出口**:即便有失败数据,也缺少"可排序、可下钻、可导出"的分析视图与报告,无法将失败规律转化为可反馈的客观依据。

因此,需要建设一套**推送失败案例报错数据的度量与统计分析能力**:从推送失败的数据采集、分类建模,到多维聚合分析与可导出的报告,形成完整的失败可观测闭环。

---

## 二、需求目的

围绕"**采集 → 分类 → 分析 → 反馈**"四件事,提供:

1. **失败数据埋点采集**:在推送结局事件中补充失败分类、接口级/行级字段分布、未归类原文样本等维度,为后续分析提供数据基础;
2. **失败分类建模**:把后端返回的自由中文失败文案,稳定归类为"失败分类"与"接口级/行级字段"维度,区分接口级公共参数错(一次错=整批失败)与行级字段错;
3. **失败报错聚合分析**:按"字段缺陷热点 / 接口级公共参数 / 来源平台 / 插件版本成功率 / 未知原因"五个视角聚合,输出可排序、可下钻、可对比的视图,看清"失败到底集中在哪";
4. **分析结果可导出反馈**:支持导出为 CSV / 文本报告,作为失败规律的客观依据对外反馈。

> 一句话:**建设推送失败案例报错数据的度量与统计分析能力,把散落的失败变成可归因、可反馈的数据资产。**

---

## 三、功能清单

### 3.1 推送失败数据埋点采集

#### 功能简述
在推送结局事件中补充失败相关维度,使每次推送失败都能被结构化记录,为后续分类与分析提供数据基础。

#### 功能内容

##### 3.1.1 采集字段

| 字段 | 含义 |
|---|---|
| 追踪号 | 推送链路追踪号 |
| 文件名 / 文件类型 | 失败文件与类型 |
| 来源平台 | 案例来源平台(如 TMS / RFWeb / 手工) |
| 插件版本 | 插件版本(用于版本维度切片) |
| 推送时间 | 推送发生时间 |
| 总行数 / 失败行数 / 成功行数 | 行级计数 |
| 失败分类分布 | 失败分类与行数 `分类:行数` |
| 接口级失败分布 | 接口级公共参数失败与行数 |
| 行级字段失败分布 | 行级字段失败与行数 |
| 未归类原文样本 | 未归类失败的原始文案 |
| 是否前置拦截 | 是否因语法/样例等被前置拦截(未推送) |

##### 3.1.2 采集约束

- 失败数据随推送结局事件一并上报,保证"一次推送 = 一条完整失败记录";
- 未归类原文样本截断至合理长度(建议 200 字/条),控制数据体积;
- 采集过程不应阻塞推送主流程,异常时静默降级。

---

### 3.2 推送失败分类建模

#### 功能简述
把后端返回的自由中文失败文案,稳定归类为"失败分类"与"接口级/行级字段"两个正交维度,既保留中文原文供展示,又产出稳定短码供聚合统计。

#### 功能内容

##### 3.2.1 失败分类维度

归类优先级:**先复用结构化信号,再走中文文本归类**。

| 来源 | 分类 | 说明 |
|---|---|---|
| 预校验结构化信号 | 占位 / 空标识 / 样例 / 字段映射错误 等 | 客户端已明确,直接映射 |
| 后端中文文本(关键词) | 网络 / 鉴权 / 重复 / 字段非法 / 不存在 / 服务异常 / 业务拒绝 | 按关键词优先级归类 |
| 都不命中 | 未归类 | 兜底归类,不丢失败 |

##### 3.2.2 接口级 / 行级字段维度

从失败文案抽取命中的接口字段,并带级别:

| 级别 | 含义 |
|---|---|
| 接口级(公共参数,一次错=整批失败) | 测试任务编号 / 子任务 / 产出物 / 来源平台 / 设计人 等请求体顶层或公共参数 |
| 行级(每行独立) | 案例标识 / 案例路径 / 案例名称 / 步骤描述 / 预期结果 / 优先级 / 类型 / 前置条件 / 关键案例 / 测试要点 / 步骤数量一致性 等单条案例字段 |

分层的目的是避免"设计人无权限"这类接口级一次错误,在计数维度淹没"步骤描述缺失"等行级字段的真实分布。

##### 3.2.3 设计要点

- 中文原文只作"展示",分类/字段短码只作"统计",二者解耦;
- 新增后端错误类型:只需在归类规则表加一条规则,不改持久化结构、不改采集字段。

---

### 3.3 失败报错聚合分析视图

#### 功能简述
基于采集与分类后的失败数据,提供五视角聚合分析,输出"可排序、可下钻、可对比"的视图,直接回答"这些案例失败集中在哪"。视图由插件内命令调出,也可导出供二次分析。

#### 功能内容

##### 3.3.1 五视角聚合

| 视角 | 聚合维度 | 输出示例 | 说明 |
|---|---|---|---|
| ① 字段缺陷热点 | 按行级字段失败汇总行数,降序 | `步骤描述: 842, 预期结果: 530, 案例名称: 210` | 行级字段缺失/格式错集中处 |
| ② 接口级公共参数 | 按接口级失败汇总,标注"连坐整批" | `设计人: 100(整批), 来源平台: 30` | 公共参数一次错导致整批失败 |
| ③ 来源平台失败分布 | 按来源平台切片失败率 | `TMS: 失败率 12%, RFWeb: 3%` | 哪类来源平台的案例更糟 |
| ④ 插件版本成功率对比 | 按插件版本分组成功率 | `v1.4: 88% → v1.5: 93%` | 插件侧改动对失败率的影响(仅观测) |
| ⑤ 未知原因追踪 | 汇总未归类原文聚类 | "无效的状态值" ×23 | 分类体系盲区,需补规则 |

##### 3.3.2 视图交互

- **默认视图**:字段缺陷热点 Top10(行级)+ 接口级 Top5,直接回答"失败最集中在哪";
- **筛选**:可按来源平台 / 插件版本 / 时间窗过滤,定位"某来源/某版本"的问题;
- **下钻**:点某字段 → 列出近 20 个含该失败的 文件名 + 时间,便于抽样核对;
- **对比模式**:选两个插件版本 → 展示成功率差值与各字段失败率变化(仅观测插件侧变动影响)。

##### 3.3.3 导出

- "导出 CSV":输出 `字段,级别,失败行数,失败文件数,涉及来源,示例版本` 五列,供数据侧做趋势看板或对外反馈;
- "复制报告":生成纯文本摘要(见 §3.4),便于贴工单/IM。

---

### 3.4 分析结果导出与反馈

#### 功能简述
把聚合分析结论固化为可带走的报告,作为失败规律的客观依据对外反馈。本需求不负责把报告自动回传(超出插件边界),仅提供导出能力。

#### 功能内容

| 能力 | 说明 |
|---|---|
| 文本报告 | 含 时间范围 / 总推送行数 / 总失败行数 / 成功率 / 五视角 Top 摘要 / 未归类原文样本 |
| CSV 导出 | 字段级失败明细表,可二次透视 |
| 未归类原文样本 | 未归类原文聚类 Top10 + 次数,附"建议归属分类"草拟,供补分类体系 |

**文本报告示例**:

```
推送失败报错分析报告
时间范围: 2026-07-01 ~ 2026-07-31
总推送行数: 12,000 | 失败行数: 1,480 | 成功率: 87.7%
---
【① 字段缺陷热点(Top5)】
- 步骤描述为空: 842 行
- 预期结果为空: 530 行
- 案例名称为空: 210 行
【② 接口级公共参数】
- 设计人无权限: 100 行(整批连坐)
【③ 来源平台失败率】
- TMS: 12.3% | RFWeb: 3.1% | 手工: 5.0%
【④ 插件版本成功率】
- v1.4: 88.0% | v1.5: 91.2%
【⑤ 未归类原文 Top3】
- "无效的状态值": 23 次
- "阶段信息不匹配": 11 次
```

---

### 3.5 未知失败原因归类补盲(度量反哺分类体系)

#### 功能简述
未归类原文是分类体系最薄弱处。度量视图应定期(或命令触发)对未归类原文做本地聚类,输出"高频未归类原文 Top",供插件开发补充分类规则,缩小未归类占比。

#### 功能内容

| 能力 | 说明 |
|---|---|
| 高频未归类榜单 | 对未归类原文去重计数,输出 Top10 原文 + 出现次数 |
| 占比监控 | `未归类占比 = 未归类行 / 总失败行`,目标逐步压降 |
| 补规则提示 | 每条附"建议归属分类"草拟,开发采纳后补充分类映射 |

## 四、整体架构

本需求覆盖"采集 → 分类 → 分析 → 导出"全链路:

- **采集层**:推送结局事件携带失败分类、接口级/行级字段分布、未归类原文样本等维度;
- **分类层**:把自由中文失败文案归类为稳定短码,中文原文与统计短码解耦;
- **持久化层**:失败数据本地结构化存储,读写异常降级,近 30 天滚动;
- **分析层(新增)**:插件内分析命令读取存储,做五视角聚合,渲染分析视图 / 导出 CSV / 复制报告;
- **分类补盲**:仅扩展插件内分类映射规则,不改存储结构、不改采集字段。

各层解耦:分类层只产数据不影响流程、分析层纯消费、补盲只扩展映射;采集层异常静默降级,不阻塞推送。

## 五、验收标准

| 编号 | 验收项 | 标准 |
|---|---|---|
| AC-1 | 失败数据采集 | 每次推送失败(含拦截类)的结局事件均携带 失败分类分布/接口级失败分布/行级字段失败分布/未归类原文样本 |
| AC-2 | 采集不阻塞 | 采集/持久化异常时静默降级,不弹错、不影响推送主流程 |
| AC-3 | 分类覆盖 | 预校验信号与后端文本均归类为正确分类(含未归类兜底) |
| AC-4 | 归类优先级 | 同时带结构化信号与后端文本时取结构化信号 |
| AC-5 | 接口级/行级分层 | 接口级(一次错=整批)与行级字段分层聚合,互不淹没 |
| AC-6 | 字段缺陷热点 | 分析视图按行级字段失败行数降序输出 Top10,标明级别=行级 |
| AC-7 | 接口级连坐标识 | 接口级失败单独展示并标注"一次错连坐整批" |
| AC-8 | 来源失败分布 | 可按来源平台切片失败率,定位高失败来源 |
| AC-9 | 版本对比 | 选两插件版本输出成功率差值与字段失败率变化(仅观测) |
| AC-10 | 未知聚类榜单 | 对未归类原文去重计数输出 Top10 原文 + 次数 |
| AC-11 | 导出 CSV | 导出含 字段/级别/失败行数/失败文件数/来源/版本 的 CSV |
| AC-12 | 复制报告 | 生成含五视角摘要 + 未归类原文样本的纯文本报告 |
| AC-13 | 筛选与下钻 | 可按来源/版本/时间过滤,点字段下钻到失败文件列表 |
| AC-14 | 归类补盲闭环 | 高频未归类原文可转化为分类映射规则补充 |
| AC-15 | 存储滚动 | 失败记录保留近 30 天滚动,不无限增长 |
| AC-16 | 映射可扩展 | 新增分类只在映射表追加一行,分析与渲染无需改代码 |
