# 测试要点文件与测试案例文件关联及关联展示功能需求文档

> 文档视角：业务 / 用户（测试架构师、用例工程师、测试负责人、可视化插件浏览者）
> 适用范围：在「测试任务 / <子任务文件夹>」目录体系下，将测试要点文件（Markdown / XMind）与测试案例文件（CSV / YAML / YML / JSON）建立绑定关联，并在资源管理器、状态栏、可视化插件 / 大纲视图中呈现关联结果
> 配套能力（不在本文档展开）：关联关系的**匹配计算引擎**见 `point-case-linker-requirements.md`（负责按 `parent_id` + `path` 归一化匹配、输出 type 1/2/3 分档与统计）；本文档聚焦"如何建立绑定"与"如何把关联关系与匹配结果展示给用户"
> 说明：本文档描述用户需要的能力、业务规则与验收标准，不涉及具体实现方式。
> 章节约定：每个功能模块均按「需求背景与目标」「交互与功能规则」两部分展开。

---

## 1. 总体背景与目标

在测试大纲编写与测试案例落地的过程中，存在两份并行数据：

- **测试要点文件**（Markdown / XMind）：描述"测什么"，每条测试要点携带序号（pointId）、测试点名称（pointName）、路径（pointPath，形如"功能条目/测试要点"）。位于 `测试任务 / <任务> / 测试大纲/` 下。
- **测试案例文件**（CSV / YAML / YML / JSON）：描述"怎么测"，案例通过 `parent_id` 字段回指所属测试要点序号，并可能带 `path` 字段冗余保存所属路径。位于 `测试任务 / <任务> / 测试案例/` 下。

用户有两层诉求：
1. **显式绑定**：测试架构师希望把某个测试要点文件与一个或多个测试案例文件**显式绑定**，形成稳定的"要点 ↔ 案例"对应关系，用于大纲浏览、快速跳转、覆盖率核对。绑定是用户对"谁属于谁"的**主动声明**，与匹配引擎基于字段的**自动推断**互补。
2. **关联展示**：无论是显式绑定还是自动匹配，用户都需要在不打开多个文件的前提下，一眼看到"这个测试要点下覆盖了哪些案例""这条案例挂在哪个测试要点下"，并能在二者之间快速跳转、识别未覆盖 / 弱关联（type 2/3）的情况。

总体目标：
1. **双向绑定入口**：在资源管理器右键（或命令面板）上，测试要点文件可"绑定测试案例"、测试案例文件可"绑定测试要点"，且方向不可错配。
2. **绑定安全可控**：候选扫描限定同任务目录、占用保护（1:1 不互相破坏）、未绑/已绑/被占用状态清晰、保存后即时刷新。
3. **绑定生命周期同步**：重命名 / 删除任一端文件时，绑定记录自动更新或清理，不残留脏绑定。
4. **多形态关联展示**：资源管理器 🔗 徽标、状态栏跳转按钮、可视化插件 / 大纲树中按测试要点聚合展示案例（含匹配类型分档与统计）、诊断命令输出关联概览。
5. **未覆盖与弱关联提示**：展示层对"无案例覆盖的要点""仅弱关联（type 2/3）的案例"给出可识别的视觉或统计提示，辅助补全用例。

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 测试要点文件 | 位于 `测试任务 / <任务> / 测试大纲/` 下的 `.md` / `.xmind` 文件 |
| 测试案例文件 | 位于 `测试任务 / <任务> / 测试案例/` 下的 `.csv` / `.yaml` / `.yml` / `.json` 文件 |
| 绑定（显式关联） | 用户通过对话框主动建立的"要点 ↔ 案例"对应关系，持久化在绑定记录中 |
| 匹配（自动推断） | 由匹配引擎基于案例 `parent_id` + `path` 与要点清单自动计算出的归属关系，分 type 1/2/3 三档 |
| 占用（Occupancy） | 一个案例文件已绑定给某要点时，对其它要点而言处于"被占用"状态，避免一案例多要点绑定冲突 |
| 关联展示 | 在资源管理器 / 状态栏 / 可视化插件 / 大纲树中呈现"要点下有哪些案例""案例属于哪个要点"及覆盖情况 |
| 匹配类型分档 | type 1 = parent_id + path 双命中（最强）；type 2 = 仅 path 命中；type 3 = 仅 parent_id 命中（最弱） |
| 测试任务目录结构 | 路径须包含 `测试任务 / <子任务文件夹>`，绑定与展示均限定在该结构内 |

## 3. 功能需求

### 3.1 绑定入口与方向校验

#### 需求背景与目标
绑定入口必须贴合用户操作习惯（资源管理器右键最自然，命令面板适合键盘流），且**方向不可错配**——要点文件只能发起"绑定测试案例"，案例文件只能发起"绑定测试要点"，否则容易把关系建反。

#### 交互与功能规则
- **要点文件入口**：在 `测试任务 / <任务> / 测试大纲/` 下的 `.md` / `.xmind` 文件上右键，上下文菜单出现「绑定测试案例」；点击打开绑定对话框，方向为"要点 → 案例"，对话框扫描同任务下的测试案例候选。
- **案例文件入口**：在 `测试任务 / <任务> / 测试案例/` 下的 `.csv` / `.yaml` / `.yml` / `.json` 文件上右键，出现「绑定测试要点」；点击打开对话框方向为"案例 → 要点"，候选为同任务测试大纲下的要点文件。
- **多扩展名覆盖**：要点侧 `.md` 与 `.xmind` 均能发起"绑定测试案例"；案例侧四种扩展名（`.csv` / `.yaml` / `.yml` / `.json`）均能发起"绑定测试要点"。
- **非任务目录拦截**：不在「测试任务 / <子任务>」结构下的文件右键绑定被拦截并提示，不打开对话框、不埋点进入正常流程。
- **方向错配拦截**：在测试大纲的要点文件上误触发"绑定测试要点"、或在测试案例文件上误触发"绑定测试案例"时，方向校验失败并提示正确用法（要点侧提示"绑定测试案例只能用于测试大纲目录"、案例侧提示对应文案）。
- **命令面板入口**：命令面板可检索「绑定测试案例」「绑定测试要点」并执行；无右键上下文时回退到当前活动编辑器文件推断方向，推断失败给出提示。

### 3.2 绑定对话框与候选管理

#### 需求背景与目标
绑定对话框是用户建立关联的主阵地，需要清晰呈现"可绑哪些、已绑哪些、被谁占用"，让绑定操作安全、不破坏既有 1:1 关系。

#### 交互与功能规则
- **候选扫描（要点 → 案例）**：打开"绑定测试案例"对话框时，扫描同任务 `测试案例` 目录下全部 `.csv` / `.yaml` / `.yml` / `.json`（递归、跳过以 `.` 开头的隐藏目录）；扫描期间显示加载态，不假死。
- **候选扫描（案例 → 要点）**：打开"绑定测试要点"对话框时，扫描同任务 `测试大纲` 目录下的 `.md` / `.xmind`。
- **已绑定标记**：候选中已与当前源绑定的项标记为"已绑定"，默认勾选 / 高亮；其余为未绑定。
- **占用保护**：候选若已被其它要点（非当前源）绑定，标记为"已被其他要点绑定"且不可选择，并展示占用者相对路径，避免误选破坏 1:1 占用关系。
- **空态提示**：目标目录无任何候选时，显示空态提示（如"暂无候选案例"），并提供「打开目录」按钮在资源管理器定位到目标目录，不报错。
- **保存即绑定 / 解除**：在对话框选择若干候选并保存，即以覆盖方式写入"源 → 选中候选"的绑定关系（旧绑定被新选择覆盖）；选择 0 个候选保存即解除该源的原绑定。
- **保存后自刷新**：保存成功后自动刷新两端文件的 🔗 装饰器与状态栏跳转按钮，并提示"已绑定 N 个测试案例"，无需用户手动切换编辑器。

### 3.3 绑定生命周期同步

#### 需求背景与目标
绑定关系建立后，用户会对文件重命名、移动或删除。绑定记录必须随之更新或清理，否则会出现"指向已不存在文件"的脏绑定。

#### 交互与功能规则
- **重命名同步**：任一端文件重命名后，绑定记录中的路径自动更新为新路径，关联关系不丢失，跳转仍有效。
- **删除要点**：删除某测试要点文件（`.md` / `.xmind`）时，移除该要点的整条绑定记录，并从其余案例侧剔除该要点引用。
- **删除案例**：删除某测试案例文件时，移除该案例相关的绑定记录，对应要点侧不再显示已失效关联。
- **跨区保护**：重命名 / 移动导致文件离开"测试任务 / <子任务>"结构时，绑定按规则清理，不产生跨区脏绑定。

### 3.4 关联展示：资源管理器与状态栏

#### 需求背景与目标
绑定关系建立后，用户需要在日常浏览文件时就能感知关联，并能在两端文件间一键跳转，无需记忆路径。

#### 交互与功能规则
- **🔗 徽标装饰**：已参与绑定的要点文件与案例文件在资源管理器中均显示 🔗 装饰徽标；未参与绑定的普通文件不显示。
- **状态栏跳转（要点侧）**：打开已绑定的测试要点文件时，状态栏显示「跳转到已绑定的测试案例」按钮（含绑定案例名 tooltip）；点击打开对端案例文件并定位。
- **状态栏跳转（案例侧）**：打开已绑定的测试案例文件时，状态栏显示「跳转到已绑定的测试要点」按钮；点击打开对端要点文件。
- **状态栏动态显隐**：未绑定的文件打开时状态栏跳转按钮自动隐藏；切换编辑器时按当前活动文件动态更新。
- **保存后自现**：在对话框完成绑定后，状态栏跳转按钮立即出现，不需要手动切换编辑器触发。
- **跳转健壮性**：
  - 未绑定文件点击跳转时，提示"是否立即绑定"，选择后可直接打开绑定对话框；
  - 跳转目标文件已被删除时，给出告警"绑定的测试案例 / 测试要点文件不存在"，不静默失败。

### 3.5 关联展示：可视化插件 / 大纲树聚合

#### 需求背景与目标
测试架构师在大纲视图中浏览测试要点时，希望直接看到"这个要点下覆盖了哪些案例""覆盖是否充分"，而不是逐个打开文件核对。展示层应基于**匹配引擎**的关联结果（绑定关系 + 自动匹配）聚合呈现，并区分关联强度。

#### 交互与功能规则
- **按要点聚合案例**：可视化插件 / 大纲树以测试要点为节点，其下展开显示该要点关联的全部测试案例（名称、关键摘要如"【前置条件】…【预期结果】…"）。
- **匹配类型分档呈现**：每个案例标注其关联强度——type 1（parent_id + path 双命中）为强关联、type 2（仅 path）为路径兜底、type 3（仅 parent_id）为弱关联；展示层以可区分的标识（如不同颜色 / 角标）呈现三档，便于识别"哪些是弱证据"。
- **未覆盖要点提示**：对没有任何案例（绑定或匹配）覆盖的测试要点，在大纲树中以明显标识（如空心 / 待补充标记）提示，辅助补全用例。
- **统计概览**：展示层给出关联统计——总匹配案例数、type 1/2/3 分布、孤儿案例数（parent_id 与 path 均无法命中任何要点）、父点尾号剥离次数（数据质量观测）；统计与匹配引擎输出一致。
- **诊断命令**：提供诊断命令，输出当前激活要点文件对应的关联 envelope（按要点聚合的案例清单）与 stats（总数、类型分布、孤儿、剥离次数）两块 JSON，便于排查关联异常（如绑定案例存在但匹配为 0 的情况）。
- **覆盖式刷新**：绑定关系变化、文件保存、重命名后，大纲树 / 插件视图的关联展示自动刷新，保持与底层数据一致。

### 3.6 关联展示：案例侧反向归属

#### 需求背景与目标
用例工程师在编辑某条案例时，也需要知道"我这条案例挂在了哪个测试要点下"，以便确认归属是否正确、避免错位。

#### 交互与功能规则
- **反向归属展示**：在测试案例编辑器（或案例文件视图）中，展示该案例通过绑定 / 匹配归属到的测试要点名称与路径；归属取自匹配引擎的反向索引（案例 → 要点，O(1) 查询）。
- **弱关联提示**：若案例仅以 type 2 / type 3 命中（缺少 parent_id 或 path 不一致），在归属展示中给出"弱关联"提示，建议用户补全 parent_id / path 以提升关联可靠性。
- **孤儿案例提示**：若案例既无绑定、匹配也未命中任何要点（孤儿），在展示中标注"未关联任何测试要点"，提示用户建立绑定或补全字段。

## 4. 用户操作流程

### 4.1 绑定测试要点与测试案例
1. 在资源管理器定位到 `测试任务 / 任务A / 测试大纲 / 登录要点.md`，右键选择「绑定测试案例」。
2. 对话框扫描同任务 `测试案例` 目录下候选；已绑定的默认勾选，被其它要点占用的不可选并展示占用者。
3. 勾选目标案例后保存，提示"已绑定 N 个测试案例"，两端文件出现 🔗 徽标，状态栏出现跳转按钮。

### 4.2 跳转与生命周期
1. 打开已绑定要点文件，状态栏显示「跳转到已绑定的测试案例」，点击直接打开案例并定位。
2. 重命名任一端文件，绑定记录自动更新，🔗 与跳转仍有效。
3. 删除要点文件，其整条绑定记录被清理，案例侧不再显示该失效关联。

### 4.3 大纲树查看覆盖情况
1. 在可视化插件 / 大纲视图中展开测试要点节点，查看其下聚合的案例清单与每条的关联强度（type 1/2/3）。
2. 无覆盖的要点以待补充标记提示；统计区展示总匹配数、三档分布、孤儿数。
3. 执行诊断命令，输出 envelope 与 stats JSON 核对异常关联。

### 4.4 案例侧确认归属
1. 打开某测试案例文件，查看其归属的测试要点名称与路径。
2. 若显示"弱关联"或"未关联任何测试要点"，补全 parent_id / path 或建立显式绑定。

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 非「测试任务 / <子任务>」结构下的文件右键绑定 | 拦截并提示，不打开对话框 |
| 要点文件误触发"绑定测试要点" | 方向校验失败并提示正确用法 |
| 案例文件误触发"绑定测试案例" | 方向校验失败并提示正确用法 |
| 候选被其它要点占用 | 标记"已被其他要点绑定"且不可选，展示占用者 |
| 目标目录无候选 | 空态提示 + 「打开目录」按钮，不报错 |
| 保存时选择 0 个候选 | 解除该源原绑定（覆盖式清空） |
| 任一端文件重命名 | 绑定路径同步更新，关联不丢失 |
| 删除要点文件 | 移除该要点整条绑定，清理案例侧引用 |
| 删除案例文件 | 移除相关绑定记录 |
| 跳转目标已被删除 | 告警"绑定的文件不存在"，不静默失败 |
| 未绑定文件点击跳转 | 提示"是否立即绑定"，可直达对话框 |
| 大纲树中要点无任何案例覆盖 | 以待补充标记提示 |
| 案例仅 type 2 / type 3 命中 | 展示"弱关联"提示，建议补全字段 |
| 案例为孤儿（无绑定且无匹配） | 标注"未关联任何测试要点" |
| 绑定保存后 | 立即刷新 🔗 徽标与状态栏，无需切换编辑器 |
| 诊断命令输出 | 输出 envelope（按要点聚合案例）+ stats（总数/三档/孤儿/剥离）两块 JSON |

## 6. 验收标准

1. **双向绑定入口**：测试大纲下的 `.md` / `.xmind` 可"绑定测试案例"、测试案例下的 `.csv` / `.yaml` / `.yml` / `.json` 可"绑定测试要点"；非任务目录、方向错配均被拦截并提示；命令面板入口可用。
2. **绑定对话框安全**：候选扫描限定同任务目录（递归、跳过隐藏目录）；已绑定项标记、被占用项禁选并展示占用者；空态有提示与打开目录入口；保存覆盖式写入、0 选即解除。
3. **生命周期同步**：重命名 / 删除任一端，绑定记录自动更新或清理，不残留脏绑定、不跨区脏关联。
4. **资源管理器与状态栏展示**：已绑定两端文件显示 🔗 徽标；打开已绑文件状态栏显示对应跳转按钮并可一键跳转；未绑定隐藏；保存后即时自现；跳转目标缺失 / 未绑均有友好提示。
5. **大纲 / 插件聚合展示**：可视化插件 / 大纲树按测试要点聚合案例，标注 type 1/2/3 关联强度、提示未覆盖要点，统计总匹配数、三档分布、孤儿数、剥离次数；诊断命令输出 envelope + stats。
6. **案例侧反向归属**：案例文件展示其归属要点；弱关联 / 孤儿均有明确提示，引导用户补全关联。
