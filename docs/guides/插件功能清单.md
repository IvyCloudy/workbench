## 一、快速了解

**TestCase Viewer** 是一个 VS Code 扩展插件，为测试案例文件提供专属的表格化编辑体验。您可以在插件中像操作 Excel 一样编辑测试案例，并通过一键推送将数据提交到后端系统。

### 支持的文件格式

- **CSV** — 标准 CSV 表格（支持多行文本字段）
- **YAML** / **YML** — 支持嵌套步骤明细的 YAML 案例文件
- **JSON** — JSON 格式案例文件

### 文件存放位置

- **测试案例**：必须位于工作区的 `测试任务/<任务名>/测试案例/` 目录下，插件才能完整识别和处理
- **测试要点**：位于工作区的 `测试任务/<任务名>/测试大纲/` 目录下，用于存放测试点清单（Markdown 格式）

### 界面组成

```
┌─────────────────────────────────────────────────┐
│  任务绑定状态 | 任务编号 | 任务名称               │
├─────────────────────────────────────────────────┤
│  搜索框 | 筛选按钮 | 推送 | 查找 | 选区信息      │
├──────────────────────────────────────────────────┤
│  行号 │  testcase_id │  列A  │  列B  │  ...     │
│  #1   │  MA...       │  值   │  值   │          │
│  #2   │  TC...       │  值   │  值   │          │
│ ...   │              │       │       │          │
└──────────────────────────────────────────────────┘
```

## 二、案例编辑器

### 2.1 打开与创建文件

| 操作 | 方式 |
|------|------|
| **打开已有文件** | 在 VS Code 资源管理器中单击 CSV / YAML / JSON 案例文件，自动以表格编辑器打开 |
| **新建测试案例** | 在资源管理器中右键 `测试案例/` 目录 → **新增测试案例** → 选择 CSV 或 YAML 格式，插件自动创建带模板的新文件 |
| **切换文本编辑** | 点击工具栏 📄 图标，切换到 VS Code 原生文本编辑器 |

> 每个打开的文件拥有独立的编辑标签页（Tab），不同文件的状态互不影响。

### 2.2 单元格编辑

#### 基本编辑

| 操作 | 方式 |
|------|------|
| **进入编辑** | 双击单元格 |
| **保存修改** | 按 `Enter` |
| **取消修改** | 按 `Esc` |

#### 多行文本编辑

当单元格内容包含多行文本（如步骤描述、预期结果等）时：

| 操作 | 方式 |
|------|------|
| **展开多行编辑** | 拖动行号格下方分割线拉高行高，或双击行号格切换展开/收起 |
| **输入换行** | 在多行模式下按 `Enter` 换行 |
| **提交多行内容** | 按 `Ctrl/Cmd + Enter` |
| **强制插入换行符** | 按 `Alt/Option + Enter` |

> 多行编辑时，输入框会以浮动窗口形式显示，不受单元格大小限制，方便完整查看和编辑大段文本。多行内容保存到文件时采用标准 CSV 格式，换行内容自动以双引号包裹，确保下次打开时正常显示。

#### 特殊类型编辑

| 列类型 | 编辑方式 | 说明 |
|--------|----------|------|
| **步骤明细列** | 双击打开独立弹窗 | 在弹窗中编辑每个步骤的字段（操作描述、预期结果、UI检查等），支持添加/删除/复制步骤 |
| **数组列** | 双击打开列表弹窗 | 显示为标签样式，弹窗中逐项编辑，支持增删改排序 |
| **受保护列** | 禁止编辑 | 显示为灰色底色，尝试编辑时会给出提示 |

#### 批量填充

选中矩形选区后，编辑选区内的任意一个单元格，该值会批量写入整个选区中同一列的单元格，大幅提升效率。

### 2.3 行与列操作

通过右键菜单操作：

| 操作 | 位置 | 说明 |
|------|------|------|
| **在上方插入行** | 右键行 | 在当前行上方添加空行，自动生成唯一标识 |
| **在下方插入行** | 右键行 | 在当前行下方添加空行 |
| **在下方复制行** | 右键行 | 完整复制当前行内容到下方（标识和编号重新生成） |
| **删除行** | 右键行 | 删除当前行（可撤销） |
| **批量删除** | 选中多行后右键 | 删除所有选中的行 |
| **插入列** | 右键列头 | 在当前列左侧或右侧插入新列 |
| **删除列** | 右键列头 | 删除当前列（受保护列不允许删除） |
| **重命名列** | 右键列头 | 修改列名称（受保护列不允许重命名） |
| **清空选中列** | 选中多列后右键 | 清空所有选中列的内容 |

### 2.4 选区操作

支持类似 Excel 的多种选区方式：

| 方式 | 操作 |
|------|------|
| **单选行** | 点击行号格 |
| **连续多选行** | 点击起始行 → 按住 `Shift` 点击结束行 |
| **离散多选行** | 按住 `Ctrl/Cmd` 逐一点击行号格 |
| **拖动选行** | 按住鼠标在行号格上拖动 |
| **单选列** | 点击列表头 |
| **连续多选列** | 点击起始列 → 按住 `Shift` 点击结束列 |
| **单元格矩形选区** | 点击起始单元格 → 按住 `Shift` 点击对角单元格，或直接拖动 |
| **全选** | 点击左上角 `#` 角格，或按 `Ctrl/Cmd + A` |

> 行选、列选、单元格选区互相排斥，同一时间只能激活一种。开启筛选时，选区只覆盖可见行，不会误选隐藏的数据。

### 2.5 列宽与行高

| 操作 | 方式 |
|------|------|
| **调整列宽** | 拖动列头右侧分割线（最小 40px） |
| **自动适配列宽** | 双击列头右侧分割线（自动根据内容调整，上限 600px） |
| **调整行高** | 拖动行号格下方分割线 |
| **自动适配行高** | 双击行号格下方分割线 |
| **恢复默认行高** | 双击行号格 |
| **展开/收起多行内容** | 双击行号格在默认高度和完整高度之间切换 |

## 三、资源管理器右键操作

插件在 VS Code 资源管理器中提供了丰富的右键菜单操作，无需打开文件即可快速创建新案例或测试要点，以及一键推送。

### 3.1 新增测试案例

在资源管理器中，右键 `测试任务/<任务名>/测试案例/` 目录或其子文件夹，菜单中会显示 **新增测试案例** 子菜单：

| 操作 | 说明 |
|------|------|
| ▸ **CSV (.csv)** | 基于模板创建标准 CSV 测试案例文件，自动包含表头和示例行 |
| ▸ **YAML (.yaml)** | 基于模板创建 YAML 测试案例文件，包含嵌套步骤明细结构 |

#### CSV 模板样例

创建后得到的 CSV 文件包含以下表头和一行示例数据：

| 表头列名 | 示例值 |
|----------|--------|
| `testcase_id` | 案例唯一标识，不可修改 |
| `路径` | 功能条目/测试要点/ |
| `名称` | 测试名称示例 |
| `案例描述` | 案例详细描述 |
| `前置条件` | 案例前置条件 |
| `步骤描述` | 步骤1：案例步骤1 → 步骤2：案例步骤2 → … |
| `预期结果` | 步骤1：【UI检查】UI检查点 → 步骤3：【接口调用】接口检查点 + 【数据检查】数据检查 |
| `案例类型` | 功能点类/流程类/界面类... |
| `优先级` | 高/中/低 |
| `执行方式` | 手工/自动化 |

> 示例行的 `testcase_id` 为占位文案「案例唯一标识，不可修改」，推送时该行会被自动过滤。

#### YAML 模板样例

创建后得到的 YAML 文件包含完整的嵌套结构，展示步骤明细各字段的填写格式：

```yaml
- testcase_id: 案例唯一标识，不可修改
  path: 功能条目/测试要点/
  name: 案例名称
  description: 案例描述
  preconditions:
    - 案例前置条件
  steps:
    - id: 1
      operation: 步骤名称1
      data:
        - 步骤数据1
        - 步骤数据2
      ui_expected:
        - UI检查点1
        - UI检查点2
      api_expected:
        - API检查点1
        - API检查点2
      db_expected:
        - 数据库检查点1
        - 数据库检查点2
    - id: 2
      operation: 步骤名称2
      data:
        - 步骤数据1
        - 步骤数据2
      ui_expected:
        - UI检查点1
        - UI检查点2
      api_expected:
        - API检查点1
      db_expected:
        - 数据库检查点1
        - 数据库检查点2
  tags: 案例标签
  type: 功能点类/流程类/界面类...
  test_type: 手工/自动化
  priority: 高/中/低
```

> YAML 模板中 `steps` 为数组，每个步骤包含 `operation`（步骤名称）、`data`（步骤数据）、`ui_expected`（UI检查）、`api_expected`（接口调用）、`db_expected`（数据检查）五个子字段，均为数组类型。表格编辑器中双击步骤明细列会打开独立弹窗进行编辑。

创建后，文件会自动用表格编辑器打开，表头已预设好，示例行为您展示填写格式。您可以修改示例行或删除后填入真实数据。

> 通过右键创建的案例文件会被标记为"插件创建"，后续推送时自动识别来源。

### 3.2 新增测试要点

在资源管理器中，右键 `测试任务/<任务名>/测试大纲/` 目录或其子文件夹，菜单中会显示 **新增测试要点**：

- 自动创建 `测试要点.md` 文件（已存在则递增编号：`测试要点1.md`、`测试要点2.md`……）
- 基于模板自动填充测试点表格结构
- 创建后文件名自动进入编辑状态，可直接修改
- 用 VS Code 文本编辑器打开

> 测试要点是 Markdown 格式文档，用于记录测试点清单，与测试案例（CSV/YAML）属于不同的工作流。

### 3.3 推送测试案例

在资源管理器中，右键 `测试任务/<任务名>/测试案例/` 目录下的 `.csv`、`.yaml`、`.yml`、`.json` 案例文件，菜单中会显示 **推送测试案例**：

- 系统自动打开文件并解析全部行数据
- 一次性提交整个文件的所有案例到后端
- 适用于全新文件的**首次全量提交**或**批量同步**

> 详细推送流程和结果说明请参见 [推送测试案例](#五推送测试案例) 章节。

## 四、查找、筛选与替换

### 4.1 搜索过滤

工具栏搜索框支持**实时关键词过滤**：输入任意文本，表格即时只显示匹配行（搜索范围为所有列）。按 `Enter` 立即触发，按 `Esc` 或点击 `✕` 清空搜索。

点击工具栏 **⟳ 重置按钮** 可一键清空搜索、筛选和查找面板，并重新加载文件最新内容。

### 4.2 数据状态筛选

工具栏提供五个**互斥**的快捷筛选按钮：

| 按钮 | 功能 | 何时可用 |
|------|------|----------|
| ⚠️ **仅看推送失败** | 只显示之前推送失败的行（红色底色） | 存在推送失败行时 |
| ✏️ **仅看已修改** | 只显示修改后尚未推送的行 | 存在本地修改时 |
| 🟢 **仅看新增** | 只显示通过插入行新增的数据 | 存在新增行时 |
| 🗑️ **仅看已删除** | 显示已删除的行（灰色条纹样式） | 存在删除操作时 |
| 🏷️ **仅看已标记** | 只显示手动标记颜色的行 | 存在标记行时 |

> 再次点击已激活的按钮或选择其他按钮可取消/切换筛选。

### 4.3 列筛选

每个列表头右侧有一个 **🔽 漏斗图标**，点击打开该列的筛选弹窗：

- 弹窗列出该列所有去重值及每项的行数
- 勾选需要保留的值 → 点击 **确定** 应用筛选
- 弹窗内可搜索值列表、全选/反选、或清除筛选
- 多个列的筛选条件会联动生效（某列弹窗中的计数已排除其他列筛选掉的行）
- 有筛选条件的列，漏斗图标变为**蓝色高亮**

> 编辑数据后，如果当前筛选条件不再匹配任何行，筛选会自动清除并给出提示。

### 4.4 查找与替换

通过 🔍 按钮或 `Ctrl/Cmd + F` 打开查找替换面板：

| 功能 | 操作 |
|------|------|
| **查找** | 输入关键词，匹配到的单元格黄色高亮，当前活动格更深色 |
| **导航匹配项** | 点击 ↑ 上一个 / ↓ 下一个 |
| **区分大小写** | 点击 **Aa** 开关 |
| **替换当前** | 点击 **替换**，替换当前匹配单元格的第一处匹配 |
| **全部替换** | 点击 **全部替换**，替换表格中所有匹配项 |

> 受保护列（如 ID 列）会被跳过，不会参与查找替换。

## 五、推送测试案例

推送是将编辑好的测试案例数据提交到后端系统的操作。

### 5.1 编辑器内推送

| 步骤 | 操作 |
|------|------|
| 1 | 在表格中选中需要推送的行（可多选） |
| 2 | 点击工具栏 **推送测试案例** 按钮，或右键 → **推送测试案例** |
| 3 | 按钮显示"推送中…"并置灰，防止重复点击 |
| 4 | 等待推送完成后查看结果弹窗 |

> 适合场景：修改部分案例后增量推送。如需全文件推送，可直接在资源管理器中右键文件选择"推送测试案例"（详见 [资源管理器右键操作](#三资源管理器右键操作)）。

#### 推送来源自动判定

推送时插件会自动判断案例来源，无需手动设置。判定规则：

- 如果是通过插件命令创建的案例文件 → 标记为"插件创建"
- 如果所选案例编号以 `TC` 开头 → 标记为"外部导入"
- 其他情况 → 默认标记为"插件创建"

#### 步骤描述格式化

推送时，案例中的**步骤描述**和**前置条件**如果包含多行文本，自动转换为 Web 页面可正确显示的格式，确保后端系统中多行内容排版正确。

### 5.2 推送结果

推送完成后弹出结果提示：

| 结果 | 提示样式 | 说明 |
|------|----------|------|
| ✅ **全部成功** | 绿色提示 | 所有选中行推送成功，自动消失 |
| ⚠️ **部分成功** | 橙色警告对话框 | 列出失败行明细，支持一键复制失败信息 |
| ❌ **全部失败** | 红色错误对话框 | 列出全部失败行，支持一键复制 |

- 失败行明细可点击行号快速跳转到对应位置
- 超过 50 条失败时，弹窗只显示前 50 条，完整明细输出到输出面板
- 网络异常时给出中文提示和排查建议

### 5.3 推送后的变化

| 变化 | 说明 |
|------|------|
| **编号回写** | 成功后后端返回的案例编号自动写入对应行，显示为绿色高亮 |
| **修改标记清除** | 推送成功的行，黄色修改高亮消失 |
| **新增标记清除** | 推送成功的新增行，绿色背景消失 |
| **失败行标记** | 推送失败的行显示红色底色，后续可通过"仅看推送失败"筛选定位 |
| **历史失败保留** | 之前的失败行标记保留，当前推送成功后清除该行的失败标记 |

## 六、数据状态标记

编辑器通过颜色标记直观展示每行数据的当前状态：

| 标记 | 视觉效果 | 含义 | 何时消失 |
|------|----------|------|----------|
| **已修改** | 单元格黄色背景 | 该单元格被编辑但尚未推送 | 推送成功 |
| **新增行** | 整行绿色背景 | 通过插入行添加的新数据 | 推送成功或删除 |
| **已删除** | 灰色条纹样式 | 被删除但变更未推送的行 | 推送成功或撤销 |
| **推送失败** | 整行红色底色 | 上次推送失败（包含失败时间） | 重新推送成功 |
| **编号回写** | 单元格绿色/橙色 | 推送后后端返回的编号 | 下次推送或刷新 |
| **手动标记** | 右键指定颜色标记 | 手动标记以便关注某些行 | 手动清除标记 |

> 推送失败状态和失败时间戳会**跨会话保留**，关闭 VS Code 后再打开仍能看到上次失败的行，便于继续修复。

> 背景色和字体色可**独立组合选择**，例如白色背景 + 红色文字，满足不同标注需求。同一单元格如被多次标记，**时间戳越新的标记优先级越高**。标记数据跨会话保留。

## 十、要点↔案例 绑定

**测试要点** (`.md` / `.xmind`) 与 **测试案例** (`.csv` / `.yaml` / `.yml` / `.json`) 之间可以建立**1:1**的绑定关系。绑定后：

- 双方任意一侧都可以一键跳转到已绑定的对端文件
- 已绑定文件在资源管理器中显示绿色 🔗 徽标，鼠标悬停显示对端文件名
- 文件重命名、移动、删除时，绑定关系自动同步维护，无需手动清理

> **1:1 语义**：同一时刻，一个测试要点只能绑定一个测试案例，反之亦然。已被绑定的文件在绑定弹窗中会显示为「已被绑定」的灰色状态，无法被其他文件抢占。

### 10.1 绑定测试案例（要点侧发起）

在资源管理器中，右键 `测试任务/<任务名>/测试大纲/` 目录下的 `.md` 或 `.xmind` 文件，菜单中会显示 **绑定测试案例**：

| 步骤 | 说明 |
|------|------|
| 1 | 弹出绑定弹窗，自动扫描同一测试任务下 `测试案例/` 目录中的所有 `.csv` / `.yaml` / `.yml` / `.json` 文件 |
| 2 | 已被其他要点绑定的案例文件会置灰并标注「已被绑定」，无法选择 |
| 3 | 若当前要点已经绑定过某个案例，该项会绿底加粗置顶，radio 默认勾选 |
| 4 | 单选一个候选文件（或不选表示解除绑定），点击 **保存绑定** 完成 |

#### 弹窗功能一览

| 元素 | 说明 |
|------|------|
| 🔍 **搜索框** | 按文件名或相对路径实时过滤 |
| 「隐藏已被占用」 | 默认勾选，隐藏被其他文件绑定的候选；当前源文件的已绑定项始终保留 |
| 「取消绑定」按钮 | 一键清空当前选择（相当于选择"不绑定"） |
| **↗ 定位** | 点击候选行右侧的 ↗ 图标，在资源管理器中定位该文件 |
| 「解除绑定」按钮 | 顶部横条已绑定项旁的按钮，快速清空当前绑定 |
| 「保存绑定」按钮 | 文案根据当前状态自动切换：`保存绑定` / `修改绑定` / `解除绑定`；无变化时禁用 |
| **× 关闭** | 弹窗右上角或按 `Esc` 关闭 |

### 10.2 绑定测试要点（案例侧发起）

在资源管理器中，右键 `测试任务/<任务名>/测试案例/` 目录下的 `.csv`、`.yaml`、`.yml`、`.json` 文件，菜单中会显示 **绑定测试要点**。

- 弹窗自动扫描同一测试任务下 `测试大纲/` 目录中的所有 `.md` / `.xmind` 文件
- 交互与弹窗功能与 **10.1 绑定测试案例** 完全一致（方向相反）
- 若目标要点已被其他案例绑定，该项显示为「已被绑定」灰色状态

### 10.3 一键跳转对端文件

对**已经建立绑定**的文件，右键菜单额外提供跳转命令：

| 源文件位置 | 命令 | 效果 |
|-----------|------|------|
| 测试大纲 `.md` / `.xmind` | **跳转到已绑定的测试案例** | 打开对应案例文件并在资源管理器中定位 |
| 测试案例 `.csv/.yaml/.json` | **跳转到已绑定的测试要点** | 打开对应要点文件并在资源管理器中定位 |

- 若当前文件**尚未建立绑定**，命令会弹出提示，可选择 **立即绑定** 直接进入绑定弹窗
- 若绑定的对端文件**已被删除**（且未被同步清理），会给出警告提示，避免用户困惑

### 10.4 文件级绑定徽标

已建立绑定的文件在资源管理器中会显示 **绿色 🔗 徽标**，与"已绑定任务"文件夹的蓝色 🔗 徽标做视觉区分：

| 徽标颜色 | 含义 | 位置 |
|---------|------|------|
| 🔗 蓝色 | 该文件夹已绑定为测试任务的根目录 | 任务文件夹 |
| 🔗 绿色 | 该文件已建立 要点↔案例 绑定关系 | 具体文件 (`.md/.xmind/.csv/.yaml/.json`) |

- **鼠标悬停徽标** 会显示对端文件的名字，例如：`已绑定测试案例：login_case1.yaml`
- 徽标由高性能 O(1) 缓存驱动，5 秒 TTL，大工作区也不卡顿
- 绑定关系文件变更后自动刷新，无需手动刷新资源管理器

### 10.5 绑定关系总览面板

VS Code 侧边栏「资源管理器」底部设有 **要点⇄案例 绑定** 面板，集中展示当前工作区所有绑定关系：

| 功能 | 说明 |
|------|------|
| **两级树形结构** | 顶级显示测试要点（`.md` / `.xmind`），二级展开为该要点绑定的测试案例 |
| **点击定位** | 单击任一节点，自动在资源管理器中展开并定位该文件 |
| **空态提示** | 没有任何绑定关系时显示提示语，引导用户去右键菜单创建绑定 |
| **自动刷新** | 绑定文件变更后（保存、外部改动、rename/delete 同步）面板自动刷新 |

### 10.6 重命名 / 删除 自动同步

插件持续监听工作区文件系统事件，绑定关系会自动维护：

| 事件 | 自动行为 |
|------|---------|
| 重命名/移动**测试要点**文件 | 绑定库中对应的 `point` 路径同步更新为新路径 |
| 重命名/移动**测试案例**文件 | 绑定库中对应的 `cases` 路径同步更新 |
| **删除测试要点**文件 | 绑定库中该要点及其对应的绑定记录整体清理 |
| **删除测试案例**文件 | 绑定库中该案例从 `cases` 数组中剔除；若剔除后 `cases` 为空，整条记录一并删除 |

> 所有同步操作均带有**乐观锁**：若在写入瞬间发现文件被其他进程/窗口改动过，会自动重试一次，避免多窗口冲突覆盖。

### 10.7 绑定关系存储与团队共享

绑定关系存储在工作区根目录下的：

```
.plugin/.tms/point-case-bindings.json
```

文件内容为标准 JSON，结构清晰、跨平台兼容（路径统一使用 POSIX 相对路径）：

```json
{
  "version": 1,
  "bindings": [
    {
      "point": "测试任务/登录模块/测试大纲/登录用例.md",
      "cases": ["测试任务/登录模块/测试案例/login_case1.yaml"],
      "updatedAt": 1732000000000
    }
  ]
}
```

#### Git 策略建议

| 场景 | 建议 |
|------|------|
| 团队协作、绑定关系需**共享给其他成员** | ✅ 将 `.plugin/.tms/point-case-bindings.json` **提交到 Git 仓库** |
| 仅个人本地使用、绑定关系是个人偏好 | 将 `.plugin/.tms/` 加入 `.gitignore` |

> 该文件是纯文本 JSON，多人协作时的合并冲突通常可以手动解决。也可以直接删除后重新绑定。

#### 调试日志开关

如需排查绑定问题，可在 VS Code 设置中开启：

- 设置项：`testcaseViewer.debug.pointCaseBinding`
- 默认值：`false`（关闭）
- 开启后，绑定弹窗的诊断日志会输出到 **开发者控制台**（`帮助 → 切换开发人员工具`）

## 十三、重要规则说明

### 文件存放要求

案例文件必须位于工作区内的以下目录结构中：

```
测试任务/<任务名称>/测试案例/<任意子目录>/xxx.csv
测试任务/<任务名称>/测试案例/<任意子目录>/xxx.yaml
测试任务/<任务名称>/测试案例/<任意子目录>/xxx.json
```

不符合此目录结构的文件，插件功能（如推送）可能受限或不可用。

### 格式支持

- **CSV**：标准 CSV 格式，支持多行文本字段（换行内容以双引号包裹）
- **YAML / YML**：支持嵌套步骤明细和复杂结构
- **JSON**：支持嵌套结构

### 受保护列

以下列受到保护，禁止编辑、删除或重命名：
- **案例唯一标识**（系统自动生成，`MA` 开头的标识符或 `TC` 开头的导入编号）
- **后台配置的其他受保护列**（如关键业务字段）

> 受保护列在表格中显示为灰色底色，尝试编辑时会给出提示。

### 未绑定任务不可推送

文件必须先绑定到有效的测试任务，才能使用推送功能。未绑定时表头显示"未绑定任务"，推送按钮不可用。

### 撤消与重做

- 支持最多 **100 步**撤消历史
- 涵盖编辑、插入、删除、粘贴、标记等所有操作
- 切换 Tab 后撤消历史独立保留

### 状态持久化

以下状态会按文件路径隔离保存，切换 Tab 后再切回自动恢复：
- 列宽设置
- 行高设置
- 单行展开/收起状态
- 列筛选条件
- 搜索关键词
- 滚动位置
- 推送失败行记录（跨会话保留）

### 表头中英映射

当数据文件使用英文列名时，插件可自动将表头显示为中文，方便阅读和编辑。反过来，当数据文件使用中文表头时，推送时会自动还原为英文字段名，确保后端正常解析。

#### 配置方式

推荐使用**命令面板一键完成**：

| 方式 | 操作 | 效果 |
|------|------|------|
| **推荐：命令直达** | `Cmd/Ctrl + Shift + P` → 输入「**配置表头中英映射**」并回车 | ⚡ 自动打开 `.plugin/.tms/headerLabels.json`：文件不存在则自动创建并写入内置默认映射模板，文件存在则直接打开 |
| 设置面板 | `文件 → 首选项 → 设置`（`Cmd/Ctrl + ,`），搜索 `testcaseViewer` | 在设置 UI 中逐项编辑，可切换「用户」/「工作区」Tab 控制作用范围 |

#### 自定义映射

如需覆盖内置映射或添加新字段，在 VS Code 设置中修改对应配置项即可。配置可写入以下两个位置的 `settings.json` 文件：

| 范围 | 配置文件路径 | 适用场景 |
|------|-------------|----------|
| **工作区设置** | 工作区根目录下 `.plugin/.tms/headerLabels.json` | 仅对当前工作区生效，适合团队统一配置 |
| **用户设置** | VS Code 用户配置目录下的 `settings.json` | 对所有工作区生效，适合个人偏好 |

> 通过 VS Code 设置面板（`Cmd/Ctrl + ,`）修改时，可在「用户」和「工作区」Tab 之间切换，VS Code 会自动写入对应的 `settings.json` 文件。

**示例：新增英文列 `owner` 的中文显示（仅对当前工作区生效）**

1. 在工程根目录创建或打开 `.plugin/.tms/headerLabels.json`
2. 添加以下内容：

```json
{
  "owner": "负责人"
}
```

已有映射不会被清除，新加的和内置的映射会自动合并。

#### 优先级规则

| 优先级（高 → 低） | 配置文件 | 说明 |
|-------------------|----------|------|
| 工作区设置 | `.plugin/.tms/headerLabels.json` | 作用于当前工作区，最高优先级 |
| 用户设置 | 用户全局 `settings.json` | 作用于所有工作区的个人偏好 |
| 插件内置默认值 | `package.json` | 通用默认映射，最低优先级 |

> 同名 key 在高优先级中会自动覆盖低优先级。例如 `.plugin/.tms/headerLabels.json` 中设置了 `"testcase_id": "用例ID"`，则该工作区中 `testcase_id` 列显示「用例ID」而非内置默认的「案例唯一标识」。

### 清理文件高亮

当需要清除编辑器中的所有数据标记（如修改高亮、推送失败标记、手动标记等）时，可使用清理命令：

| 方式 | 操作 |
|------|------|
| **命令面板** | `Cmd/Ctrl + Shift + P` → 输入「**清理文件高亮**」并回车 |

该命令一次性清除以下**五类**数据：

| 清除项 | 说明 |
|--------|------|
| 编辑变更高亮 | 所有单元格的黄色"已修改"标记 |
| 推送失败记录 | 红色底色 + 失败时间戳 |
| 快照基线 | 用于对比"已修改"状态的原始数据快照 |
| 删除行追踪 | "仅看已删除"筛选中的幽灵行 |
| 手动标记 | 所有右键设置的背景色/字体色标记 |

> 适合场景：确认数据无误后做一次全面清理，或将文件移交他人时清空个人标记。清理操作**不可撤销**，请确认后使用。

### 文件外部修改与重载

插件时刻监控案例文件的变更，确保编辑器中始终显示最新数据：

| 触发方式 | 说明 |
|----------|------|
| **外部编辑器修改** | 用其他程序编辑并保存案例文件后，插件在 150ms 内自动检测并重载 |
| **VS Code 文本编辑器保存** | 在文本编辑器模式下修改并保存后，切回表格编辑器自动同步 |
| **Tab 切回** | 从其他 Tab 切回案例文件时，自动重新解析并刷新数据 |
| **手动重置** | 点击工具栏 ⟳ 重置按钮，强制重载 |

**智能防干扰机制：**
- 插件**自己保存**的文件变更在 3 秒内不会被重复重载，避免"保存 → 检测变更 → 再次重载"的死循环
- 短时间内多次外部变更被合并处理（150ms 防抖），避免频繁刷新

### 不合格文件的降级处理

如果案例文件不在合规目录结构下（即不满足 `测试任务/<任务名>/测试案例/` 路径规则）：

| 行为 | 说明 |
|------|------|
| **编辑器降级** | 文件仍可通过右键"用测试案例编辑器打开"查看，但表格编辑器顶部显示错误提示 |
| **功能限制** | 推送、在线查询、任务绑定等依赖后端的功能**不可用** |
| **文本编辑器回退** | 错误页提供「用文本编辑器打开」按钮，方便直接查看原始内容 |

> 如需完整使用插件功能，请将文件移动至合规目录路径下。
