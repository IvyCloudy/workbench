# 案例编辑器增强功能需求文档

> 文档视角：业务 / 用户（测试人员、案例编辑者、测试负责人）
> 适用范围：表格编辑器中的「测试案例」文件，覆盖新行结构化编辑、步骤对象解析与展示、内容标记与过滤、字段保护（配置化删除/重命名）、表头中英文映射等编辑器增强能力
> 说明：本文档描述「用户需要什么能力、业务规则与验收标准」，不涉及前端/后端具体实现方式。
> 章节约定：每个功能模块均按「需求背景与目标」「交互与功能规则」两部分展开。

---

## 1. 总体背景与目标

测试案例在表格编辑器中以行列形式维护，每一列可能是普通文本、可多选的标签集合（数组），或一个结构化的对象（如一条测试步骤）。日常编辑中存在以下业务痛点：

- **新行录入门槛高**：插入行时，对象 / 数组类型的列若让用户手填原始 JSON 极易出错，需要引导式弹窗。
- **步骤对象晦涩**：`steps` 列往往是结构化的步骤对象，编辑器应结构化展示，推送时也要按对象语义正确下发，而非当作一段文本。
- **临时标记与聚焦**：编辑过程中用户希望对某些单元格 / 行做临时标记（如"待确认""重点关注"）以便复查，并能一键只看这些标记行；标记不能污染真实数据。
- **字段保护诉求**：不同测试任务对字段有保护要求（某些列不可删除 / 重命名），应可配置，而非写死。
- **表头可读且可控**：表头既要中文友好，又要保真底层英文字段；且业务团队应能自行定义每一列显示什么中文名，不局限于系统预置。

总体目标：降低结构化数据录入门槛、保证对象语义一致、提供轻量标记与聚焦能力、配置化字段约束、表头中英文映射（系统 + 用户双可配）。

---

## 2. 术语与前提

| 术语 | 业务含义 |
|------|----------|
| 明细列 | 主表中某一列，其值对应一组结构化内容（单个对象，或一组步骤对象），需通过弹窗编辑 |
| 标签集合列（数组列） | 一列可填多个值的字段（如多个前置条件），主表以标签形式展示，双击进入多项编辑 |
| 嵌套对象 | 整行对应一个对象（如一条结构化步骤），而非步骤列表 |
| 步骤列表 | 整行对应一组步骤对象；每个步骤含操作、数据、各类预期结果等字段 |
| 冻结列 / 受保护列 | 系统强制不可变动的列（如 `testcase_id`），以及业务配置为不可删除/重命名的列 |
| 中文映射 | 「英文字段名 → 中文显示名」的对照表，仅用于表头与弹窗展示，不写回数据文件 |
| 反向映射 | 「中文显示名 → 英文字段名」的对照表，用于中文表头文件推送时还原为英文 |

---

## 3. 功能需求

### 3.1 新插入行的对象 / 数组弹窗编辑

#### 需求背景与目标
插入新行时，对象 / 数组类型的列若让用户手填原始 JSON 极易出错，且易与相邻行数据混淆。本功能目标是：为结构化列自动预置可编辑占位，并以"继承上一行结构"的引导式弹窗降低录入门槛，保证录入形态正确、保存安全。

#### 交互与功能规则
- **自动占位**：用户插入新行（右键「插入行」、批量插入、行复制等）时，若涉及明细列或标签集合列，系统自动为该列预置结构化占位（空对象 / 空数组），并提供正确的编辑入口，而非留下空白或纯文本；同时记录该列的"结构类型"（对象 / 数组），确保后续弹窗按正确形态打开、保存时不被误判为相邻行数据。
- **弹窗继承上一行结构**：点击该列单元格打开编辑弹窗，弹窗结构应与**上一行同列**一致——上一行是单个对象则按该对象字段骨架呈现（单条、不提供"新增步骤"）；上一行是步骤列表则按步骤列表呈现，支持步骤的新增 / 复制 / 删除 / 上下移动。字段集合应覆盖该对象已有字段、案例通用字段、步骤必备字段（操作、数据、各类预期结果），与上一行对齐。
- **分类型编辑形态**：文本字段用普通输入框；数组字段（如多个预期结果）每项独立编辑、可增删 / 展开；对象字段提供 JSON 编辑，支持一键格式化与语法高亮预览（key、字符串、数字、布尔/null 以不同颜色区分）。
- **回填、校验与取消**：确认后结构化内容写回单元格并在主表按既有方式呈现；支持取消（Esc / 点遮罩），取消则不写回任何改动。数字类字段实时校验：输入非法数字即时提示，保存拦截并指明是第几项不合法。
- **空结构兜底**：若新行对象尚无任何字段，弹窗自动按字段骨架补出一条空结构（数组置空数组、对象置空对象、其余置空文本）并标记为可保存，确保用户总能进入编辑而非卡死。

---

### 3.2 步骤对象内容的展示与推送解析

#### 需求背景与目标
`steps` 列往往是结构化的步骤对象，若当作一段文本维护，既不便于阅读也易被推送环节误处理（丢失嵌套层级）。本功能目标是：主表结构化展示步骤对象，并在推送时按对象语义正确还原下发，保证前后端语义一致。

#### 交互与功能规则
- **结构化展示**：主表中步骤类列以可点击入口呈现；点击后弹窗左侧为步骤列表（优先显示"操作"，其次名称 / 编号，副标题展示步骤标识），右侧为当前步骤的字段编辑区，区分文本 / 数组 / 对象三类，数组项可独立编辑、对象支持 JSON 编辑与高亮。弹窗标题显示该列中文名（若已配置映射）、英文字段名、所在行号，便于定位。
- **推送正确解析**：推送阶段，步骤对象内容必须被**正确还原为对象结构**后传给后端，而非当作字符串或丢失嵌套层级；嵌套的子对象、子数组均保持原结构下发，保证后端按对象语义消费。
- **空 / 非法对象处理**：步骤对象为空占位时视为可编辑占位，不报错；若内容为非合法结构，推送阶段给出明确提示（如"步骤内容非合法对象"），不静默以错误结构下发。保存文件时，明确为空的字段（空文本 / 空数组）不写回，避免冗余空字段。

### 3.3 表格内容标记、取消标记与标记过滤

#### 需求背景与目标
编辑过程中用户希望对某些单元格 / 行做临时标记（如"待确认""重点关注"）以便复查，并能一键只看这些标记行聚焦问题；标记必须是纯视觉的，不能污染真实数据与推送。本功能目标是：提供灵活的标记 / 取消标记能力（支持颜色区分），并提供"仅看已标记行"的过滤聚焦能力。

#### 交互与功能规则
- **标记范围与触发**：支持对**单元格**与**整行**标记——选中整行即整行标记；框选一片单元格按行展开标记；右键单个单元格单格标记。在搜索 / 列筛选 / 仅看失败等过滤视图下，标记只作用于**当前可见行**，避免隐藏行被误标记。
- **颜色选择**：点击「标记」弹出颜色选择器，提供背景色与字体色两套调色板并实时预览；确认后标记以彩色高亮呈现。
- **取消标记**：选中已标记区域执行「取消标记」，系统按"逐格减法"精确剔除落在选区内的标记，未被覆盖的部分保留。
- **标记状态属性**：标记为纯视觉状态，**不修改单元格实际数据值、不参与推送、不影响导出**；标记 / 取消均支持撤销恢复；标记状态可持久化（跨刷新保留），具体保留策略由配置决定。
- **仅看已标记行（标记过滤）**：工具栏提供「仅看已标记行」开关，开启后表格只显示被标记的行（整行标记或其中任一单元格被标记均计入）；该过滤与其余过滤（仅看失败 / 修改 / 新增 / 删除）互斥，开启一种即关闭其它，保证视图单一聚焦。
- **过滤按钮状态联动**：当前无任何标记行时，按钮置灰不可点并提示"暂无已标记行"；存在标记时按钮显示当前标记行数；开启过滤后高亮并提示"再次点击退出"；若标记被全部清除而正处于过滤态，自动退出过滤、恢复全部行。
- **与搜索 / 列筛选叠加**：「仅看已标记行」可与关键字搜索、列筛选**叠加**使用，最终只显示"既被标记、又命中搜索 / 列筛"的行。
- **过滤态操作边界**：在过滤视图中执行标记 / 取消标记仍只作用于当前可见行，避免隐藏行被误标记；推送流程若需跳转到某失败行而正处于任意过滤态，应自动退出全部过滤并提示用户，以保证定位准确。

### 3.4 配置化限制字段调整（删除 / 重命名）

#### 需求背景与目标
不同测试任务对字段有不同保护要求（某些列不可删除 / 重命名），写死会导致灵活性不足。本功能目标是：将字段保护由配置驱动，既能兜底系统级关键列（如 `testcase_id`），又能让业务按需声明受保护列，删除 / 重命名约束即时生效。

#### 交互与功能规则
- **删除限制（冻结兜底 + 配置化）**：列删除前双重保护——① 冻结列（如 `testcase_id`）禁止删除，提示冻结列不可删除（删除会破坏推送语义与失败标记联动）；② 受保护列（业务必备列，由配置清单声明）禁止删除，提示该列受保护不可删除。正常右键菜单对受保护列直接隐藏删除入口，运行时校验为二次防御。
- **重命名限制（冻结兜底 + 配置化）**：列重命名前同样校验冻结列与受保护列，分别提示不可重命名；重命名后若与已有列重名给出提醒（可能影响字段定位），但仅冻结列强制收紧；若被改名的列关联有明细结构，其关联应同步跟随改名，避免弹窗 / 粘贴 / 渲染失效。
- **配置来源与即时生效**：受保护字段清单由配置驱动（非硬编码），便于不同测试任务 / 模板差异化约束；配置变更后，编辑器即时按新约束调整列操作可用性（菜单项显隐 + 运行时校验），无需重建文件。

### 3.5 表头中英文映射（系统预置 + 用户自定义双通道）

#### 需求背景与目标
表头既要中文友好又要保真底层英文 key；且业务团队应能自行定义每一列显示什么中文名，而非局限于系统预置。核心诉求是：映射可多层叠加、团队可自行配置并随仓库分发，展示层友好，底层始终以英文 key 通信；当中文库头文件推送时也能正确还原为英文 key。

#### 交互与功能规则
- **多层来源与合并优先级（从低到高）**：
  1. **系统内置默认**：开箱即用的常见字段中文名（如 `testcase_id → 案例唯一标识`）。
  2. **用户个人设置**：对当前用户全局生效。
  3. **工作区设置**：对当前项目/工作区生效，覆盖用户个人同名字段。
  4. **工作区映射文件（最高优先级）**：项目内映射配置文件（平铺的"英文字段: 中文名"），适合团队共享、随仓库分发，强制覆盖前三层。
  - 未配置且不在内置默认中的字段：表头只显示英文 key，不影响功能；多个来源配置同一字段时按上述优先级覆盖。
- **用户自行配置（两种入口）**：
  - **入口一 · 命令生成/编辑映射文件**：提供命令一键打开或生成项目内的映射配置文件；文件不存在时自动生成带模板的配置文件并打开，用户按"英文字段: 中文名"增改即可。
  - **入口二 · 设置界面编辑**：在编辑器设置中直接编辑映射项（用户级 / 工作区级均可），无需接触配置文件。
  - 两种方式最终汇入同一份合并结果，编辑器一致对待。
- **映射驱动展示**：表头有映射时第一行显示中文名、其下显示英文 key，悬浮提示"中文（英文key）"；无映射时仅显示英文 key。弹窗字段名同理：有映射显示"中文（主）+ 英文 key（辅）"，无映射仅英文 key。
- **映射热更新**：用户修改映射配置或映射文件后，表头应**实时刷新**为新中文名，无需关闭重开文件。
- **底层始终以英文 key 通信**：无论表头展示中文还是英文，推送 / 导出 / 接口调用一律以**英文 key** 为准，用户无需关心底层字段拼写，中文仅为展示层。
- **反向映射与中文表头推送还原**：当案例文件本身是中文表头（首行是中文列名）时，推送前需把中文列名还原为英文 key，否则后端按英文契约解析会全部为空。系统应自动完成还原（标准中文模板表头按语义映射，其余自定义中文名按"中文名 → 英文字段"的反向映射还原）。反向映射同样可配置（多层合并）；**若用户自定义了某中文名，应同步配置其反向映射**，否则该列推送时无法还原、字段丢失——系统应在用户漏配时给出提示。
- **可配置扩展与团队共享**：新增字段无需改代码即可经配置获得中文展示；团队可将映射配置文件纳入版本管理，随仓库分发统一的中文表头规范，个人设置用于本地补充 / 覆盖。

## 4. 用户操作流程

### 4.1 新行结构化编辑
1. 在案例编辑器插入一行（右键「插入行」/ 批量插入）。
2. 对象 / 数组列已自动预置空结构占位，点击单元格打开结构化弹窗。
3. 弹窗按上一行同列结构呈现（单对象 / 多步骤），逐字段填写。
4. 对象字段可格式化 JSON 并切换语法高亮；数字字段非法时即时提示。
5. 点击「保存」写回并刷新主表；「取消 / Esc」丢弃本次修改。

### 4.2 步骤对象处理
1. 编辑步骤列为对象内容，主表以可点击入口展示。
2. 点击打开弹窗：左侧步骤列表，右侧字段编辑区（文本 / 数组 / 对象三类）。
3. 点击推送，步骤对象被正确解析为对象结构下发后端，嵌套层级完整；非法结构有明确提示。

### 4.3 标记 / 取消标记与标记过滤
1. 选中单元格或整行，右键「标记」→ 选背景色 / 字体色 → 确认。
2. 标记以彩色高亮呈现，不改动数据；可撤销。
3. 复查完毕，选中标记区域右键「取消标记」，按需精确剔除。
4. 点击工具栏「仅看已标记行」，表格只显示被标记的行；按钮显示当前标记行数，再次点击退出。无标记时按钮置灰。
5. 「仅看已标记行」可与搜索框、列筛选叠加，只展示"既标记又命中"的行；开启时自动关闭其它过滤。

### 4.4 字段保护
1. 打开受配置保护的案例文件，受保护列右键菜单无删除 / 重命名项。
2. 若通过其它途径触发，运行时拦截并提示受配置保护。
3. 配置变更后，约束即时生效。

### 4.5 表头中文映射（含用户自定义）
1. **查看**：表头按合并后的映射显示中文名（如「案例唯一标识」），其下显示英文 key（`testcase_id`）。
2. **系统预置**：常见字段开箱即有中文名，无需配置。
3. **自定义（文件）**：执行命令打开/生成项目映射配置文件，按"英文字段: 中文名"增改；若文件本身为中文表头，还需配置反向映射（中文名: 英文字段）。
4. **自定义（设置）**：在设置界面直接编辑映射项，即时生效。
5. **热更新**：保存后表头立即刷新，无需重开文件。
6. **推送无感**：推送 / 导出后台自动以英文 key 通信，中文表头文件自动还原为英文 key 下发。

## 5. 异常与边界

| 场景 | 期望行为 |
|------|----------|
| 插入行上一行同列无结构（纯文本） | 新行该列按普通文本录入，不弹窗 |
| 新行对象字段骨架为空 | 弹窗自动补空结构并标记可保存，用户可编辑 |
| 弹窗内填写非法 JSON | 格式化 / 保存时提示，不写回错误结构 |
| 数字字段含非法值 | 输入即时提示，保存拦截并指明第几项 |
| 过滤视图下执行标记 | 仅标记可见行，隐藏行不被误标 |
| 取消标记选区与已有标记部分重叠 | 精确剔除重叠部分，未覆盖部分保留 |
| 点击「仅看已标记行」但当前无标记 | 按钮置灰不可点，提示"暂无已标记行" |
| 标记被全部清除时正处于过滤态 | 自动退出过滤，恢复全部行 |
| 仅看已标记 + 搜索 / 列筛选叠加 | 显示"被标记且命中"的交集行 |
| 推送定位失败行时处于过滤态 | 自动退出全部过滤并提示，保证准确定位 |
| 尝试删除冻结列 | 提示冻结列不可删除并阻断 |
| 尝试重命名受保护列 | 提示受保护列不可重命名并阻断；关联结构同步改名 |
| 表头无对应中文映射 | 回退显示英文 key，不影响功能 |
| 步骤对象为空占位 | 视为可编辑占位，不报错；推送按空对象下发 |
| 自定义中文名但漏配反向映射 | 中文表头文件推送时该列无法还原、字段丢失（应提示补全反向映射） |
| 映射配置文件格式非法 | 静默降级为空映射，编辑器正常打开，不阻断 |
| 多个来源配置同一字段中文名 | 按"项目文件 > 工作区 > 个人 > 系统默认"优先级覆盖 |
| 修改映射文件后未手动刷新 | 表头实时自动刷新 |

## 6. 验收标准

1. **新行结构化编辑**：插入含对象 / 数组列的新行时自动预置空结构占位并记录结构类型；点击打开结构化弹窗，弹窗结构（单对象 / 多步骤、字段顺序）与上一行一致；对象字段支持 JSON 格式化与语法高亮；数字字段非法即时提示、保存拦截；取消不写回。
2. **步骤对象处理**：步骤对象在主表以可点击入口展示，弹窗内左侧步骤列表 + 右侧三类字段编辑；推送时按对象 / 对象数组结构正确解析下发，嵌套层级完整；非法 / 空字段按规则处理，空字段不写回。
3. **标记与标记过滤**：支持单元格 / 整行标记与取消标记，颜色可选，过滤视图下仅标记可见行；标记持久化、可撤销、不污染数据与推送；「仅看已标记行」可按标记过滤（含行与单元格标记），无标记时禁用、有标记时显示计数，与搜索 / 列筛选可叠加，与其它过滤互斥；推送定位失败时自动退出过滤态。
4. **字段保护**：冻结列与配置化受保护列的删除 / 重命名被禁用并提示；菜单隐藏入口 + 运行时双重校验；关联结构跟随重命名；保护清单配置驱动、即时生效。
5. **表头中英文映射**：
   - 系统默认中文名开箱即用；团队可通过**项目映射文件**或**设置界面**两种方式自定义中文名；
   - 多层来源按"项目文件 > 工作区 > 个人 > 系统默认"优先级合并；
   - 修改后表头实时热更新；
   - 推送 / 导出一律以英文 key 通信；中文表头文件经反向映射自动还原为英文 key 下发；漏配反向映射时提示补全；
   - 映射文件非法时静默降级，不阻断编辑器；
   - 新字段无需改代码即可经配置获得中文展示。
