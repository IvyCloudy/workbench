# 新增测试案例功能说明

## 功能概述

采用**真正的 VS Code "New File" 交互方式**，提供最原生、最流畅的测试案例创建体验。

## 文件标识特性

### 如何识别通过命令创建的文件？

通过"新增测试案例"命令创建的文件，会被记录到工作区下的 **`.vscode/testcase-viewer/created-files.json`**，用于标识文件的创建方式和时间。

> 该方案不会修改 YAML/JSON/CSV 文件本身的内容，避免干扰解析逻辑。

#### 记录文件结构

位置：`<workspaceRoot>/.vscode/testcase-viewer/created-files.json`

```json
{
  "/abs/path/to/.../测试案例/登录功能测试.yaml": {
    "createdAt": "2026-06-13T14:44:22.123Z",
    "version": "1.0"
  }
}
```

#### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| 顶层 key | 文件绝对路径 | `/.../测试案例/xxx.yaml` |
| `createdAt` | 创建时间（ISO 8601） | `2026-06-13T14:44:22.123Z` |
| `version` | 模板版本 | `1.0` |

#### 识别方法

**程序检测（推荐）**：使用工具模块 [fileIdentifier.ts](/Users/myronliu/IdeaProjects/yyy/workbench/src/utils/fileIdentifier.ts) 提供的 API：

```typescript
import { isCreatedByCommand, getFileCreationInfo } from './utils/fileIdentifier';

if (isCreatedByCommand(filePath)) {
    const info = getFileCreationInfo(filePath); // { createdAt, version }
}
```

#### 自动同步

- 文件**重命名**：记录中的路径自动更新到新路径
- 文件**删除**：对应记录自动清理
- 提供 `cleanupRecords()` 用于一次性清理已不存在的文件记录

#### 优势

- ✅ **零侵入**：不修改 YAML 内容，不影响解析与对比
- ✅ **兼容性好**：避免前置元数据带来的解析与同步问题
- ✅ **可追溯**：记录创建时间和模板版本
- ✅ **可扩展**：JSON 结构便于增加更多元数据字段

#### 注意事项

- ⚠️ 该 JSON 文件位于 `.vscode/` 下，建议纳入项目共享或按需添加到 `.gitignore`
- ⚠️ 手动复制/移动文件**不会**自动产生记录
- ⚠️ 删除记录文件不影响 YAML 数据，仅会丢失"通过命令创建"的标识信息

## 核心特性

### ✨ 真正的 New File 风格

本功能完全模拟 VS Code 原生的 "New File" 交互：

1. **右键点击** → 自动创建默认文件
2. **资源管理器中 inline 编辑** → 文件名处于编辑状态
3. **直接输入新名称** → 按回车确认
4. **自动用插件编辑器打开** → 进入表格编辑模式

### 🎯 与 VS Code New File 的对比

| 特性 | VS Code New File | 新增测试案例 |
|------|------------------|--------------|
| **触发方式** | 资源管理器右键 / 命令面板 | ✅ 相同 |
| **文件创建** | 先创建默认名文件 | ✅ 相同 |
| **文件名编辑** | 资源管理器中 inline 编辑 | ✅ 相同 |
| **编辑器打开** | 用默认编辑器打开 | ✅ 用插件编辑器打开 |
| **模板支持** | 无 | ✅ 有（基于模板） |
| **多格式支持** | 任意格式 | ✅ YAML/JSON/CSV |

## 使用方式

### 方法一：资源管理器右键（推荐）

支持在以下任意位置右键触发"新增测试案例"菜单：

| 右键位置 | 是否支持 | 新文件创建位置 |
|---|---|---|
| `测试任务/<任务名>/测试案例` 文件夹本身 | ✅ | 直接在该目录下 |
| `测试案例/` 下任意子文件夹 | ✅ | 在该子文件夹下 |
| `测试案例/` 下已有的 `.yaml` / `.yml` / `.json` / `.csv` 文件 | ✅ | 与该文件同目录 |

步骤：

1. **右键点击** 上述任一位置
2. 选择 **新增测试案例**
3. **自动创建** `未命名测试案例.yaml`（同名时自动递增）
4. **文件名自动进入编辑模式**（inline 编辑）
5. **直接输入新名称**，按回车确认
6. **自动用插件编辑器打开**（表格视图）

### 示例
```
步骤：
1. 右键点击"测试案例"文件夹（或其下子文件夹/已有案例文件）
2. 文件 "未命名测试案例.yaml" 被创建并选中
3. 文件名处于编辑状态，直接输入 "登录功能测试"
4. 按回车确认
5. 文件自动用表格编辑器打开
```

### 方法二：命令面板

1. 按 `Ctrl+Shift+P`（Mac: `Cmd+Shift+P`）
2. 输入 "新增测试案例"
3. 按照相同流程创建（需当前活动文件位于测试案例目录下）

## 常见问题

### Q: 看不到"新增测试案例"菜单？
确保右键位置满足以下任一条件：
- 路径以 `测试任务/<任务名>/测试案例` 结尾（即"测试案例"文件夹本身）
- 路径位于 `测试任务/<任务名>/测试案例/` 之下（子文件夹或案例文件）

### Q: 如何创建不同格式？
在重命名时修改扩展名，如：`测试案例.json`

### Q: 创建失败？
检查：文件名是否合法、文件是否已存在、是否在正确目录。

### Q: 为什么用插件编辑器打开？
插件编辑器提供表格视图，更适合编辑测试案例。

### Q: `.vscode/testcase-viewer/created-files.json` 可以删除吗？
可以。删除后只会丢失"通过命令创建"的标识信息，不会影响 YAML 数据本身和编辑器使用。
