## 一、功能概述

「案例推送」是将本地 CSV / YAML / JSON 格式的测试案例文件**推送到测试任务管理系统**的功能。推送成功后，系统返回的 `testCaseNo`（案例编号）会**自动回写**到原文件的对应行。

**核心能力：**
- 支持两种入口：**编辑器内推送**（可选行）和**资源管理器右键推送**（整文件）
- 每行案例有唯一的 `tsId` 标识，推送结果可精准匹配回写
- 推送前强制校验任务绑定状态，未绑定拒绝推送
- 推送结果按成功/失败分类展示，失败行高亮标记

## 二、文件要求

### 2.1 目录结构要求（强约束）

测试案例文件必须放在以下目录结构中：

```
<项目根目录>/
└── 测试任务/
    └── <任务编号>_<子任务名称>/            ← 示例: TT_2024_0001_测试任务1
        └── 测试案例/
            └── .../<文件名>.csv            ← 支持 .csv / .yaml / .yml / .json
```

> ⚠️ **不在此目录结构下的文件，推送功能不可用。**

### 2.2 支持的格式

| 格式 | 扩展名 |
|------|-------|
| CSV | `.csv` |
| YAML | `.yaml` / `.yml` |
| JSON | `.json` |

### 2.3 文件自动生成的追踪列

每次打开文件时，插件会自动为每一行生成两个追踪列，**不可手动编辑**：

| 列名 | 说明 |
|------|------|
| `tsId` | 每行唯一标识（自动生成），推送匹配用 |
| `testCaseNo` | 案例编号，推送成功后自动填入 |

## 三、操作方式

### 方式一：编辑器内推送（推荐）

适用场景：需要**选择性推送**部分案例行。

#### 操作步骤

1. **打开文件**  
   在 VS Code 中双击测试案例文件，默认以表格编辑器打开。

2. **选取要推送的行**  
   - 点击**行号格**选中单行
   - `Shift + 点击` 扩展选区多行
   - `Ctrl/Cmd + 点击` 离散多选
   - 点击左上角 **`#`** 格全选可见行
   - 搭配「查找 / 筛选」功能先过滤目标行，再全选

3. **确认选区**  
   表格顶部会实时显示 `已选中 X 行`。

4. **点击「推送」按钮**  
   位于编辑器顶部工具栏。

5. **等待推送完成**  
   按钮变为 loading 状态，请勿重复点击。

6. **查看推送结果**  
   结果自动以弹窗或通知展示（详见「五、结果解读」）。

#### 界面示意

```
┌──────────────────────────────────────────────┐
│  已绑定任务: TT_2024_0001 · 测试任务1         │
│  已选中 3 行          [推送]  [仅看失败行]      │
├──────────────────────────────────────────────┤
│ # │ tsId       │ testCaseNo │ 案例名称      │
│ ☑ │ uuid-xxx   │            │ 登录测试      │
│ ☑ │ uuid-yyy   │ TC_001     │ 搜索测试  ← 已推送（有编号）
│ ☐ │ uuid-zzz   │            │ 支付测试      │
└──────────────────────────────────────────────┘
```

---

### 方式二：资源管理器右键推送

适用场景：**快速推送整个文件**，无需打开编辑器。

#### 操作步骤

1. 在 VS Code 左侧**资源管理器**中定位到测试案例文件
2. 右键点击文件，选择 **「推送测试案例」**
3. 推送结果自动展示

#### 右键菜单示意

```
资源管理器
├── 测试任务/
│   └── TT001_测试任务1/
│       └── 测试案例/
│           └── login_case.csv  ──右键──→ 推送测试案例 ✅
└── 其他目录/
    └── some_file.csv           ──右键──→ （无推送菜单） ❌
```

> ⚠️ **只有合规目录下的文件**才会显示右键推送菜单。

## 四、推送流程

```
① 选取行 / 右键文件
        ↓
② 校验任务绑定（未绑定 → 拒绝推送并提示）
        ↓
③ 解析文件数据
        ↓
④ 推送至系统
        ↓
⑤ 推送成功 → 自动回写 testCaseNo 到文件
   推送失败 → 不修改文件
        ↓
⑥ 展示推送结果（弹窗 / Toast 通知）
```

## 五、结果解读与处理

### 5.1 全部成功 ✅

| 展示形式 | 行为 |
|---------|------|
| 右下角 Toast 通知 | 显示「推送成功：N 条」，自动消失 |

文件中的 `testCaseNo` 列已自动填充案例编号。

### 5.2 部分成功 ⚠️

| 展示形式 | 行为 |
|---------|------|
| 警告弹窗 | 显示成功/失败统计 + 失败明细列表 |

**弹窗功能：**
- 成功 / 失败 数量统计
- 失败案例列表（含失败原因）
- 点击行号可**跳转到对应行**
- 「复制失败明细」按钮，一键复制到剪贴板

**后续操作：**
- 失败行在表格中**红色高亮**标记
- 可使用「仅看失败行」按钮快速筛选失败案例
- 修正后**仅勾选失败行再次推送**

### 5.3 全部失败 ❌

| 展示形式 | 行为 |
|---------|------|
| 错误弹窗 | 显示所有失败明细 |

> 全部失败时**不会修改原文件**，`testCaseNo` 列保持不变。

### 5.4 失败数量较多（> 50 条）

弹窗仅展示前 50 条失败明细，完整列表输出到「测试案例推送」输出面板。

**查看输出面板：**  
VS Code 菜单 → 查看 → 输出 → 下拉选择 **"测试案例推送"**

## 六、常见问题

### Q1：推送按钮或右键菜单不显示？

| 可能原因 | 解决方法 |
|---------|---------|
| 文件不在合规目录 | 将文件放入 `测试任务/xxx/测试案例/` 路径下 |
| 文件格式不支持 | 仅支持 `.csv` / `.yaml` / `.yml` / `.json` |
| 文件未绑定任务 | 联系管理员在任务绑定配置中添加该任务 |
| 非表格编辑器打开 | 右键文件 → 打开方式 → 选择 TestCase Viewer |

### Q2：推送提示"任务未绑定"？

说明该文件所在的任务目录尚未在系统中完成绑定。需要联系项目管理员，在任务绑定配置中补充该任务的绑定信息。绑定信息通常包括任务编号、子任务名称、阶段 ID 等。

### Q3：推送后文件中的 testCaseNo 没有更新？

| 可能原因 | 解决方法 |
|---------|---------|
| 全部推送失败 | 查看弹窗中的失败明细，修正后重新推送 |
| 文件被外部程序占用 | 关闭其他程序后重新打开文件 |
| 推送时网络异常 | 检查网络连接后重试 |

### Q4：如何查看推送日志？

- 方式一：VS Code → 查看 → 输出 → 选择 **"测试案例推送"** 频道
- 方式二：推送结果弹窗中查看失败明细

### Q5：推送出问题时如何开启详细诊断日志？

当推送出现难以定位的问题（如"某些行为何被判失败"、"接口返回是否被正确解析"、"拆批分流是否符合预期"等）时，可临时开启 **推送链路诊断日志**，观察 `runPush` 各阶段（入口、预校验、样例过滤、分批、映射、请求、响应解析、汇总、异常）的详细数据。

**开启方式**（三选一）：

| 方式 | 操作 |
|------|------|
| ⭐ 设置 UI（推荐） | `Cmd/Ctrl + ,` → 搜索 `testcaseViewer debug push` → 勾选复选框 |
| 用户级 settings.json | `Cmd/Ctrl + Shift + P` → `Preferences: Open User Settings (JSON)` → 加入 `"testcaseViewer.debug.push": true` |
| 工作区级 settings.json | 在项目根目录创建 `.vscode/settings.json` 并加入同一行（仅对当前项目生效） |

**查看日志**：
- VS Code → 查看 → 输出 → 下拉选择 **"TestCase 推送诊断"** 频道
- 开启后触发一次推送，该频道会自动弹出并追加带时间戳的详细日志

**特性**：
- **默认关闭**，关闭状态下**零运行开销**（不做序列化、不写 console、不创建输出频道）
- **配置热切换**，改动 `settings.json` 后**无需重启** VS Code，下一次推送即生效
- 排查完毕请**关闭开关**，避免日志噪声

> 💡 该日志与「测试案例推送」频道各自独立：前者用于**开发排查**（完整链路观测），后者用于**用户查看推送结果**（成功/失败明细）。

## 七、操作建议

### 推送前
- 使用**查找/筛选**功能检查数据完整性，确保必填字段无遗漏
- 大量数据建议**分批推送**，先试推几行确认无误后再全量推送
- 推送前确保文件已**保存**最新内容

### 推送中
- 保持文件编辑器打开，不要关闭 Tab
- 避免在推送过程中修改文件内容

### 推送后
- 检查 `testCaseNo` 列是否已正确填入
- 使用「仅看失败行」查看并处理失败案例
- 失败行高亮会**累积**，直到该行推送成功后才自动清除

## 九、推送来源平台判定（sourcePlatform）

推送时，每行案例会被自动判定 `sourcePlatform`（案例来源平台）并写入请求体。该字段决定后端按哪种来源通道处理案例，**无需用户手动填写**，由插件按以下规则自动分流：

| 优先级 | 条件 | sourcePlatform | 说明 |
|--------|------|----------------|------|
| 1 | 文件由插件"新增测试案例"命令创建 | `testAgentMA` | 命令创建的文件带装饰标记，强制走 MA 通道 |
| 2 | 所选案例中存在以 `TC` 开头的 `testcase_id` | `testAgent` | 识别为既有存量案例 |
| 3 | 其他情况（默认） | `testAgentMA` | 含 `MA`+hex、`MA`+标准 UUID 等新增标识 |

**分流特性：**
- 一次推送中**不同行可走不同通道**：插件按 `sourcePlatform` 自动**拆批**，同通道的行归为一批请求。
- 判定逻辑封装在公共方法 `getPushSource(filePath, rows)` 中，编辑器内推送与资源管理器右键推送共用同一规则，结果一致。
- 若后端返回"无效的案例来源 / 当前不支持案例来源"等错误，均指向 `sourcePlatform` 字段，可参考第六章 Q5 开启诊断日志排查。

## 十、步骤换行格式化与字段拼接规则

推送结构化文件（YAML / JSON）时，步骤（`steps`）会被转换为接口所需的 `description` 与预期值字段。转换规则如下：

### 10.1 换行符转换（nl2br）

所有文本字段中的真实换行符 `\n` 在推送时统一转换为 HTML 换行标签 `<br>`，以保证后端 Web 页面正确呈现多行内容：

| 字段 | 转换规则 |
|------|----------|
| 案例描述（description 顶层） | `\n` → `<br>` |
| 前置条件（preconditions） | `\n` → `<br>` |
| 步骤描述（每个 step 的 operation + data） | `\n` → `<br>` |
| 预期值（expected） | `\n` → `<br>` |

### 10.2 步骤 → description 拼接

每个步骤按固定模板拼为一段 `description`：

```
步骤名称(operation) + <br> + 数据(data，多项以 <br> 连接)
```

- **operation 必填**：若某步骤缺失 `operation`（步骤名称），推送前会**拦截并明确报错**（指出第几个步骤缺操作步骤），不会提交脏数据。
- **data 为空时**：仅推送 `operation` 内容，不拼接 `<br>`。
- 多个步骤各自生成一段 `description`，与步骤**一一对应**。

### 10.3 预期值序号化

预期值（`ui_expected` / `api_expected` / `db_expected`）为数组时，推送前会为**每项自动添加序号**（从 1 开始），数组内多项以换行分隔，便于后端按序展示断言点。

> 以上转换均在推送映射层（`pushDataMapper`）完成，**不修改本地源文件**，仅作用于推送给后端的数据。

## 十一、展开步骤与推送的关系

编辑器支持将"步骤"列**原地展开为内联子表格**（见《测试案例编辑器操作文档》第二十一章），该能力与推送完全兼容：

- **共享数据源**：展开子表格与弹窗编辑器读写同一份 `steps` 源数据，无论哪种方式修改，推送时都基于最新内容。
- **列名对应**：展开子表格中"步骤名称"列即 yaml 的 `operation` 字段，是推送必填项（见 10.2）。
- **展开态不影响推送**：推送时直接读取文件/内存中的 `steps` 结构，与界面是否处于展开态无关。
- **仅结构化文件**：展开步骤仅对 YAML / JSON 生效；CSV 的步骤列只是合并文本，推送按合并文本解析，无嵌套展开。

## 十二、快捷操作速查

| 操作 | 方式 |

| 推送选中行 | 表格编辑器顶部「推送」按钮 |

| 查看推送日志 | VS Code 输出面板 → 选择 "测试案例推送" |
| 开启诊断日志 | 设置搜索 `testcaseViewer debug push` → 勾选 → 输出面板选择 "TestCase 推送诊断" |
