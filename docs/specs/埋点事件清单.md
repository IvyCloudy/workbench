# 埋点事件清单

> 对接 API：
> ```ts
> sendTelemetryEvent(eventName: string, props?: StringGenerateProperties)         // 普通事件
> sendTelemetryErrorEvent(eventName: string, props?: StringGenerateProperties)     // 错误/异常事件（业务可预期错误、接口失败、未捕获异常等统一入口）
> ```
> `StringGenerateProperties = { [key: string]: string }`，所有 prop 值均为 `string`。
>
> 源码位置：`src/utils/telemetry.ts`  ·  `stackHead()` 由 `src/services/utils.ts` 提供。

#### 4.1 推送结果字段字典（`*.complete` / `*.aborted` / `*.failed` 共享）

**行计数字段**

| 字段 | 类型 | 语义 | 计算口径 |
|---|---|---|---|
| `totalRows` | string(number) | 文件解析出的**原始总行数** | 包含标题行以下所有数据行（含样例、含被过滤的） |
| `successRows` | string(number) | 接口返回成功的行数 | 后端 `SUC0000` 且行内无 `errorMsg` |
| `failedRows` | string(number) | 最终失败行数（含预校验 + 接口） | `preValidationFailedRows` + 接口返回失败行 |
| `preValidationFailedRows` | string(number) | **本地预校验**拦截的行数 | 未真正调用后端接口的部分。占比越高说明本地兜底越有效 |
| `costMs` | string(number) | 端到端耗时（毫秒） | 从 `pushStart` 到 `.complete` 触发；含接口调用+回写+快照 |

**分类维度**（沿用）

| 字段 | 类型 | 语义 | 示例值 |
|---|---|---|---|
| `failCategoryBreakdown` | string | 按**错误短码**聚合的分布串 | `"fieldMissing:42,duplicate:8,network:2"` |
| `topFailCategory` | string | 上表 count 排名 top1 的短码 | `"fieldMissing"` |

> `category` 枚举（详见 [pushFailureCategory.ts](../../src/utils/pushFailureCategory.ts) 的 `classifyFailure`）：`placeholder`（占位 testcase_id）/ `emptyTestcaseId`（空 testcase_id）/ `sample`（样例占位）/ `mapError`（客户端字段映射失败兜底；已知字段/性质的映射错误优先拆为 `${field}.${nature}` 复合码，如 `sourceId.empty`/`description.empty`/`expected.empty`/`testCasePath.format`）/ `network`（网络/超时）/ `auth`（鉴权/权限/无权限）/ `yamlSyntax`（YAML 语法/解析错误，文件级前置拦截，早于 runPush）/ 字段级复合码 `${field}.${nature}`（如 `testCaseName.empty`/`testCasePath.empty`/`sourceId.dup`/`type.enum`，nature∈empty/length/format/enum/dup；取不到字段时落 `fieldEmpty`/`fieldLength`/`fieldFormat`/`enumInvalid`/`fieldDup`）/ `checkpointZero`（检查点数为0）/ `stepMismatch`（步骤与预期数量不一致）/ `taskStageMissing`（测试任务编号未匹配阶段信息）/ `fieldInvalid`（字段类兜底）/ `notFound`（其他不存在/未找到兜底）/ `taskNotFound`（任务不存在/未绑定，如任务下未绑定）/ `testPointMissing`（任务下未匹配到有效测试要点）/ `pathNotMatchPoint`（案例路径错误未匹配到有效测试要点）/ `serverError`（服务端 5xx）/ `sourceNotSupported`（案例来源不被支持/无效，如无效的案例来源、当前不支持案例来源）/ `bizReject`（其他业务拒绝兜底）/ `unknown`（无法归类兜底）。

**字段维度（兼容口径，全字段合并）**

| 字段 | 类型 | 语义 | 示例值 |
|---|---|---|---|
| `failFieldBreakdown` | string | **不区分层级**的全字段错误分布串 | `"designer:100,description:42,expected:30"` |
| `topFailField` | string | 上表 count 排名 top1 的字段名 | `"designer"` |

> ⚠️ **已知陷阱**：接口级公共参数错误（如 `designer` 无权限）会让**整批 N 行**都被记为 `designer` 失败，从而在合并串里以 `N` 的计数**淹没**行级字段的真实分布。这个维度**保留仅为不打断存量看板**，新分析请改用下面的分层维度。

**字段维度（分层口径 🆕，推荐）**

| 字段 | 类型 | 语义 | 示例值 |
|---|---|---|---|
| `interfaceFailBreakdown` | string | **接口级公共参数**错误分布串 | `"designer:100,artifactId:5"` |
| `topInterfaceFailField` | string | 接口级 top1 字段名（无接口级错误时为 `""`） | `"designer"` |
| `caseFailBreakdown` | string | **caseList 行级字段**错误分布串 | `"description:42,expected:30,sourceId:8"` |
| `topCaseFailField` | string | 行级 top1 字段名（无行级错误时为 `""`） | `"description"` |

> **接口级字段（5 个）** = 请求体顶层 / header 公共参数，1 次错通常导致整批 N 行全失败：
>
> | 字段码 | 语义 | 后端错误示例 |
> |---|---|---|
> | `testTaskNo` | 测试任务编号（顶层，必填） | "测试任务编号...不能为空" / "未匹配到有效阶段信息" |
> | `subTestTaskId` | 子任务 Id（顶层，必填） | "子任务Id 不能为空" |
> | `artifactId` | 产出物 Id（顶层，必填，≤500 字符） | "产出物Id不能为空" / "长度不能超过500个字符" |
> | `sourcePlatform` | 案例来源平台（顶层，枚举） | "无效的案例来源(TMS/RFWeb/...)" / "当前不支持案例来源(testAgent/...)" |
> | `designer` | 设计人（header，必填，≤200 字符） | "设计人不能为空" / "设计人无权限" / "长度不能超过200个字符" |

> **行级字段（13 个）** = caseList[] 数组元素字段，每行独立失败：
>
> | 字段码 | 语义 | 常见后端报错 |
> |---|---|---|
> | `sourceId` | 案例唯一标识 / testcase_id（必填，≤36） | "案例来源Id 不能为空" / "sourceId 已存在" / "案例已存在请勿重复添加" |
> | `testCasePath` | 案例路径（必填，≤1500，须 `/` 结尾） | "案例路径不能为空" / "路径格式不正确必须以/结尾" / "案例路径错误未匹配到有效测试要点" |
> | `testCaseName` | 案例名称（必填，≤250） | "案例名称不能为空" / "案例名称长度不能超过250个字符" |
> | `testCaseDes` | 案例描述 | — |
> | `description` | 步骤描述（必填，与预期数量一致） | "步骤描述不能为空" / "步骤描述与预期结果数量不一致" |
> | `expected` | 预期结果（必填，≤8000） | "预期结果不能为空" / "案例检查点数为0请查看预期结果检查分类" |
> | `priority` | 优先级（低/中/高） | "数据中包含无效的案例优先级" |
> | `type` | 案例类型（界面类/流程类/...） | "数据中包含无效的案例类型" |
> | `preCondition` | 前置条件（≤5000） | "前置条件长度不能超过5000个字符" |
> | `keyFlag` | 关键案例（是/否，必填） | "关键案例不能为空" / "关键案例格式不正确请填写是或否" |
> | `projectDes` | 项目说明 | — |
> | `planExecNum` | 计划执行次数 | — |
> | `testType` | 默认执行方式（自动化/半自动化/手工） | "数据中包含无效的案例默认执行方式" |

> **📊 计数口径说明**（避免误读）：
>
> - 每个 breakdown 都是**按后端返回的失败条目**逐条聚合，接口级错误目前是**按被影响行数计数**（不是「1 次事故=1」）：一批 100 行因 `designer` 无权限全失败，`interfaceFailBreakdown` 记为 `designer:100`，与 `failedRows≈totalRows` 相印证。
> - 所以判断「接口级连坐」的标志是：`topInterfaceFailField != ""` **且** `failedRows` 接近 `totalRows`。
> - 判断「哪个字段问题最多」时**分开看** `topInterfaceFailField`（配置/权限问题）与 `topCaseFailField`（数据质量问题），避免混为一谈。
> - 别名匹配规则（后端中文报错 → 字段码）见 [pushFailureCategory.ts](../../src/utils/pushFailureCategory.ts) 的 `INTERFACE_FIELD_ALIASES`；契约测试见 [pushCore-telemetry-contract.test.ts](../../src/test/pushCore-telemetry-contract.test.ts)。

### 5.1 多文件批量推送（`explorerPush.batch.*`）

右键在资源管理器批量推送 N 个文件时触发，与 §5 的单文件事件**并行发送**（外层批次事件 + 内层每个文件仍走 §5 的 `explorerPush.complete/aborted/failed`）。batch 事件**只做文件/批次维度聚合**，不重复统计行级/字段级失败——想看"哪个字段错最多"需下钻到单文件事件。

| 功能模块 | eventName | 描述 | 类型 | props | 全路径 |
|----------|-----------|------|------|-------|--------|
| 批量 | `explorerPush.batch.start` | 🆕 批次启动 | info | `fileCount`, `extBreakdown` | `pushHandler.ts:handleBatchPush()` |
| 批量 | `explorerPush.batch.fileResult` | 🆕 单文件推送完成摘要 | info | `ext`, `resultType`, `succ`, `fail`, `total`, `failCategoryBreakdown?`, `topFailCategory?`, `failFieldBreakdown?`, `topFailField?`, `interfaceFailBreakdown?`, `topInterfaceFailField?`, `caseFailBreakdown?`, `topCaseFailField?` | `pushHandler.ts:handleBatchPush()` |
| 批量 | `explorerPush.batch.cancelled` | 🆕 用户中途取消批次 | info | `fileCount`, `completed`, `remaining`, `durationMs` | `pushHandler.ts:handleBatchPush()` |
| 批量 | `explorerPush.batch.postRefresh` | 🆕 批次结束统一刷新已打开的 webview 面板 | info | `refreshed`, `total` | `pushHandler.ts:handleBatchPush()` |
| 批量 | `explorerPush.batch.openFile` | 🆕 从总结面板点开文件 | info | `ext`, `hasError` | `pushHandler.ts:handleBatchPush() → progressPanel.done` |
| 批量 | `explorerPush.batch.done` | 🆕 批次汇总 | info | `fileCount`, `totalSucc`, `totalFail`, `errorFiles`, `cancelled`, `durationMs`, `extBreakdown`, `failCategoryBreakdown?`, `topFailCategory?`, `failFieldBreakdown?`, `topFailField?`, `interfaceFailBreakdown?`, `topInterfaceFailField?`, `caseFailBreakdown?`, `topCaseFailField?`, `taskNotFoundSamples?`, `testPointMissingSamples?`, `pathNotMatchPointSamples?`, `sourceNotSupportedSamples?`, `unknownSamples?` | `pushHandler.ts:handleBatchPush()` |

> **字段语义**：
>
> - `fileCount`：本次批量选中的文件数
> - `extBreakdown`：文件类型分布，形如 `"csv:3,yaml:2"`（`batch.start` 按输入分布 / `batch.done` 按已处理结果分布）
> - `resultType`（`batch.fileResult`）：`success`（全成功）/ `partialFail`（部分行失败）/ `error`（整个文件推送异常）
> - `succ` / `fail` / `total`（`batch.fileResult`）：本文件行级统计
> - `completed` / `remaining`（`batch.cancelled`）：取消时已完成 / 剩余文件数
> - `refreshed` / `total`（`batch.postRefresh`）：实际刷新的 webview 面板数 / 结果集总数（只刷新已打开的面板，是性能优化点，未打开的文件靠 `pushFailureStore.json` 持久化恢复）
> - `hasError`（`batch.openFile`）：`"1"`=点的失败文件 / `"0"`=点的成功文件
> - `cancelled`（`batch.done`）：`"1"`=批次被取消 / `"0"`=正常完结
> - `totalSucc` / `totalFail`（`batch.done`）：所有文件行级成功/失败合计
> - `errorFiles`（`batch.done`）：`resultType='error'` 的文件数（整文件挂）
> - `durationMs`：从 `batch.start` 到当前事件的耗时（毫秒）
