## 1. 总体架构

案例编辑器基于 VS Code `CustomEditorProvider` 构建，整体分三层：

- **扩展端（Node/ts，src/）**：文件解析、推送、持久化、配置监听、消息分发。
- **WebView 前端（media/pages/table-editor/editor/*.js）**：表格渲染、选区、右键菜单、弹窗、标记着色、列操作等纯前端交互。
- **通信桥**：前端通过 `postMessage` 发送 `init / save / pushTestCase / mark / setMarkRects / openTextEditor` 等消息；扩展端经 `dispatchEditorMessage`（`src/handlers/editorMessageHandlers.ts`）表驱动分发。

关键类与入口：

| 职责 | 模块 |
|------|------|
| 自定义编辑器框架、会话生命周期 | `src/providers/BaseEditorProvider.ts` |
| 推送主流程（含回写、高亮刷新） | `src/handlers/pushCore.ts` + `PushViaHttpClient`（`BaseEditorProvider.ts`） |
| 数据帧组装与下推 | `src/services/webviewDataPusher.ts` |
| 标记持久化 | `src/utils/markStore.ts` |
| 表头中英映射 | `src/utils/headerLabels.ts` |
| 编辑后高亮持久化 | `src/utils/highlightStore.ts` |
| 前端主表渲染/选区 | `02a-render.js` / `02c-row-cell-sel.js` / `02d-sel-utils.js` |
| 前端标记 | `03e-mark.js` |
| 前端列操作 | `03f-col-ops.js` |
| 前端明细弹窗 | `03c-detail-modal.js` / `03d-detail-write.js` / `05c/05d` |
| 前端明细辅助 | `03h-detail-helpers.js` |
| 前端行操作 | `03d-row-ops.js` |

前端脚本按职能拆分为约 20 个文件，加载顺序固定（`BaseEditorProvider.buildEditorHtml` 中 `editorScriptFiles` 数组）；因函数声明在每个 `<script>` 内部独立提升（不跨脚本），顺序不可随意调整。

## 2. 功能详细设计

### 2.1 新插入行的对象 / 数组弹窗编辑

#### 需求要点
插入新行时，对象 / 数组类型的列自动预置结构化占位（空对象 / 空数组）并记录结构类型，避免用户手填 JSON 出错、避免保存时误判为相邻行数据；点击单元格以"继承上一行结构"的引导式弹窗编辑。

#### 涉及模块与文件
- 前端：`03d-row-ops.js`（`insertRow` / `copyRowInline` / `copySelectedRows`）、`03h-detail-helpers.js`（`_inferDetailColKind` / `_writeDetailCellFromRaw`）、`03c-detail-modal.js` / `03d-detail-write.js`（弹窗编辑）。
- 扩展端：解析器在 `parse` 阶段产出 `detailTables`（见 2.2）。

#### 核心数据结构
- `S.data.detailTables`：数组，每个元素是某明细列的元数据：
  ```ts
  {
    field: string;          // 对应主表列名
    headers: string[];      // 该明细表字段
    rowGroups: string[][];  // 显示文本二维结构
    rawRowGroups: any[][];  // 真实对象/对象数组结构（按行）
    rawRowTypes: ('array'|'object'|'none')[]; // 每行列级类型
  }
  ```
- 主表 `S.data.rows[ri][ci]` 仅存显示文本（如 `[2 项]` / `{4 字段}`），真实结构在 `rawRowGroups`。

#### 关键流程
1. **插入空占位（insertRow）**：
   - 新行自动生成 `testcase_id`（UUID），`testCaseNo` 置空（由推送响应回写）。
   - 遍历所有明细表 `idts`，在插入位置 `splice(at, 0, [])` 向 `rowGroups / rawRowGroups / rawRowTypes` 插入空条目，保持与主表行数一致。
   - **关键**：`rawRowTypes[at]` 写入 `_inferDetailColKind(dt)` 推断出的列级类型（`'array'`/`'object'`），而非 `'none'`。这保证：① 保存路径识别为"空对象/空数组"而不是回退到 `originalData[rowIdx]`，避免相邻行数据被错复制；② 弹窗按对应类型展示（嵌套对象 / 步骤列表）。
2. **打开弹窗（点击明细列单元格）**：`03c-detail-modal.js` 依据该行 `rawRowTypes` 决定呈现"单对象骨架"或"步骤列表（支持新增/复制/删除/上下移动）"，字段集合覆盖已有字段 + 通用字段 + 步骤必备字段（操作、数据、各类预期结果），与上一行对齐。
3. **分类型编辑**：文本用输入框；数组项独立增删/展开；对象字段提供 JSON 编辑 + 语法高亮（key / 字符串 / 数字 / 布尔 / null 配色）。
4. **写回（_writeDetailCellFromRaw）**：将编辑结果规范化写入 `rawRowGroups`，同步 `rowGroups` 显示文本与 `rawRowTypes`，并刷新主表显示文本（`[N 项]`/`{N 字段}`），同时标记 `S.mods` / `S._detailModCellKeys`。
5. **回填校验与取消**：数字字段实时校验，非法即时提示、保存拦截并指明第几项；取消（Esc / 点遮罩）不调用写回。
6. **空结构兜底**：若新行对象无字段，弹窗按字段骨架补一条空结构（数组置 `[]`、对象置 `{}`、其余置空文本）并标记可保存。

#### 边界与防御
- 复制行同样重新生成 `testcase_id`、清空 `testCaseNo`，并同步 `rawRowTypes` 源类型，避免 id 冲突或结构错位。
- 批量插入用 `S._insertRowSkipSideEffects` 标记跳过内部 `pushHistory`/`saveFile`，最后统一执行，避免 N 次撤销栈膨胀。
- 行结构变化后清除单元格矩形选区（`S.cellSel = null`），防止索引错位。

### 2.2 步骤对象内容的展示与推送解析

#### 需求要点
`steps` 等步骤类列结构化展示；推送时按对象语义正确还原下发（嵌套层级完整），不丢结构、不当字符串；空/非法对象有对应处理。

#### 涉及模块与文件
- 解析端：`src/parsers/yaml-parser.ts`、`json-parser.ts`（产出 `detailTables`）。
- 前端：`03h-detail-helpers.js`（`_readDetailCellRaw` / `_writeDetailCellFromRaw`）、`03c/03d` 弹窗、`04-push-find.js`、`05c/05d`。
- 推送端：`BaseEditorProvider.rebuildPushDataFromDisk` + `src/handlers/pushCore.ts`。

#### 核心数据结构
读取真实结构：`_readDetailCellRaw(ri, ci)`：
- 取 `getDetailTableByCol(ci)` 得到该列明细表；
- 若 `rawRowTypes[ri] === 'object'` 返回单个对象（或 null），否则返回 `rawRowGroups[ri]` 的浅拷贝数组；
- 主表单元仅存显示文本，真实结构恒在 `rawRowGroups`。

#### 关键流程
1. **结构化展示**：主表步骤列以可点击 chip（`[N 项]`/`{N 字段}`）呈现；点击打开弹窗——左侧步骤列表（优先显示"操作"，其次名称/编号，副标题显示步骤标识），右侧三类字段编辑区（文本/数组/对象）。弹窗标题显示中文名（如已映射）+ 英文字段名 + 行号。
2. **推送正确解析（rebuildPushDataFromDisk）**：
   - 推送前重新 `parser.parse(filePath)` 取 `sourceData`，建立 `testcase_id → 源记录` 的 Map（**浅拷贝入 Map**，防止 `pushCore.stampRowIndex` 原地写 `__rowIndex` 污染 parser 内部）；
   - 前端选中的行按 `testcase_id` 匹配并用**文件源数据**替换显示文本，确保推送的是原始对象结构而非 `[2 项]` 之类显示文本；
   - 解析失败回退到前端提交数据（并发送埋点），保证流程仍可推进。
3. **空 / 非法对象处理**：
   - 空占位视为可编辑占位不报错；
   - 内容非合法结构时，推送阶段给出明确提示（如"步骤内容非合法对象"），不静默以错误结构下发；
   - 保存时明确为空的字段（`''`/`[]`）不写回，避免冗余空字段。

#### 边界与防御
- 源记录必须浅拷贝后入 Map（否则未来 parser 加缓存会污染内部结构，见 `BaseEditorProvider.ts` 注释）。
- 嵌套子对象/子数组在 `rawRowGroups` 中保持原结构，序列化（parser.save）经 `reconstructDetail` 还原，推送数组下标→行号映射（`pushIndexToRow`）兜底首推行号错位。

### 2.3 表格内容标记、取消标记与标记过滤

#### 需求要点
支持单元格/整行标记（颜色可选），纯视觉、不污染数据、可持久化、可撤销；"仅看已标记行"过滤，与其它过滤互斥、可与搜索/列筛叠加。

#### 涉及模块与文件
- 前端：`03e-mark.js`（`collectMarkRects` / `countMarkedInRects` / `markSelected` / `unmarkSelected` / `applyMarkWithColors` / 颜色选择器）。
- 扩展端持久化：`src/utils/markStore.ts`（`MarkRect[]` 存于 `globalStorageUri/marked-cells.json`）。

#### 核心数据结构
`MarkRect`（扩展端 `markStore.ts`）：
```ts
interface MarkRect {
  r1: number; c1: number;  // -1 表示整行（忽略列维度）
  r2: number; c2: number;
  bgColor?: string;        // 背景色，如 "#e3f2fd"
  fontColor?: string;      // 字体色，如 "#d32f2f"
  timestamp?: number;      // 叠加时最近操作优先
}
```
前端内存态 `S._userMarks = { rects, cellMap?, rowMap?, rowSet?, cellTime?, rowTime? }`，用于 O(1) 查询 `isUserMarked(r,c)`。

#### 关键流程
1. **标记范围与触发（collectMarkRects）**：
   - 行选 → 每行一个 `c1=-1` 整行矩形；
   - 单元格矩形选区 → 用 `getSelRectRows()` 取**过滤后可见行号**，逐行下发，避免隐藏行被误标记；
   - 单格右键 → 单格矩形。
2. **颜色选择（showMarkColorPicker）**：背景色 6×10 调色板 + 字体色 3×10 调色板，实时预览；确认调用 `applyMarkWithColors`，经 `S.vscode.postMessage({type:'mark', rects, bgColor, fontColor})` 持久化并 `renderTable()`。标记/取消均先 `pushHistory()` 纳入撤销栈。
3. **取消标记（unmarkSelected）**：
   - 展开选区为 `r:c` 集合；遍历已存储矩形，逐格判断是否落在选区内，未覆盖的单元格重聚合成水平连续段矩形写入 `newRects`（cell-by-cell 减法）；
   - 结果为空则提示"选区内无标记"；否则更新 `S._userMarks.rects` 并 `postMessage({type:'setMarkRects', rects})` 持久化。
4. **仅看已标记行（过滤）**：工具栏开关，开启后只显示整行标记或任一单元格被标记的行；与"仅看失败/修改/新增/删除"互斥（开启一种即关其它）；可与关键字搜索、列筛选叠加（取交集）。无标记时按钮置灰并提示"暂无已标记行"；处于过滤态时显示计数，再点退出；标记全清且正处过滤态则自动退出恢复全部行。
5. **过滤态操作边界**：过滤视图下标记/取消只作用于当前可见行；推送定位失败行时若处于任意过滤态，自动退出全部过滤并提示，保证定位准确。

#### 边界与防御
- 标记文件不存在时自动创建空 `{}`；格式异常降级为空对象，不阻断编辑器。
- `cleanupOrphanedMarks()` 异步清理已删除文件的孤儿记录（用 `fs.promises.access` 替代同步 `existsSync`，避免大文件阻塞事件循环）。
- 标记状态跨刷新保留（`marked-cells.json`），与推送高亮（`highlightStore`）物理隔离，互不影响。

### 2.4 配置化限制字段调整（删除 / 重命名）

#### 需求要点
冻结列（`testcase_id`）+ 业务受保护列（配置清单）禁止删除/重命名；菜单隐藏入口 + 运行时双重校验；关联明细结构同步跟随改名；保护清单配置驱动、即时生效。

#### 涉及模块与文件
- 前端：`03b-resize-colsel.js`（`isFrozenCol` / `isProtectedCol`）、`03f-col-ops.js`（`deleteCol` / `renameCol`）、`03c-col-ops` 右键菜单构造。
- 配置常量：`PROTECTED_COLS`（`03b-resize-colsel.js` 顶部「配置常量」区）。

#### 核心数据结构
```js
// 受保护列名清单（英文字段名，与 headers 一致）
var PROTECTED_COLS = [
  'testcase_id', 'testCaseNo', 'path', 'name',
  'preconditions', 'description', 'priority', 'test_type', ...
];
```

#### 关键流程
1. **删除限制（deleteCol）**：
   - 先 `isFrozenCol(ci)`（`headers[ci]==='testcase_id'`）→ 提示"冻结列不允许删除"并阻断（删除破坏推送语义与失败标记联动）；
   - 再 `isProtectedCol(ci)`（遍历 `PROTECTED_COLS`）→ 提示"『列名』为受保护列不允许删除"并阻断；
   - 正常右键菜单对受保护列直接不渲染"删除该列"项，运行时校验为二次防御。
2. **重命名限制（renameCol）**：同样先 `isFrozenCol` 后 `isProtectedCol` 拦截；若新名与已有列重名给出 warning（仅冻结列强制收紧）；重命名后若与明细表 `field` 同名则同步改名（`detailTables[*].field`、`S._detailField`），避免弹窗/粘贴/渲染失效。
3. **配置即时生效**：`PROTECTED_COLS` 是前端常量，修改后编辑器按新约束调整菜单项显隐 + 运行时校验，无需重建文件（如需跨任务差异，可后续下沉为配置项）。

#### 边界与防御
- 删除列时同步回收 `detailTables` 中 `field` 等于被删列名的孤儿表，否则 YAML 序列化会输出野数据；同步转移高亮/修改集合（`_shiftColIdxHighlights`）、列筛选索引、列选区、列宽索引。
- 受保护列仅锁"列名/列存在性"，不限制单元格编辑、粘贴、批量清空、填充等数据操作（与 `isFrozenCol` 完全只读语义区分）。

### 2.5 表头中英文映射（系统预置 + 用户自定义双通道）

#### 需求要点
表头中文友好且保真英文 key；团队可自定义中文名；多层来源合并、热更新；底层始终英文 key 通信；中文表头文件推送时经反向映射还原为英文。

#### 涉及模块与文件
- 映射加载/合并/持久化：`src/utils/headerLabels.ts`。
- 推送还原：`normalizePushData`（同文件）、`src/utils/pushDataMapper.ts`。
- 前端展示：表头渲染（`02a-render.js`）读取消息附带的映射；热更新监听经 `BaseEditorProvider` 注册 `onHeaderLabelsChange` 订阅。

#### 核心数据结构
```ts
type HeaderLabels = { [enKey: string]: string }; // 英文 key → 中文名
```
四层来源（从低到高）：
1. 插件内置默认（`package.json` 的 `default` 字段）；
2. 用户设置 `testcaseViewer.headerLabels`；
3. 工作区设置 `testcaseViewer.headerLabels`；
4. 工作区文件 `.plugin/.tms/headerLabels.json`（最高优先级，`{key: value}` 平铺对象，随仓库分发）。

前三层由 VS Code 配置系统自动合并；第 4 层由 `getHeaderLabels()` 手动读取覆盖。

#### 关键流程
1. **读取与合并（getHeaderLabels）**：
   - 取 `vscode.workspace.getConfiguration().get(CONFIG_KEY)` 得前三层合并结果；
   - 读 `.plugin/.tms/headerLabels.json` 逐 key 覆盖（仅 string 值生效）；
   - 未配置字段 → 表头只显示英文 key，不影响功能。
2. **两种配置入口**：
   - 命令 `openOrCreateHeaderLabelsSettings`：文件不存在则读当前合并默认值生成模板写入 `.plugin/.tms/headerLabels.json` 并打开；存在则直接打开。
   - 设置界面编辑 `testcaseViewer.headerLabels`（用户级/工作区级）。两路汇入同一合并结果。
3. **映射驱动展示**：表头有映射时第一行中文名、其下英文 key，悬浮提示"中文（英文key）"；弹窗字段名同理中英文并列；无映射仅英文 key。
4. **热更新（onHeaderLabelsChange）**：同时监听 VS Code 配置变更（`onDidChangeConfiguration`）与文件系统 `.plugin/.tms/headerLabels.json` 变更（`createFileSystemWatcher`），任一变化即回调前端刷新表头，无需重开文件。
5. **底层英文通信 + 反向映射（normalizePushData）**：
   - 推送/导出一律以英文 key 为准；
   - 若数据首行含中文 key（中文表头文件），用 `getReverseHeaderLabels()` 还原：先由正向表自动反转兜底，再用显式 `testcaseViewer.headerReverseLabels` 覆盖；
   - 例外：典型中文 CSV 模板表头（步骤描述/名称/预期结果/路径/前置条件/案例类型/优先级/执行方式）跳过反向映射，交由 `mapChineseRowToCaseItem` 按语义映射（避免与简单 key 改名语义冲突）。
6. **漏配提示**：用户自定义中文名若未同步配置反向映射，该列推送时无法还原、字段丢失——应在漏配时提示补全。

#### 边界与防御
- 配置非法格式 → 静默降级为空对象，编辑器正常打开不阻断。
- 多层同字段按"项目文件 > 工作区 > 个人 > 系统默认"覆盖。
- 自动反转兜底对重复中文名做去歧义（`!en.includes('-') && existing.includes('-')` 优先保留非复合 key），显式反向映射可精确控制。

## 3. 跨功能交互与一致性

- **会话隔离**：每个 webview panel 独享 `EditorSession`（`BaseEditorProvider`），避免多 Tab 共用单例状态互相覆盖；`panelMap` 按 `filePath` 索引供外部推送结果定位。
- **自保存守护**：落盘后 3 秒（`SELF_SAVE_GUARD_MS`）内忽略外部变更通知，避免 `fsWatcher` 自反弹覆盖高亮；可见性切换/外部变更均强制重新 `parse` 并 diff 下发。
- **持久化分层**：标记（`markStore`）与推送高亮（`highlightStore`）物理隔离；标记不参与推送、不影响导出。
- **行号对齐**：推送失败行定位优先用 `rowIndexMap`（testcase_id→1-based 行号），缺失时兜底 `pushIndexToRow[i]`，避免按数组下标错位。
- **撤销栈**：标记/取消标记、列增删/重命名、行增删/复制均先 `pushHistory()`，支持整体撤销。
