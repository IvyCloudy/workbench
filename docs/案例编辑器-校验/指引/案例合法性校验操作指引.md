## 一、功能概述

「案例合法性校验」是在**案例编辑器（表格 webview）**内，对测试案例文件做"可推送性自查"的能力：把"哪一行、哪一格、什么问题"精确呈现出来，让你在推送前就修好，而不是等到推送失败才回头找。

> 定位策略：本功能**只定位、展示问题**，不擅自改值。其中确定性可修复的问题（如必填空值、格式可归一化项）由独立的「一键修复」功能承接，本指引只讲"校验与定位"。

**核心能力：**

- 两种触发：**编辑期自动校验**（打开 / 编辑时自动跑）与**手动校验**（工具栏「校验」/「格式校验」按钮）
- 单元格级精确高亮（红底 = 错误，黄底 = 警告）+ 结果面板列出每行每格的问题与原因
- 结果面板每条问题带「定位」按钮，一点即跳到对应单元格
- 推送前自动跑**预校验门控**：错误行拦截、警告行可"忽略并继续"
- 校验规则与推送前的本地预校验**共用同一份字段约束**，校验通过即代表"推送时不会因行级字段错失败"

## 二、适用场景与前提

- **适用对象**：用案例编辑器（表格 webview）打开的测试案例文件（CSV / YAML / JSON / XLSX 等，路径通常位于 `测试任务/*/测试案例/**`）。
- **前提**：
  - 文件已被编辑器正确加载（表头映射正常）。
  - 校验本身不要求先绑定任务；但推送时才需要绑定测试任务。
- **不在校验范围**：
  - **样例行**（`testcase_id` 为占位值如 `TESTCASE_ID` 的行）整行跳过，不校验、不计入问题。
  - 后端业务校验（如案例已存在、权限等）不在编辑期校验范围，需推送时由系统判定。

## 三、触发方式

### 3.1 编辑期自动校验（打开即跑）

- **打开文件**：编辑器加载案例文件后自动跑一次全表校验，并弹出**校验结果面板**展示结论。
- **编辑 / 保存**：后续每次编辑会触发**防抖刷新**——只刷新红 / 黄高亮与问题状态，**不再弹窗**，避免打断输入。
  - 防抖档位：YAML / JSON 文件 500ms，CSV 文件 800ms，大于 512KB 的大文件 1500ms。

### 3.2 手动校验（主动自查）

- **工具栏按钮**：点击编辑器工具栏的「校验」/「格式校验」按钮，对当前全表跑一次校验并弹出结果面板。
- **命令面板**：也可通过命令面板运行格式校验相关命令触发。
- 手动校验基于当前已加载的表格数据（无需重新解析文件），对所有非样例行执行。

## 四、结果面板与高亮解读

### 4.1 校验结果面板

- 以列表形式展示每条问题，每条包含：**行号 · 中文列名（字段码）· 级别 · 原因**。
- 顶部给出汇总（如"校验通过，可推送"或"发现 N 个问题"）。
- 每条问题带「定位」按钮，点击后页面滚动到该单元格并临时聚焦高亮。

### 4.2 单元格高亮（红底 / 黄底）

| 高亮颜色 | 级别 | 含义 |
|---------|------|------|
| **红底** | 错误（error，硬拦截） | 该行该格存在硬性非法，推送时会被剔除或阻断，必须修 |
| **黄底** | 警告（warn，软拦截） | 疑似问题或质量类提示，可"忽略并继续"推送，建议修 |

- 同一单元格的多条问题会聚合为一条展示，高亮作用于该单格。
- 若某问题对应的字段在当前表头中**找不到对应列**（如新增字段未纳入表头映射），会**降级为整行高亮**并在面板标注"列缺失，请检查表头映射"，不会静默丢弃。
- 中性说明：`testcase_id` 为空的行会被剔除且不推送，但该行**不单独红底标记**，请关注结果面板的"空标识"类问题。

## 五、校验项一览

下表为常见的校验项与处理建议，**具体级别（错误 / 警告）以编辑器实际展示为准**。

| 问题类别 | 典型表现 | 级别 | 处理建议 |
|---------|---------|------|---------|
| 样例行占位 | `testcase_id` 为 `TESTCASE_ID` 等占位值 | 跳过 | 非用户数据，无需处理 |
| 标识为空 | `testcase_id` 为空 | 错误 | 补全唯一标识；该行会被剔除不推送 |
| 标识格式非法 | `testcase_id` 不符合格式要求 | 错误 | 修正为合法唯一标识；剔除不推送 |
| 标识重复 | 多个数据行 `testcase_id` 相同 | 错误 | 修改为互不相同 |
| 案例类型非法 | `type` /「案例类型」不在白名单 | 错误 | 改为合法值（见下方白名单） |
| 执行方式非法 | `test_type` /「执行方式」不在白名单 | 错误 | 改为合法值（见下方白名单，支持 `接口`/`界面` 简写） |
| 优先级非法 | `priority` /「优先级」不在白名单 | 错误 | 改为 `高` / `中` / `低` |
| 关键案例非法 | `key_flag` /「关键案例」不在白名单 | 错误 | 改为 `是` / `否` |
| 计划执行次数非法 | 非非负整数 | 错误 | 改为 0 或正整数 |
| 名称空 | 案例名称为空 | 错误 | 补全名称 |
| 必填 / 长度 / 格式 | 字段超长、含非法字符等 | 错误 | 按提示修正 |
| 待补充占位 | 内容含 `TODO` / "待补充"等 | 警告 | 建议补全；可忽略继续 |
| 步骤 / 预期缺失 | 缺少步骤描述或预期结果 | 警告 | 补全步骤 / 预期（语义类，需业务判断） |
| 步骤与预期数量不一致 | 预期数 ≠ 步骤数 | 警告 | 检查步骤 / 预期配对（语义类） |

### 5.1 枚举白名单（最新）

- **案例类型（`type` /「案例类型」）**，共 13 项：
  `流程类`、`功能点类`、`报表统计类`、`界面类`、`报文接口类`、`批处理类`、`其他`、`算法类`、`可用性检查类`、`数据仓库类`、`安全类`、`性能类`、`AI类`
- **执行方式（`test_type` /「执行方式」）**，4 项 + 简写：
  `手工`、`UI自动化`、`接口自动化`、`自动化`；另支持简写 `接口` → `接口自动化`、`界面` → `UI自动化`（大小写不敏感，自动识别）
- **优先级（`priority` /「优先级」）**：`高`、`中`、`低`
- **关键案例（`key_flag` /「关键案例」）**：`是`、`否`

> 空值处理差异：推送时 `案例类型` / `优先级` / `关键案例` 留空会按默认值兜底（`功能点类` / `低` / `否`）；但**编辑期校验对"列存在时的空值"按错误拦截**。建议编辑时就把这几列填好，避免推送与校验口径不一致。

## 六、如何处理发现的问题

1. **定位**：在结果面板点击问题的「定位」按钮，跳到对应单元格（红 / 黄高亮）。
2. **手改**：直接在该单元格修正值（如把非法枚举改成白名单内的值）。
3. **可修复项（A/B 类）**：必填空值、格式可归一化等确定性可修复问题，使用独立的「一键修复」功能批量或单格修复（详见相关文档）。
4. **不可修复项（C 类）**：语义不符、需业务判断的项（如枚举拼错、步骤 / 预期缺失），面板仅给**建议值文案**，不自动写盘，需你手动修改。
   - 枚举非法：建议值会列出白名单（如"建议改为：手工 / UI自动化 / 接口自动化 / 自动化"）。
   - 步骤 / 预期缺失：建议"至少补充一个步骤 / 预期结果"。

## 七、推送前预校验与门控

点击「推送」时，系统会**自动先跑一遍预校验**，并弹出**前置校验窗口**：

- **存在错误（error）行**：这些行会从推送数据中**剔除**（不发给后端），窗口只提供「关闭」，**不允许继续推送**这批错误行。
- **仅有警告（warn）行**：窗口提供「取消」与「忽略并继续」——选择"忽略并继续"后，警告行会随正常数据一起推送；选择"取消"则中止本次推送。
- **全部行被剔除**：推送短路并提示原因（如"缺列""占位 / 空 / 格式非法"等），不会发出任何后端请求。

> 提示：预校验与编辑期校验**规则一致**。编辑期把问题都修掉（红底清零），推送时就不会被门控拦截。

## 八、常见问题

**Q1：我编辑文件时为什么没弹窗？**  
A：只有**打开文件**时会弹结果面板；之后的编辑 / 保存只刷新红黄高亮，不弹窗，以免打断输入。

**Q2：红底和黄底有什么区别？**  
A：红底 = 错误（硬拦截，推送会被剔除或阻断，必须修）；黄底 = 警告（软拦截，可"忽略并继续"推送，建议修）。

**Q3：执行方式填"接口""界面"可以吗？**  
A：可以。系统会把 `接口` 自动识别为 `接口自动化`、`界面` 自动识别为 `UI自动化`（大小写不敏感），校验与推送都支持。

**Q4：案例类型有哪些合法值？**  
A：共 13 项，见 [5.1 枚举白名单](#51-枚举白名单最新)。不在其中的值会被判为非法（错误）。

**Q5：样例行会被校验吗？**  
A：不会。`testcase_id` 为占位值（如 `TESTCASE_ID`）的样例行整行跳过，不计入问题、不参与推送。

**Q6：我开了"仅看失败行"等过滤视图，隐藏行会被漏判吗？**  
A：不会。校验基于**全量数据行**（不受前端过滤视图影响），结果面板可与过滤视图叠加显示；隐藏行同样参与校验，不会漏判（但视觉上你可能看不到高亮，属已知的"隐藏行误伤"边界）。

**Q7：校验通过就一定推送成功吗？**  
A：校验覆盖绝大多数**行级字段错**（空值 / 枚举 / 格式 / 长度等），并尽量与推送约束对齐；但后端业务校验（如案例已存在、权限、接口级参数）仍需推送时由系统最终判定。

## 九、操作建议

- 养成习惯：编辑完、推送前点一次「校验」，把红底清零再推送，可大幅减少推送失败。
- 红底（错误）必须修；黄底（警告）建议修，确属误报可在推送门控时"忽略并继续"。
- 对重复性可修复问题（空值、格式），优先用「一键修复」批量处理，再对手动项逐个修正。
- 表头映射若有新增字段，确保纳入 `headerLabels`，否则相关列问题会降级为整行高亮。
